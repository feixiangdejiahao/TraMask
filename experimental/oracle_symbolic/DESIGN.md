# 观测等式的线性上下文代入

现有三个测试提供观测等式 `A.actual = a`、`B.actual = b`、`C.actual = c`。本原型按 AST 找到 `B.actual` 中**恰好一次** `A.actual`，得到上下文 `K[□]`。随后用独立常量解释器验证 `K[a] = b`，导出 `K[C.actual] = K[c]`。只允许已有代码中的上下文；不会执行仓库函数，也不由模型发明期望值。

例如，`f(3)==3`、`f(3)+1==4`、`f(8)==8` 给出 `K[v]=v+1`。解释器先验证 `3+1==4`，再计算 `8+1==9`，生成 `f(8)+1==9`。相比直接搬运 B 的常量 `4`，期望值由同一个上下文推导且可复算。

**支持范围。** 常量为 `None/bool/int/str/list/tuple`；运算为整数一元正负、`+/-/*//%`，同类型字符串/列表/tuple 拼接及整数重复，列表/tuple 构造。除 carrier 外不允许任何函数调用、名字、属性、下标、比较、短路、推导式或更新。节点和常量大小均有固定预算；不定义的常量运算明确拒绝。匹配对象是 actual 的完整 AST，故 `f(3)+3` 中第二个 `3` 不会因数值相同而被替换。两个相同 carrier 出现时拒绝，避免将一次观测解释为可重复调用。

**条件与反例。** 这是 builtin 值语义下的等式代入，不是普通 Python `==` 的无条件定理。自定义对象可能 `obj==8` 为真但 `obj+1` 不等于 `9`；继承内建类型、重载运算、绑定变化也不能凭一个相等断言排除。因此结果标为 `conditional`，明确需要 carrier 的内建值语义与调用上下文保持前提。`f()+f()` 被拒绝；`f()+side_effect()` 不会被执行；B 的期望无法通过 `K[a]` 重算时也拒绝。列表/tuple 的值等式不证明对象身份或别名关系。

**与统一 test analogy 的关系。** 该核不另选测试或另造组合：A/B/C 和待迁移 actual 仍由同一个语法类比确定；它作为断言槽的可检查 oracle 传输步骤，把“固定 B.expected”替换为“常量解释 `K[C.expected]`”。只在同一个线性上下文解释得通 A→B 时产生提案。它减少一类错误常量搬运，并不能替代类型/绑定前提审查、semantic gate 或实验中的独立误报审计。

**检错增益的边界。** 在上述纯内建值前提下，`C.actual==c` 本来就蕴含 `K[C.actual]==K[c]`。这里没有改变被测 API 的输入或状态，因此单独加入这条测试通常不会增加对被测程序的检错能力。它适合作为 oracle 运输的局部推导工具，不应把“生成了正确断言”算作“发现了遗漏组合”。若前半段还改变了 API 输入，仍需另行建立该新输入对应哪个已知观测值；这个核心没有解决那一语义问题。目前不将它接入实验流水以增加表面的有效测试数量。
