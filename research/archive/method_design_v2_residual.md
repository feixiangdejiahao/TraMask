**候选方法：关系残差切片及其适用边界**

**实现后的实验更新：** 第 0 节的检索方向已做成本地原型并运行七例。全部目标测试/断言进入清单，但完整排序 Test Hit@10 为 **0/7**，关键词基线为 **7/7**；去掉输入取值差优先级后为 **4/7**。因此不能继续将下面的手工例子作为 A 检索有效性的证据。实现范围、消融和失败原因见 [实验报告](../anchor_retrieval_experiment.md)。关系残差及组合生成部分没有在本轮实现或评价。

**本轮审查后的定位：关系残差不再被视为七个 pilot 共同支持的核心方法。** [A 的检索与逐例适用性审查](../anchor_applicability_audit.md) 发现，P2 用普通断言切片即可解释；P3 还需位级组合；P1/P4/P5 存在额外建模前提；P6/P7 不满足当前“固定 oracle、迁移供体”的条件。以下保留关系残差作为一个较窄的优化假设，而非已验证的统一方案。

该候选抽象是**关系残差（relational residual）**。限定研究问题为：已经有一条适用范围有根据的可执行关系时，哪些额外输入条件会破坏它？关系从哪里来、测试 A 如何找到，必须分别回答，不能藏在“提取特征”中。

中心 insight：**影响程序输出，不等于影响某条测试规律的成立。应该组合那些影响“规律是否成立”的因素。** 对规律两侧共同保持的行为作符号消去，可以把全程序的依赖问题缩小到交互本身。

下文保留原型方法设计；最新检索实验见上述更新，没有调用外部模型。逐例事实仍见 [手工分析](../manual_case_analysis.md)。

**0. 如何在大量 validation tests 中检索 A**

A 是一条断言及其可执行上下文，而不一定是完整 test 函数。对仓库与 trajectory 测试建立“生产端观察位置→断言”的索引，去掉重复执行及源码编辑器的保护断言；保留输入参数行和代码版本。只打印结果的脚本可以提供输入，但不提供可继承的断言。

从 patch 的生产代码改动 Δ 检索它能影响的观察位置，再按需计算共享的跨过程切片。优先候选满足 `BS(a) ∩ Δ ≠ ∅`；其中有某个输入依赖在 A 的上下文始终固定、在其他测试中出现不同取值的，优先用于重组。按入口、观察字段、断言及上下文分组分配预算，不比较任意两份完整测试，也不先让 LLM 猜哪份测试重要。未解析的依赖不能当成无依赖。

P2 的本地 AST 清点有 2,047 个 `test_` 函数定义；parser 测试文件有 30 个，其中 6 处断言直接读取 `character`，包含 shortcut 的 `character is None`。这是索引粒度的具体例子，不是已实现的完整算法或加速实验。算法应处理所有受改动影响的观察字段，而不是预先获知目标是 `character`。

检索 A 不等于证明 A 的 oracle 可迁移，也不等于找到双执行关系。P2 可以直接复用 issue 支持的单次执行断言；P6/P7 则仍缺少目标观察或对应 oracle。算法、复杂度边界、源码证据及逐例判断见 [审查文档](../anchor_applicability_audit.md)。

**1. 核心抽象：把测试规律变成一个布尔程序**

考虑一条可执行关系测试：

```python
def relation(x):
    assume(G(x))
    assert L(x) == R(x)
```

`L`、`R` 是已有测试中的程序表达式，可以包含被测 API 调用；`G` 是该关系的适用条件。比如 `decode(encode(x)) == x`，或在两个独立初态上执行相同操作后，clone 与原对象的观察值相等。它们都是代码，不包含需要模型解释的 feature / intent / contract 描述字段。

定义该关系的残差：

\[
D_r(x) \triangleq [L(x)\ne R(x)].
\]

`D_r(x)=0` 表示关系成立，`D_r(x)=1` 表示关系被破坏。常见蜕变关系可写成：

\[
L(x)=\pi(P(\tau(x))),\qquad R(x)=\rho(\pi(P(x))).
\]

其中输入变换 `τ`、观察 `π`、输出变换 `ρ` 都是可执行函数；实际算法直接处理关系测试的 AST，无须维护这四个语义标签。

**组合的含义：** 测试 A 已检查关系 r；测试 B 提供另一输入取值或构造片段。将 B 的片段放进 A 的输入后，检查同一个 r。新增 test 的 oracle 就是原关系表达式，不需要模型再猜组合结果。

只有普通常量断言的有限样本不能逻辑推出任意输入上的关系。主算法以已有可执行关系测试为种子；从 issue 补全关系是一个独立、可选的种子来源，不把它藏在“提取特征”的步骤里。

**2. 一个可以完整算出的例子**

假设正确规律要求：开启 a 会使结果增加 1。候选实现为：

\[
P(a,b,c)=a+b+c-ab,\qquad a,b\in\{0,1\}.
\]

已有测试检查了 `(0,0,0)→0`、`(1,0,0)→1`、`(0,1,0)→1`。a、b 分别测试均通过。用关系式表示第一条规律：

\[
P(1,b,c)=P(0,b,c)+1.
\]

普通 backward slice 会告诉我们输出依赖 a、b、c。对关系两侧作符号消去则得到：

\[
\begin{aligned}
D_r(b,c)
 &= [P(1,b,c)\ne P(0,b,c)+1] \\
 &= [1+c\ne b+c+1] \\
 &= [b\ne0].
\end{aligned}
\]

因此第二个因素是 b；c 虽然影响输出，却不会影响这个关系。把测试 B 已有的 `b=1` 迁入关系测试，即可机械生成：

```python
assert P(1, 1, 0) == P(0, 1, 0) + 1
```

这同时回答了选哪两个行为、怎样组合、如何生成 oracle。它也说明程序分析需要做什么：**切关系残差，而不是把两个输出的普通切片取并集。**

**3. 核心算法：配对消去，再作最小测试重组**

算法输入为候选程序 P、已有测试 T 和从 T 得到的关系种子 r；输出为违反 r 的最小组合测试。

**第一步：构建有界关系程序。** 将 `L(x)`、`R(x)` 转为共享符号输入的两份 SSA 表达式。两边的可变状态分开初始化。只展开关系观察所需的调用；循环使用固定展开界。关系输入保持符号化，不能先代入 seed 的取值再切片，否则会把例子中的 `b=0` 当常量而漏掉交互。

**第二步：配对切片。** 从观察对 `(L,R)` 反向处理，按程序语言的精确语义化简两侧共同项，再找残差仍依赖哪些输入。以下是原型需要的关键规则，`δ(u,v)=[u≠v]`：

| 形态 | 关系化简 |
|---|---|
| 相同符号值 | `δ(e,e) = false` |
| 相同整数平移 | `δ(u+c,v+c) = δ(u,v)` |
| 记录/元组相等 | 分解为相应字段的差异析取，删除相同字段 |
| 两侧同一分支条件 | `δ(ite(g,a,b),ite(g,c,d)) = ite(g,δ(a,c),δ(b,d))` |
| 两侧不同分支条件 | 保留两条件的四种配对，不能强制它们走同一分支 |

相同整数平移规则用于数学整数或相同宽度的模加，不直接用于浮点数。相同调用文本也不能当作相同符号值；只有实参、状态和调用语义支持相等时才消去。

令 `e_r = Simplify(D_r)`，`S_r = FV(e_r)`。`S_r` 是残差的输入依赖集合，允许是过近似。将这些变量沿定义—使用链回溯到测试的构造实参，便获得可迁移的输入槽位。相同槽位按解析后的形参/字段定义点对应，不按变量名字或测试描述匹配。

这里有一个直接的正确性性质：在该有界模型中，若两份输入在 `S_r` 上相同，则 `e_r` 的值相同。因此改变其余槽位不可能改变这条关系的 verdict；可以固定为 seed 值。该性质为组合空间裁剪提供了依据。

**第三步：求最小组合。** 对每个残差槽位，收集其他测试在该槽位上已经使用过的值或闭合构造片段。记由这些片段得到的有限替换集合为 `Θ_T`，固定非残差槽位，只求：

\[
\theta^*=\arg\min_{\theta\in\Theta_T}
 |\operatorname{changedSlots}(\theta)|
\quad\text{s.t.}\quad
 G(\theta x_0)\land D_r(\theta x_0)=1.
\]

按替换槽位数 1、2、… 递增求解即可实现最小化；第一版限制最多两个供体片段。形参之间已有的构造依赖作为同一片段保留。生成代码时只替换输入构造片段，原 `L == R` 断言保持不变，再在实际 candidate 上执行确认。

```text
ResidualRecombine(P, T, r, x0):
    e = PairedSimplify(BoundedProduct(P, r))
    slots = TraceInputs(FreeVariables(e))
    donors = ProjectExistingTests(T, slots)
    for k in [1, 2]:
        x = Solve(G_r(x) and e(x),
                  changes_from(x0) <= k,
                  changed_values_from = donors,
                  other_slots_fixed_to = x0)
        if x exists:
            t = InstantiateSameRelation(r, x)
            if Execute(t, P) violates the relation:
                return MinimizeInput(t)
```

实现核心是一个配对表达式 worklist 和一个有限域求解问题。符号展开由固定边界限定；没有推断协议语法、全语言 alias graph 或并发调度的总框架。返回的失败需要与种子关系的正确性一起评价，不能通过改 expected 来让它通过。

**4. 缺口与测试特征如何从这个抽象得到**

这里不用 LLM 给 test 写特征标签。某个测试对关系 r 的特征，就是它在 `S_r` 对应槽位上的程序绑定。两个 test 的关联，由“一个提供关系种子，另一个给残差槽位提供新绑定”定义。

对于从供体得到的绑定，若它没有被原关系测试检查过，就是一个待检查的组合；求解 `D_r=1` 优先找其中会破坏关系的组合。即使现有普通 test 已执行同样分支，只要没有检查 r，也不能据此删除这个目标。

这区分了两个对象：**遗漏组合是关系未检查过的绑定；错误组合是其中存在非零残差的绑定。** 原型以查找后一类为生成目标，而不追求填满所有 pairwise 单元格。

**5. Pilot 审查：关系能够写出，不等于算法前提成立**

P2 最适合解释固定断言的输入重组。把合法输入写为 `encode(key, modifiers, text)`，对于非 shift modified printable shortcut，可以人工写出关系：

\[
\operatorname{character}(parse(encode(k,m,t)))
=\operatorname{character}(parse(encode(k,m,\epsilon))).
\]

已有 shortcut test 断言右侧为 None；text-only test 提供合法的 text 片段。候选代码在 shortcut 分支使用 `text or None`，暴露对 `text` 的依赖。重组只迁移 text，保留非零 key code 和 modifier，不复制 text-only test 的 `character=='a'`。适用范围的语义根据来自 issue；单独两条 ground tests 不足以自动证明它。实际生成可以直接保留 `character is None`，无须先建立双执行关系，因而本例没有证明配对消去的增益。

| Pilot | 实际程序联系 | 现有算法缺少什么 / 是否必要 |
|---|---|---|
| P1 | 不同解析分支产出同一 phase 字段 | 扩展分支缺少 phase 传播及相应语法；不能只沿已有数据依赖生成 |
| P2 | text 解码结果进入 shortcut 的 character | 普通断言切片即可；关系残差不构成额外解释力 |
| P3 | modifier 位与 shifted key 共同进入 alias | 需位级组合，而非只复制完整 modifier 整数；普通切片仍可定位 |
| P4 | magic 经 tokenizer 把 path 传给 core API | 需合法引用表示的依据；现成独立测试不是已编码的两入口 MR |
| P5 | Go/VM 调用入口经 frame 产生 guest 返回值 | 需 guest 程序改写、返回结构及观察路径调整；两入口等价关系尚未自动获得 |
| P6 | clone 复制 closure 及捕获 cell | 原断言仅检查外部隔离，缺少内部共享的堆结构和 write→read oracle |
| P7 | schema 改写涉及执行方法及闭包捕获 | 已有恒等 action 无区分力；非恒等替换需要相应的新 oracle |

这些是人工适用性判断，不是实验成功率。P1/P4/P5 的困难不应只称为实现细节，P6/P7 也不能仅靠增加求解预算解决。完整证据见 [逐例审查](../anchor_applicability_audit.md)。

P7 尤其说明不能用人工新增关系掩盖种子问题：单次 action 的 `Run(f,x) == f(x)` 可以被提出，但原 recursive test 并未编码这个关系，且递归层次影响正确的整体输出。readonly 在运行时恒等，旧测试不能区分其执行与跳过；换成非恒等 action 后，原 `output == input` 又可能在正确程序上失败。此例不满足当前固定关系种子的输入重组前提。

**6. 自动化边界：种子代码与核心搜索分开**

在第 0 节检索出的候选中，较窄的关系分支只处理已经有关系的测试：归一化 assertions，向后切出关联的两次调用、输入变换及 setup，保留已有参数化和前提；可复用 MR-Scout 的 codified-MR 路线。若只有孤立常量断言，就不把它自动泛化为一个全称规律。具有可复用单次断言的候选应与普通切片基线比较，不能重新命名为残差后当作新贡献。

少量 LLM 的位置只在种子入口：针对某个 API，将 issue 与现有断言转成一段可执行关系测试，随后冻结该代码。模型不生成 feature、依赖边、组合优先级或组合后的 expected。所有方法基线获得完全相同的种子，另报零 LLM 种子的结果。本轮遵守本地分析约束，没有实际调用模型。

原型首先需要的是“已有可执行关系 + 有界关系程序 + 配对消去 + 供体重组”，不需要重新发明全自动规格恢复。种子可恢复率是必须测量的适用范围，不能拿人工编写的 pilot 关系充当自动化结果。

**7. 文献位置与论文要证明的内容**

[MR-Coupler，FSE 2026](https://arxiv.org/html/2604.10126v1) 利用方法耦合找关系生成机会。这里把已经得到的关系固定下来，分析其残差，以发现会破坏它的测试上下文。**程序上相关**与**对同一规律的真假相关**，是拟研究的差别。

[MR-Scout，TOSEM 2024](https://doi.org/10.1145/3656340) 已从测试提取可执行 MR；[MR-Adopt，ASE 2024](https://valerio-terragni.github.io/assets/pdf/xu-ase-2024.pdf) 已研究补全输入变换。这两部分应作为种子来源或基线，不计作本方案的新贡献。

[Relational Symbolic Execution](https://arxiv.org/abs/1711.08349) 已研究相关输入上的多次执行；[Path-directed source test case generation，JSS 2022](https://doi.org/10.1016/j.jss.2021.111091) 已用路径约束生成蜕变测试源输入。因此“MR + 符号执行”同样不新。需要单独检验的算法贡献是：**在求解前作关系保持项的消去，再把残差依赖投影回已有测试，进行最小供体重组。**

相对于 [Feature-Focused Test Generation，ASE 2026 已收录](https://conf.researchr.org/details/ase-2026/ase-2026-research-track/183/Feature-Focused-Test-Generation)，本方案的研究假设是：在这个任务中，以某条关系为条件的残差依赖可以直接充当组合因素，省去自然语言特征命名。这里没有主张所有输入特征都能这样恢复。

评价只围绕三个问题：

1. 同样的关系种子和执行预算下，残差切片是否比普通输出切片、随机/pairwise 组合、路径引导 MR 和直接关系符号执行减少搜索成本、增加真实缺陷检出？
2. 配对消去与供体重组各自是否有增益？分别移除它们做消融，种子固定。
3. 将新失败测试反馈给修复 agent 后，同预算的净 issue resolution 是否提高？按 issue 划分独立数据，并计入原成功任务的回归。

若配对消去没有优于直接关系符号执行，或供体没有优于普通输入求解，就应删掉相应贡献主张。当前首先需要证明自然存在的关系种子具有足够覆盖面，以及配对消去提供独立增益；七个 pilot 的人工关系表不能代替这两项证据。关系残差暂不作为覆盖整个任务的论文核心结论。
