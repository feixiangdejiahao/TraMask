# 当前算法的研究审计

2026-09-29 04:06 UTC。依据当前源码、冻结的局部实验和 `checkpoint_07`；统一配置运行尚在进行。本审计未修改生产代码，未运行仓库实验或调用 provider。另对断言校验函数做了四个本地输入检查。

**目前已经有可运行的组合构造方法，但“关系形状能提高搜索效率”这个学术核心尚未得到实验支持。** 累计 17/17 说明逐例探索已经找到正确见证；它混合历史运行、局部选定候选和多轮模型请求，不是完整流程的 17/17 检出率。最有价值的下一步是把构造能力固定下来，验证关系反馈究竟带来了什么，而不是继续增加抽象名称。

## 当前真正执行的算法

可以把一个搜索状态理解成：**一个原测试，加上一组输入修改，再加上执行时测到的局部关系。** 程序对这个状态做的操作很具体：从其他源码调用取得构件；产生有限输入修改；执行；把同一原测试上不重叠的修改继续合并。

1. 从现成完整 corpus 的测试和源文件枚举构件。Python 使用输入表示、成对编码和上下文构造器；Go/TS 使用各自的类型、调用、接收者和结构构造器。首轮按构造族轮换、保留前端确定性顺序。**当前不是先找出一个尚未覆盖的关系，再求解出输入。**
2. 可选模型步骤检查程序已经生成的完整测试，提出局部断言修改。它不负责生成输入池。新候选与模型修订分别保留。
3. 在 candidate 上依次运行原测试控制、原测试采样和生成测试，使用独立进程。对受支持的 Python 读取，在固定源码位置记录数值相对次序、引用别名、字段存在等形状。
4. 为每个已测形状保留至多两个代表。下一轮把合格代表上的输入修改，与同一原测试上的其他不冲突修改合并，再重新运行。`retained` 包括同形状的第二个代表，不能全部称为“新覆盖”。Go/TS 目前没有这类动态反馈。

对应入口是 [prepare](../scripts/run_relation_search.py)、[形状与调度](../relation_search/frontier.py)、[输入修改合并](../relation_search/instrument.py) 和 [执行反馈](../relation_search/feedback.py)。因此当前统一机制准确说是**源码构造加有限编辑搜索，关系反馈约束父节点扩展**。尚不能把多个构造器的成功全部归因于关系反馈。

## 用 P3 说明程序到底做了什么

源测试 A 有一个带替代键名的事件：

```python
k = Key("ctrl+equals_sign", None,
        modifiers=["ctrl"], shifted_key="plus")
assert k.shifted_key == "plus"
assert "ctrl+plus" in k.aliases
```

另一个测试 B 构造 `Key("ctrl+alt+shift+a", modifiers=["shift", "ctrl", "alt"])`。程序从同一个构造函数的参数中识别：一个列表保存修饰键，另一个字符串用 `+` 编码这些修饰键。于是它把 B 中 A 尚未使用的 `shift` 加入 A，**同时修改两个关联输入**：

```python
k = Key("ctrl+shift+equals_sign", None,
        modifiers=["ctrl", "shift"], shifted_key="plus")
assert k.shifted_key == "plus"
assert "ctrl+plus" in k.aliases
```

这不是拼接两个完整测试，而是保持 A 的调用和观察，把 B 中的一个输入构件接入 A，并同步它的另一种编码。由 [通用源码构造器](../relation_search/constructors.py) 确定性产生；这里没有调用模型，也没有借助动态形状挑出 Shift。实际失败是 aliases 中没有 `ctrl+plus`。正确性来自 issue 与独立协议审查，详见 [P3 评价](relation_search_evaluation_20260929.md#p3-源构造组合的两个候选)。

同一规则还产生加入 `alt` 的兄弟候选。这个候选继续断言 `ctrl+plus` 就是错误期望：它不应丢掉 Alt。两条候选的原测试控制都通过。因此本例同时说明：**程序可以保持输入之间的结构一致，却不能仅凭这种一致性证明原断言还成立。** P3 的成功支持这个构造操作可行，不支持关系反馈优于枚举。

## 哪些保证成立，哪些仍是语义假设

| 内容 | 当前能成立的结论 |
|---|---|
| 源码编辑 | 字节位置、原文本和语法可以检查；组合阶段拒绝重叠输入编辑。它不证明新场景满足业务前置条件。 |
| 输入关联 | P3 的列表与分隔编码、P4 的词法绑定与受支持插值消费者由有限规则恢复；不是任意 API 的完整语义依赖。 |
| 执行反馈 | 真实采样才计入形状；未知读取不会被当作字段缺席。引用 identity 不等于一般资源等价；相同形状也不意味着行为等价。 |
| 原测试通过 | 说明被恢复的来源控制可执行且通过；不证明迁移后的断言正确。 |
| 模型期望 | 是待验证的语义假设。常量修改仍可能错误，保留原断言同样可能错误。 |
| 缺陷判定 | 必须区别输入无效、错误期望和真正缺陷；17 例的独立人工复核不是已实现的自动 oracle。 |

还有一个具体实现边界：当前 Python/TS 的 oracle 校验器并不严格限制为“只改 expected”。它主要检查单断言/断言调用外形，以及原 observed 文本仍然出现；这不足以证明观察仍执行，也不足以禁止新增状态操作。这个限制比“语义正确性无法证明”更具体，见下文的最小反例。

## 一个最有价值的消融

**固定全部构造器、原始 corpus、oracle 和执行预算，只改变“哪些已执行父候选可以继续组合”：关系形状保留的父节点，对照所有合格已执行父节点的公平轮换。** 这就是现有 `profile` 与 `rotation` 能回答的问题，不需要添加另一套 schema 或模型职责。

先在支持实际采样、且候选池足以产生分叉的案例上比较；Go/TS 不应计入动态反馈优势。记录每个预算下独立确认的目标检出、到首个正确见证的实际执行次数，以及扩展父节点和后续候选集合是否真的不同。总预算应包括控制和种子采样；缺失 trace 不应伪装为覆盖。模型期望应对两臂的候选并集统一冻结，不把只为某一臂人工选择的正确修订带入对照。

现有 [N03 双臂实验](../results/relation_search_20260929/closed_loop/N03_comparison_v1.json) 两边都执行 10 个生成测试、10 个种子采样和 6 个控制；候选 ID 完全相同，第二轮新增形状均为 0。它证明闭环接通，**没有证明反馈有效**。如果更充分的等预算比较仍无收益，应当承认主要贡献来自源码构造，收缩关系反馈的研究主张。

STARS 值得借鉴的是让抽象直接规定搜索操作：已有变量和类型决定调用链的起点与扩展，静态搜索形成具体链，模型填剩余语义孔。这里最接近这一点的是“从现成源码恢复可连接的输入构件，并具体修改其关联位置”，而不是给每个失败场景填写关系名称。论文依据沿用 [既有逐节阅读笔记](stars_abstraction_review.md)及[原论文](https://www.software-lab.org/publications/issta2026_STARS.pdf)；本次未新增论文效果主张，也不能照搬其假设被测实现正确的回归设置。

当前两个设计文档首页还写着“完整反馈闭环尚未接入”，已落后于 [闭环实现记录](relation_search_closed_loop_20260929.md)。应在统一实验结束后按最终结果一起更新，避免旧方法、研究设想和实际算法混读。17 个 trial 均是已见开发材料，方法冻结后的新案例仍是检验泛化能力的必要证据。

## 断言结构校验的补充审计

审计版本的 `oracle.py` SHA256 为 `bf13849e30774d118e44b9312b3bfccbdf0f4f7a17b412b38fa1f586468b44e5`。直接调用 `_valid_assertion`，以下四种替换都返回 True；未执行其中的被测操作。

| 原断言及 observed | 当前允许的替换 | 问题 |
|---|---|---|
| `assert x == 1`；`x` | `assert True or x == 1` | 原观察不执行，断言恒真。 |
| 同上 | `assert x == items.pop()` | 期望位置加入了会修改状态的调用。 |
| `expect(read()).toBe(1)`；`read()` | `expect(true || read()).toBe(true)` | 原观察不执行，断言恒真。 |
| 同上 | `expect(read()).toBe(reset())` | 加入了新的状态操作。 |

同时检查了冻结缓存中的 **17 个 revisions、28 处 semantic_expected 编辑**：未发现上述利用。全部非 oracle 编辑与原程序提案逐项相同；25 处 Python 修改保留同一观察 AST 操作数、断言消息，只修改闭合常量/容器常量或比较符；Go 两处与 TS 一处也保留被测操作，分别替换字符串、整数和常量树。此结论仅关乎结构，**没有把这 17 个修订重新认定为语义正确**；例如旧 P3 修订仍可能错误。

逐项原文、请求 SHA、缓存 SHA 和最小反例检查结果保存在 [结构审计附件](relation_search_oracle_structure_audit_20260929.json)。当前统一运行使用冻结代码，审计没有修改其生产实现。后续最小修正应固定观察 AST 及其求值位置、拒绝模型新增操作，再单独允许必要的期望与比较谓词变化；这只约束模型的程序权限，仍不保证期望正确。

## 独立结构校验原型

上述修正已实现为 [experimental/assertion_operand_guard.py](../experimental/assertion_operand_guard.py)，API 为 `valid_assertion(code, old, observed, language)`；未改动正在运行的 campaign 使用的 `relation_search/oracle.py`。支持范围刻意有限：

- Python：单个二元比较断言。固定 observed AST 所在操作数和出现次数、断言消息；允许在等值、顺序、身份、成员关系各自的比较符族内变化，因此 N04 的 `==`→`!=` 可接受。新期望限闭合字面量/容器，旧期望也可原样保留。未知调用或 getter 不能通过改成常量而被删除。
- TypeScript：`expect(actual[, message]).toBe/toEqual/toStrictEqual(expected)`，允许保留原有 `.not`。整个 expect 调用、matcher、否定标志和消息固定，仅替换 expected。P7 的输入变量期望变成常量树可接受；不允许通过更换 matcher 弱化检查。
- Go：单比较 if 及 `require/assert.Equal/NotEqual`。固定实际操作数、比较符或断言 API，以及全部消息/失败体。期望可从原变量或字面量换为标量字面量；P6 的既存 `int64(103)` 可改为 `int64(5004)`，转换调用形状保持。

Go 最后一条有明确限制：只凭断言片段不能排除 `int64` 被同名函数遮蔽，因此这里只保证没有引入新调用，不证明这个既存调用是纯类型转换。生产集成若要求纯度保证，需要用源作用域解析确认预声明类型，或拒绝这类转换修订。Python 比较符变化同样可能分派不同特殊方法；固定观察计算不等于整个断言语义及副作用相同。

[95 项局部测试](../tests/test_assertion_operand_guard.py)通过，包括四个漏洞反例、观察移动/复制、消息修改、新增或删除未知操作，以及全部 17 个缓存修订的 28 处结构快照。快照自包含，不读取运行结果、不带语义正确标签。另拒绝了 `ast.literal_eval` 特别允许的 `set()`，防止它在源码中被遮蔽成有副作用的函数。这些是验证器测试，不是新增 trial 检出实验。

**结构固定仍不能保证断言足够强。** 对普通整数和 None，`x == 3` 蕴含 `x != None`，反向不成立，`x = 4` 就是反例；在明确的值域和谓词片段内，程序可以用逻辑蕴含或反例搜索证明这种弱化。但当前 API 没有对象类型和新场景契约；Python 重载比较、不同输入上下文还会改变结论。原型因此接受 `assert x == 3`→`assert x != None` 的结构，同时明确不为其语义背书。即使证明新断言比旧断言弱，也不能仅凭此判定它在新场景错误；反过来，没有变弱也不证明能检测目标缺陷。契约判断与缺陷可观察性仍需单独评价。
