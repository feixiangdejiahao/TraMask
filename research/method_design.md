# 从已有测试补齐组合：测试类比方格

2026-09-23。当前研究原型的核心是 **用三个已有测试构造缺失的第四个测试**。旧版依照七个 pilot 编写的领域变换已退出通用方法比较，保存在[历史设计](archive/method_design_context_lifting_pilot.md)。旧版的 7/7 不能作为新方法的效果。

## 一个能实际生成的例子

三个已有测试分别检验普通输入、容器输入和另一个数值：

```python
# A：普通输入
x = f(3)
assert x == 6

# B：容器输入
x = f([3])
assert x == [6]

# C：另一个数值
y = f(5)
assert y == 10
```

程序比较 A 与 C，发现输入 `3/5`、期望 `6/10`、局部变量 `x/y` 三组对应关系；再检查 B 如何同时改变输入和断言。把 B 的这项变化应用到 C，得到：

```python
# D：容器输入 × 另一个数值
y = f([5])
assert y == [10]
```

`10` 来自 C 的已有断言，外层列表来自 B 的已有断言。没有运行候选实现来猜答案，也没有预先写一个“给输入加列表”的领域算子。这是[自动生成测试](../tests/test_generic_analogy_generation.py)中实际覆盖的例子。

但三个通过的例子**不能证明第四个断言正确**：`f` 可能对不同数值采用不同规则。因此这里首先得到组合假设，而不是已经证实的缺陷测试。

## 唯一的核心抽象

把组合表示为 `A : B :: C : D`。算法从 A、C 找出共同语法骨架 P 及两套替换 σA、σC，再从 B 找出使用相同对应关系的骨架 Q：

```text
P[σA] = A       Q[σA] = B
P[σC] = C       Q[σC] = D
```

左侧两条等式把“输入、变量、期望值怎样对应”具体化；右上等式保证操作确实来自已有测试；右下等式构造新测试。实现使用 AST 反统一和替换，来源可以逐字重构，歧义有明确记录。这些是语法等式，不是语义等价证明。核心代码见[类比内核](../experimental/generic_v2/analogy.py)和[允许单侧信息消失的版本](../experimental/generic_v21/analogy.py)。

## 方法全流程

1. **找到与修复相关的观察。** AST 识别断言及测试 helper 中的断言，再沿 actual 表达式的定义—使用关系追踪输入、调用与可能状态操作。检索取前十个相关测试作为入口，来源方法见[观察前沿](observation_frontier_method.md)。它缩小搜索范围，不证明两个功能之间的语义关系。
2. **选择 A、B、C。** 先在能共享调用及绑定上下文的测试中选择三元组，至少一方来自入口测试。A、C 提供相近结构下不同输入和期望；B 提供结构变化。每次实验固定最多 2,000 个三元组、128 个候选。依赖排序变体优先选择观察同一调用／字段的 A、C，以及变化能到达观察点的 B；不把没有静态边当作不可能组合。
3. **构造 D，并携带断言。** 统一迁移输入、准备步骤和断言，不默认保留旧 expected。整测试版本复制完整上下文；调用实例版本只修改相应 helper 调用。窗口版本把断言及依赖的输入、expected 定义作为同一语法项，保留窗口内夹杂的其他语句及父测试前后文。词法绑定、语法和已存在测试检查会排除部分无效结果；窗口版本暂不支持展开参数化行。没有足够的对应关系时明确无输出。
4. **独立检查组合的语义依据。** `deepseek-v4-flash` 接收 issue、来源测试、候选和静态证据，只能选择候选 ID，不能现场改代码或填 expected。模型可能判断错误，所以这一步是有限的语义筛选，不是 oracle 证明。每例两轮独立选择，固定请求与完整响应；失败也计入结果和成本。
5. **冻结后执行并审计。** 先检查来源测试能否运行，再执行 D。候选实现失败只产生待审计报警；结合独立需求依据检查输入及断言是否有效，之后才用参考实现进行差分评价。参考通过也不能挽救错误断言。生成器和模型不读取参考补丁、隐藏 verifier、封存评价真值或执行结果。

## 程序分析负责什么

程序分析的主要贡献是找出可组合的对应关系及其实际作用位置：从断言反向找到被观察值；用调用／字段来源区分观察对象；用 AST、字节位置和词法绑定搬运代码；同时搬运输入与期望的对应关系。它让每条候选都有确定的源码来源，不依靠自然语言 schema 创造关系。

当前实现尚不能完整证明别名、状态效应、闭包捕获或嵌入字符串中另一种语言的语义。调用依赖只表明“可能影响”，不是“应该保持结果”。一个测试只有弱断言时，算法也只能尝试迁入其他测试已有的强观察，不能保证自动补出缺失的正确性质。

## 变体怎样比较

共同的研究问题是：**已有测试中的结构变化和输入／观察变化，能否可靠地重组为有检错能力的新测试？** 语句对齐、字符串表示、断言实例和依赖排序是这个假设的实现变体。另有独立的文本编辑合并对照，用于检验不做反统一是否更有效。它们分别冻结、分别报告，没有把所有算子合并后只取最好结果。

版本选择规则见[比较约定](generic_version_selection.md)，完整结果见[跨版本报告](generic_generation_cross_version_results.md)。截至当前已完成的评估，新通用版本仍没有确认的 pilot 目标检出；测试生成数量、单元测试通过和检索命中均不能替代检出率。后续批次结果以该报告为准。

## 论文 insight 与边界

MR-Coupler（FSE 2026）的启发是：先用可计算的功能耦合关系限制搜索，再生成并检验关系。我们借鉴“核心关系决定算法”，不要求使用蜕变关系。本原型选择的是测试类比方格；把反统一用于测试生成本身并不自动构成新颖性。[官方页面](https://conf.researchr.org/details/fse-2026/fse-2026-research-papers/200/MR-Coupler-Automated-Metamorphic-Test-Generation-via-Functional-Coupling-Analysis)、[论文](https://arxiv.org/html/2604.10126v1)。

ISSTA 2026 的 Mixed-Assertion 研究把同一测试内多个断言及其位置纳入生成问题。对本项目的启发是同时处理完整输入—观察关系，避免把一个孤立 expected 当成整个测试；这是我们的设计推论，并非该论文证明了本方法。[官方页面](https://conf.researchr.org/details/issta-2026/issta-2026-research-papers/123/Towards-More-Realistic-Assertion-Generation-under-Mixed-Assertion-Scenario)。

ASE 2026 的 *Escaping the Self-Repair Trap* 讨论围绕当前实现反复修正 oracle 可能削弱检错能力。本原型因此不通过“让候选测试通过”来修正 expected；论文设置与本项目的缺陷发现设置并不相同。[论文](https://arxiv.org/abs/2608.05917)。

真正需要实验支持的不是“代码能重构”，而是这种方格是否经常对应有效且此前缺失的行为交互，以及能否在有限预算下发现缺陷。目前尚没有支持这一效果的正结果，更没有测量 issue resolution rate 的提升。
