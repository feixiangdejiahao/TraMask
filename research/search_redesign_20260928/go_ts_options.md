# N05–N10：不构造 rival 的关系搜索反馈

2026-09-28。本轮只读原轨迹、源码和公开一手论文，没有调用 provider，没有运行新实验。原始案例证据见 [go_ts.md](../trajectory_logic_20260928/go_ts.md) 和其附带 SHA。以下是待实现的设计探索，不能当作已有算法能力或实验结果。

**建议优先试验一个很窄的核心：把共享对象上的多个输入，按照它们的“联合相对构型”分组，搜索尚未出现的组。** 同一分组不关心具体地址、任意字段名或整数有多大，而关心相等/先后、共享/分离、集合局部交叠。新测试即使走过完全相同的 branch，也可以属于新组。不生成另一份正确程序，不先推断业务规格，不以当前 candidate 是否已经把交互传播到断言为准。

但不能把“关系新颖性”直接宣布为创新：InvsCov 已经做状态分区和联合不变量违反，早期 relation-based testing 也已经按类型生成变量间关系。值得验证的是：**能否从真实 validation 的构造与绑定关系自动选出少量联合构型，用可执行输入变换高效到达它们。** 若只实现一张 relation coverage 表，本轮仍没有形成足够的新贡献。

## 2. 一个可机械计算的抽象，而非自然语言关系表

**观察窗口。** 在现有测试调用的入口/返回、已有 assertion 前和可解析回调的入口采样。窗口由静态调用位置与有界调用上下文标识；重复次数取固定小上界后合并。不尝试从 LLM 获得“flush 前”等阶段名。`flush` 前/后是两个具体调用边界；未采到的阶段就是该版本的覆盖边界。

**值的角色。** 角色是“参数/返回值/测试局部变量的来源位置 + 深度至多 d 的字段/下标路径”，实际对象按同一次执行中的别名关系对应。跨执行用构造来源和路径对应，不能拿裸地址比较。返回整数可带上产生它的调用 receiver，例如同一 DB 的序列号；表达式传播其来源标签。

**候选小块。** 先在同一测试资源根下，选至多 k 个可比角色。资源关联由 receiver/参数指向相同对象，或实际 def-use /共同构造来源给出。两种补充静态关联必须公开：同类型值流向同一形参/返回槽；字典/record 的 key 来自同一 generic 构造器。它们是 may-relation，会引入噪声。若只允许已发生的数据依赖，N09 被漏读字段根本不能进入搜索。

**对小块计算规范形式，词汇仅有以下三个基础域。**

| 基础域 | 精确计算 | 有限性来自哪里 |
|---|---|---|
| 有序值 | 对角色值及选中源码表达式的值，记录所有 `<、=、>` 的联合一致矩阵，即 total preorder | 固定角色数 k；不记录无界整数幅度 |
| 身份/缺省 | 角色是否缺席，以及对象的 equality/alias partition；源码常量如 `undefined`、`put` 单独保留 | 固定角色与常量表；地址只用于本次判等 |
| 有限集合/record | 对一个 key 在各集合中的 membership bit vector，记录哪些 vector 实际出现；已被源码字面 key 区别对待的 key 不重命名 | 固定集合数；任意新 key 的拼写被规范化 |

例如两个对象上的四个有序端点最多有 75 个 total preorder；如果已知各自起点严格小于终点，则剩 13 个 interval 构型。这里“已知”须来自输入构造或实际约束，不能把所有两字段对象都当 interval。四端点全联合矩阵很重要：分别覆盖每一对的 `<、=、>`，不保证曾出现 `a0 < b0 < a1 < b1`。

两个 key 集合只需区分交集、左差集、右差集是否非空，而不枚举所有字段名；这就是集合域 membership vector 的特例。`{a,b}` 与 `{a}` 已提供“共有一个、左侧另有一个”的最小见证。对象别名则是一组角色的集合划分。

一个抽象状态是“具体采样窗口 + 具体来源角色 + 上述规范形式”。这些键与运行值均由 AST/trace 算出，不包含自然语言解释。它是有损搜索分区，不是候选程序的语义等价类：相同 order 可能因距离、溢出、hash 或模运算产生不同行为。因此不能声称只测试一个代表便充分验证整个组。

## 3. 从分组到搜索：最小算法

1. 恢复已有 validations，运行 candidate，得到初始队列 Q 及已见规范形式集合 Seen。历史临时脚本也进入 Q；这一步直接处理 N06，而不计作生成成功。
2. 从代码和 trace 提取固定角色/表达式词汇。表达式只收录源码实际出现的有限纯表达式，例如 `start + count`，不任意合成深算术树。固定 k、访问深度 d、调用次数上界和最多保留的角色块数。
3. 对每个角色块，枚举尚未出现、且不违反已证类型/构造约束的规范形式。先选所需修改槽位少、支持该块的测试少的目标。未到达不等于不可达；超时只降优先级。
4. 对提供该块的 validation 做一步 AST 变换：替换一个可变输入槽、把已有同类型返回值/纯表达式绑定到后续槽、改变可重绑 receiver 的别名、删/复制 generic record 的一项、复用已有 collection/string 的插入/删除片段。重新命名局部变量并检查定义支配用途。每类变换是通用语法操作，不能含 case 名或目标 API 名。
5. 执行新测试，重算规范形式。到达新的形式就保留短测试；尚未到达时，可保留降低目标距离的有限数量中间种子。整数距离是未满足 order atoms 的数量及饱和数值差；集合距离是缺失的 membership vector 数；alias 是不满足的相等/不等对数。距离只是启发式，不是可达性证明。
6. 预算耗尽或目标到达后最小化测试，要求仍保留目标规范形式和原有效调用。已有断言/公开观察另行执行和报告，不把 candidate 的输出直接写成期望。

这里结构上省下的搜索是：不用为 `1,2,3,4` 与 `101,102,103,104` 分别保留种子，也不用为任意不同字段拼写保留同一 membership 构型；并且只变更 provenance 指向的测试槽位，不枚举仓库中所有常量。有限角色保证反馈空间有限，但其大小仍会随 k 与程序规模迅速增长。

**断言影响不能作硬保留条件。** 新输入如果没有影响当前断言，可能是测试观察过弱，也可能正是 candidate 丢掉了应存在的数据边。可以按已有 assertion 的 backward slice 近邻优先选择窗口；必须保留不在实际 slice 上、但与同一资源/返回槽相关的块。只有独立判断 oracle 有效，才能把失败叫缺陷。

**输入与观察的有限联系。** 复用已有公开读取表达式，允许对新生成的 record key /已有返回值补同类型读取；在已经存在的前后两个调用边界分别记录。它不会自动发明 N08 的可靠异步“仍未就绪”协议。如果 corpus 中没有这类等待/非阻塞读取片段，必须承认 observation generation 尚未解决，而不是说 value novelty 已经检测 bug。

## 4. 每例具体能算什么，哪里仍会卡住

| 案例 | 可搜索的具体构型 | 目前缺口与不能夸大的结论 |
|---|---|---|
| N05 | 同一 API 窗口中 preserve 标志 × 输入显示长度与 width 的 order；Style/Output 是不同调用位置 | 底层 fitting×preserve 在 STEP 54 已经执行。新颖性不会推翻 STEP 55/84 的错误接受；不能声称新抽象修复其 oracle |
| N06 | 同根 XML 对象上的 sibling-add 与 descendant-text 结构可给不同 key/path footprint 构型 | STEP 45 已执行且通过。恢复并在最终版本重跑才是首选；硬套生成会夸大贡献 |
| N07 | 两个 diff 结果在同一 base 来源上的四个 endpoint joint order，特别 `a0<b0<a1<b1` | hunk 字段和来源可采样；还要将外部 base/ours/theirs 文本变异到该内部构型。仅注入 hunk 不是完整 API 测试。通用文本片段变异是否有效尚待测 |
| N08 | 同 DB 的 target 与实际 `SeqNum+Count` 派生端点的 equality，区别于内部点与远未来点 | 绑定表达式是明确可实现操作；输出是就绪状态，可靠观察仍需已有 harness 片段。candidate 的错误 `<=` 不决定正确预期 |
| N09 | 同 trait 构造来源的 schema key 集与 params key 集，交集和 schema-only 差集同时非空；在 get 与 flush 后不同窗口采样 | 单字段 fixture 不可能有该构型，必须支持 generic record entry duplication + fresh key。只有 consumer 对 key 泛化处理才使用该变换；当前未实现。只采实际 read 集会把缺省字段丢掉 |
| N10 | same schema 构造下 mode 槽缺席/显式值 × dependent field 缺席/显式值的联合形式 | 删除已有 options 参数或 mode 字段很简单；只见 mode=undefined 并不够，需要与 requiredIf 结构绑定。参数 AST 缺席与运行 undefined 要分别保留，否则压缩掉重要上下文 |

后两例也说明，单纯给每个程序点增加“变量数值”反馈还不够。所需关系有时跨调用、跨输入构造，甚至涉及 candidate 没有读取的字段；必须先拥有输入结构的采样和来源关联。它们是实现要求，不是 trace 文件天然包含的信息。

## 5. 对三个候选方向的选择

**A. joint relational state novelty：优先做受控原型。** 优点是无需正确 rival、无需完整 spec；原型的数据结构、反馈、输入一步变换均能写出来。研究问题不是“关系比路径重要”，而是程序来源能否自动把昂贵的全笛卡尔组合缩成少量值得搜索的联合相对构型。若不给出块提取与输入 realization，仍只是旧 `(q,rho)` 换名。

**B. validation-induced empirical constraints：作为强 baseline。** 可以把成功 corpus 的常见关系反驳掉，但不能将“从成功测试中找偶然充分条件再反驳”视为新思想。InvsCov 已有直接算法；即使补上联合违反也不构成区别。若 corpus 很小或偏向合法输入，违反学习结果还可能主要得到无效输入。

**C. operation footprint / region overlap：作为 A 的一个 domain，不作为统一核心。** 对字符串区间、XML 路径、key 集、部分 object 写域很自然。但“字段集合”与“整数端点”要有可计算映射；把所有东西都写成 region 会隐藏这一步。动态 footprint 只显示已发生的 effect，buggy candidate 正好漏掉 effect 时域会变小；需要输入结构或静态 may-footprint补充，不能拿当前 effect 作完备真值。N08 scalar endpoint 和 N10 omitted option 也不需要强行空间化。

## 6. 一手文献：哪些现成思想不能声称新贡献

- [InvsCov, USENIX Security 2021](https://www.diag.uniroma1.it/delia/papers/usenixsec21.pdf)：从初始 corpus 学 likely invariants，把违反作为新反馈；包括状态分区、组合不同违反种子，以及 range analysis / comparability sets 剪枝。因此“违反经验关系”和“联合关系新颖性”已有直接先例。我们可能的区别只能来自跨 validation 的角色选择、结构域和可执行输入构造，且尚未证实。
- [Liu & Chen, JSS 2008: relation-based test generation](https://doi.org/10.1016/j.jss.2007.05.036)：预先按数据类型定义关系并作用于输入/状态变量。因此 `<,=,>,membership` 基础词汇本身不是创新；本提案必须说明关系实例如何从代码自动选择，而不是把人工挑选改成 LLM。
- [Contextual data-flow testing 技术报告](https://software.imdea.org/~alessandra.gorla/papers/Denaro-ContextualDF-TR07.pdf)：方法调用上下文能区分被简单 def-use 合并的状态交互。可借它限制哪些操作共享状态，但不把覆盖已有 def-use 当充分反馈；缺失的 def-use 边本就不能被它要求覆盖。
- [libFuzzer 官方 value profile 文档](https://llvm.org/docs/LibFuzzer.html#value-profile)：比较操作数的值特征能够提供额外反馈。它依赖存在的比较；本任务要补的是跨调用构造的联合值/对象结构，且不能只处理源码已经比较的那一对。
- [FuzzFactory, OOPSLA 2019](https://people.eecs.berkeley.edu/~ksen/papers/fuzzfactory.pdf)：可组合的 domain feedback 和保留 waypoint 已有框架。因此“自定义 feedback map 保留无新边的种子”不是新算法贡献；需要证明这个自动生成的搜索域确实减少浪费。
- [NASA MC/DC 教程](https://ntrs.nasa.gov/api/citations/20010057789/downloads/20010057789.pdf)：区分条件组合出现与条件独立影响结果，可提醒我们不要把共现当充分测试。但它针对已实现的逻辑条件，不会发现不存在的字段融合规则；不宜把 MC/DC 当本任务的新搜索目标。
- [Korat 项目及原论文目录](https://korat.sourceforge.net/publications.html)：有界结构测试生成已有长期研究。Korat 的项目接口需要 structural predicate 与 finitization；我们不能把“少量对象/字段即可找到见证”或“规范化同构输入”本身包装成新理论，也不能暗中假设已经有 repOK。

## 7. 必须用来攻击方案的反例与实验

1. **抽象盲区。** `x<y` 的两组值可因距离、溢出或哈希碰撞表现不同；深层结构、高阶共同作用、时间调度不在小 k 域内。不能由穷尽规范形式推出测试完备。
2. **无可比性。** 两值只有业务语义联系、没有共同资源或现有数据流，自动角色选择会漏掉；扩大到同类型全配对又会爆炸。这是目前最难的选择问题，不能靠“语义关联”四字跳过。
3. **输入不可实现。** 内部目标涉及经过解析/排序/压缩后的结构，外部输入变换可能无法到达；N07 是本组最直接压力例。最终应统计命中目标构型的比例与耗时，而非只报告目标枚举数。
4. **采样不足。** 在函数返回处采样不能看到瞬态错误；回调/flush 之间的阶段必须来自真实可执行窗口。动态 dataflow instrumentation 自身也可能显著拖慢预算。
5. **oracle 仍错。** N05 即使完全覆盖目标构型也可能通过；新构型计数不能代替 defect detection。N06 则应计入历史 test resurrection，不计入新组合生成。

最小实验应固定输入变换器与执行预算，只改保留/调度反馈：随机、edge、value profile、InvsCov 风格变量关系、此处 joint 来源结构分区。另做“无来源约束”“仅 pairwise atoms”“删除结构扩张”“仅已有 assertion slice”消融。报告有效测试率、单位执行得到的新目标构型数、目标构型实现率、最终公开断言/独立裁定下的缺陷检出率及人工 oracle 比例。执行次数与墙钟预算都要对齐，防止较重的分析仅用更多时间换提升。

**最强可检验主张：** 在已有 validation 附近，按同一资源上多个来源的联合相对构型保留种子，可以比只按路径或单变量值保留，更快找到有意义的遗漏输入关系。**最强反例：** candidate 根本没读取需要关联的字段，或现有 fixture 没有生成该字段的构造能力；若实现只看实际 def-use 或只替换常量，这个主张会在 N09 上立即失败。
