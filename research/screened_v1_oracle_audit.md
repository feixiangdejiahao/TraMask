# screened_v1 的 oracle 与来源对照审计

**本轮筛选存在明确误报，也没有检出 P3 的已知 alias 缺陷。尤其不能把“候选失败、参考通过”直接当作正确 oracle 的证明：本轮有 3 条这样的差分证据与 issue 明确矛盾。**

这是冻结生成物执行后的独立评估。读取范围为冻结 proposal/request、生成测试、候选代码、原有测试、issue 与执行日志；未读取参考补丁，未修改生成器，未把失败 ID 回流为生成筛选条件。[机器可核验记录](experiments/screened_v1_oracle_audit.json)包含全部分类 ID、断言输出、来源对照、issue 原文和文件 SHA256。

## 1. 实验版本与判定口径

本报告只归因于 `results/combination_screening/v1` 的冻结请求以及 `results/combination_testing/screened_v1` 的冻结测试。v1 请求包含 issue、原断言及同一输入的其他检查、具体变换 proposal；发送数量为 P1/P2 各 128、P3 为 89。模型只返回允许的 ID，不能修改输入、expected 或测试体。批准数量分别为 112、128、20。

`screening.py` 当前代码已增加既有事实矛盾检查、docstring 与校准样例；这些修改不属于本轮冻结请求，不能用 v1 的结果评价其效果。哈希与有限 ID 约束保证决定可追溯，但不能保证批准的断言语义成立。

候选报警独立定义为：生成测试在候选上失败、该测试声明的候选来源对照通过、没有全局执行错误。参考报警对参考实现独立应用相同定义。原始来源对照不是新生成的组合测试。差分证据另要求参考来源对照及同一冻结生成测试通过；仍需要独立的 oracle 审计与目标缺陷匹配。

| Case | 生成/执行 | 候选报警 | 参考报警 | 原始生成参考失败 | 差分证据 | 因来源对照阻断 | 参考来源对照失败 |
|---|---:|---:|---:|---:|---:|---:|---:|
| P1 | 112 | 47 | 15 | 36 | 19 | 24 | 4 |
| P2 | 128 | 35 | 15 | 43 | 2 | 28 | 3 |
| P3 | 20 | 8 | 1 | 9 | 1 | 8 | 2 |
| 合计 | 260 | 90 | 31 | 88 | 22 | 60 | 9 |

全部候选来源对照通过。本轮没有编译、导入、超时、跳过或未执行问题。已知目标匹配的差分证据分别为 P1 9 条、P2 1 条、P3 0 条；协议子集的已知目标检出是 **2/3**，不能用“各 case 都存在差分”报告为 3/3。

## 2. 31 条参考报警的根因

以下是对 31 条已通过参考来源对照的报警的互斥分类。序列省略共同的 `ESC [` 前缀；完整输入与逐条输出见机器记录。

| 根因 | 数量 | 具体例子及判定 |
|---|---:|---|
| 改变 phase 却保留旧 phase 常量 | 12 | `97;1:1u → 97;1:2u`，仍断言 `phase == "press"`；实际为 repeat。输入有效，断言语义错误。 |
| 改变决定 metadata 的值却保留旧值 | 9 | alternate `43 → 65` 仍要求 `shifted_key == "plus"`；primary `97 → 127` 仍要求 `base_key == "a"`；增加 shift 后仍要求整个 modifiers 等于只有 ctrl 的集合。 |
| 改变 modifier 的字符语义却保留字符 oracle | 3 | shift-only 的 `character == "A"` 被搬到非 shift 修饰快捷键；或给 `a` 加 shift 却仍要求字符为小写 a。 |
| 改变 associated text 却保留原字符 | 2 | text `65 → 233` 后仍要求 A，或反向变换仍要求 é。 |
| 丢失 text-only 适用前提 | 3 | key-code 0 原有非空 text，变换后删除 text，仍要求原字符；或把有实际主键的测试换为 code 0 且没有 text。这里只判定原 oracle 的前提丢失，**不声称它们一定违反线协议语法**。 |
| 参考结果与 issue 支持的 oracle 冲突 | 2 | P1 c0096：shift+alternate 保留、删除 text，期望 A，候选 A、参考 None。P2 c0098：shift-only 主键换为 65，期望 base_key a，候选 a、参考 A。不能自动算成生成器误报。 |

因此，31 条参考报警中，**26 条是断言语义不成立、3 条是适用前提丢失、2 条是参考与需求冲突**。前 29 条在候选上也均失败，日志显示失败发生在继承的字段断言；后 2 条候选通过。这里必须区分“输入无效”和“有效输入上的错误不变量”：前四类不能靠输入合法性检查解决。

## 3. 参考通过仍然错误的 3 条差分证据

三个 case 的 issue 均明确写道：

> shift-only printable Kitty events must preserve the shifted character and metadata, so character stays "A"

原文分别位于 `data/cases/P1/issue.md`、`data/cases/P2/issue.md`、`data/cases/P3/issue.md`；准确文件哈希已记录。冻结 proposal 的结果如下：

| Case / proposal | 冻结 obligation | source → follow-up | 继承的断言 | 候选输出 | 参考输出 |
|---|---|---|---|---|---|
| P1 c0032 | `transport_f5fab27797a7035e` | `65;4u → 65;2:1u` | `character == None` | `assert 'A' == None`，失败 | 同一断言通过 |
| P2 c0032 | `transport_a2efe54e72cc3a87` | `65;4u → 65;2:1u` | `character == None` | `assert 'A' == None`，失败 | 同一断言通过 |
| P3 c0017 | `transport_a90e7721574e9276` | `97;4u → 97;2:1u` | `character == None` | `assert 'A' == None`，失败 | 同一断言通过 |

这里 modifiers 的 wire 值 4 表示 shift+alt，2 表示只有 shift。删除最后一个非 shift modifier 后，快捷键的 `character=None` 前提消失；候选返回 A 符合 issue。**三个 source control 在候选和参考上全部通过**，所以加强来源对照门控也不能排除这种误报。参考通过只说明参考也接受了这个错误 oracle。

应新增独立评估指标 `issue_contradicted_differential_witness_count = 3`，并对这三条作 oracle 审计否决。22 条差分证据扣除它们后还剩 19 条待按语义和目标归因的证据，不能直接宣布 19 条都是真缺陷。P3 的唯一差分正是被否决的 c0017，与其 alias 目标无关。

## 4. source control 失败如何影响结论

参考上有 9 条原始断言失败，涉及 shift 字符 A、base_key 的小写归一化和 text-only metadata。它们已经在未变换的 source 上失败，不能归因于新组合。

88 条原始生成参考失败中，**57 条的参考来源对照失败**，剩余才是上述 31 条参考报警。受参考来源对照影响的生成测试共 60 条，其中 3 条生成测试本身仍通过。90 条候选报警中有 **39 条**关联失败的参考来源对照（P1 14、P2 19、P3 6）；这些候选报警仍应保留，但参考无法提供有效的组合增量判定。既不能把它们全算误报，也不能删除后报告较好的 precision。

因此 `31/200` 只能叫“参考来源对照通过的 200 条生成测试上的参考报警比例”。参考本身有需求冲突、数据集缺少独立正确实现总体，不能称为方法的全局 FPR；`88/260` 更混入了来源对照失败。

## 5. 可泛化的修正方向

1. **先做既有断言的确定性矛盾检查。** 将结构化输入规范化；若 follow-up 已在已有测试中出现且同一观测量的断言与继承 oracle 冲突，直接否决该不变量。这个规则不需要参考执行，也不以 pilot ID 为条件。
2. **分开检查输入适用前提与断言保持性。** “code 0 必须具有可用 text 才适用原 text-only 字符 oracle”属于前者；phase/metadata/字符改变属于后者。程序依赖只说明可能影响，不足以证明不变量，也不能据此一律拒绝有依赖的 membership 关系。
3. **以同一测试族的对照事实推导 guard。** 原断言、字段角色和明确需求共同区分 shift-only 与非 shift shortcut、成员保持与整个集合相等。发现反例时拒绝该搬运规则，不把 expected 改成候选或参考的当前输出。
4. **单独校验模型准入能力。** 混入由既有测试事实构造的成立/不成立对照，模型若批准明显矛盾的断言就整体拒绝本次准入结果。有限 ID 输出只能防止篡改，不能代替这种校准。
5. **评估保留三层证据。** 独立候选报警、实现间差分、需求与目标语义审计分别计数。参考实现是比较对象，不是需求真理；审计记录只能用于结果归因，不能回流为失败 ID 黑名单。

本报告没有重新生成或运行测试，也未据参考结果筛除生成物。所有分类完整保留，便于后续在新 case 上检验通用规则，而不是隐藏当前失败。
