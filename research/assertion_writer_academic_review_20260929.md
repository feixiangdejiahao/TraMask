# 当前写入来源机制的独立学术审查

本审查针对 [method_design.md](method_design.md) 与 [assertion_writer_search_20260929.md](assertion_writer_search_20260929.md) 的当前方法和证据，没有新增实验、模型请求或文献检索。

**目前得到的是一个有局部证据的研究方向，尚不是经过统一验证的学术方法。** 断言反向切片、定义与使用关系、对象绑定、可能异常路径、运行时最后写入跟踪和覆盖驱动的候选保留，分别都是已有技术。将它们组合起来可以解决实际问题，但不能仅因组合了这些技术，或给一个记录字段的 tuple 命名，就主张创新。这里值得检验的具体想法是：让原断言仍能执行，同时引导组合去改变它所读取状态的产生过程；写入来源究竟能否帮助选择更有价值的后继组合，需要算法对照证明。expected-slot 接口将模型限制在期望表达式，改善可执行输出运输，但它本身没有证明新 oracle 正确，也不能充当搜索机制的创新证据。

现有正面证据可靠但范围很小。相同候选池、相同预算下的 **3/8→4/8** 证明静态异常路径优先级在开发集新增检出 N01；这不足以判断收益是否来自写入分析，还是一般“优先尝试异常输入”就能得到。32 组真实 trace 说明相同源断言确实观察到不同写入，而插桩未改变测试结果；它是机制可测量性的证据。N01/N02 的关键观察却同时发生 writer 与布尔值变化，所以还不能说明 writer 比普通断言值反馈多提供了有效搜索信息。73 次读取不是 73 个独立缺陷；离线保留的 14 个代表中仍有 6 个错误 oracle 和 1 个未知，也不能当作搜索精度。已绑定观察约 5.25%，其余观察和非 Python 场景尚无统一分析。这些结果足以支撑原型和研究假说，不足以支持“普遍有效的组合缺口检测”或提高 issue resolution rate 的论文结论。

**最有判别力的最小实验，是只移除前沿 key 中的 writer。** 两臂固定同一构造器、源断言、静态排序、初始队列、候选去重和预算，均使用同一 source q、allocation、class/field 与精确标量值；实验臂额外保留实际 source writer，对照臂只去掉这一项。必须真实在线执行“观察→保留父候选→生成后继”的相同流程，不能只在已生成材料上离线挑代表。按相同轮数和固定的实际执行次数停止，无 LLM、无语义缓存；报告控制通过且完整 oracle 正确的检出数、首个正确检出的执行成本，以及仅因 writer 区别而被保留的父项是否最终贡献了新检出。unsupported 与 unknown 仍占同一预算规则，不能只选出现 writer 新颖性的案例。这样才能把写入来源的增量与值变化、候选生成能力和模型质量区分开。

若两臂获得相同检出和成本，尤其所有有用的新 writer 都已经由新值区分，那么当前“writer 反馈有额外搜索收益”的主张就没有支持；应保留已经证实的局部静态排序收益，而不是增加术语解释负结果。若出现稳定收益，需给出完整执行链证明：某个相同值、不同 writer 的父项在对照中被合并，但其后继暴露了独立确认的问题。这个结果仍须在规则冻结后、未参与设计的独立任务上复现，才能讨论 general。现有 17 trials 全部参与过开发，用它们再次得到更高覆盖仍是开发集改进；不应把两例局部机制扩写成统一解释全部 17 例的框架。
