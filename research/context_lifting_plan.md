**组合生成实验约定（执行结果产生前）**

开始时间：2026-09-23 07:37 UTC；用户给出的开发上限为五小时。已有检索基线保留在 `retrieval-v0.2`。本轮目标是完整的自动生成、oracle 构造、执行及缺陷判断；七例上零误报、零漏报是待验证条件，不能用检索成功替代。

核心抽象为**观察在上下文中的保持关系**：已有测试观察 `o(P,x)`；把另一种行为作为输入/调用上下文 `C` 加入，检查 `o(P,C[x])` 与由原观察运输得到的期望，或与另一条等价执行路径的观察是否一致。程序分析负责找到适用的输入位置、数据/捕获依赖及可执行改写，不用自然语言 schema 代替算法。

两种 oracle 构造操作共享这个抽象：

1. **运输已有 oracle**。例如改变 Path 变量中的文件名并正确引用它，原测试使用同一 Path 变量构造的期望随之变化。不能仅修改调用参数却冻结旧的常量断言。
2. **执行路径比较**。例如同一脚本函数从宿主调用或在脚本内部调用；同一递归结构由 recursive 构造或有限展开。期望来自独立执行路径，不能读取参考补丁产生期望。

输入因子独立性、API 等价性等若只由样例推断，都是待验证的 oracle 假设，不是可靠性定理。依赖集合包含不提供组合后断言有效性的证明。

固定规则：

- 种子优先使用当前检索 top-10 测试；其他来源/绕过检索的操作必须单独记录。
- 生成器只能读取候选 repository、候选 patch、issue、已有测试及检索记录。人工目标、manual annotations、隐藏 verifier、reference patch 不进入生成器。
- 先保存全部生成源码、来源、算法版本及哈希，再由独立 evaluator 对候选和参考运行同一份测试。参考失败不能被静默过滤；必须记录 oracle/构造失败，并说明任何后续修订。
- 原 seed/control 与组合测试分开记录。编译、导入、超时、环境失败不等同于语义缺陷；同时不能当作成功覆盖。
- 评价同时报告 case 检出、未检出、有效测试数、候选/参考的逐测试结果及无效 oracle。七个 case 只有四个 issue 家族，属于已知发现集；不得宣称未见数据泛化或普遍零误报漏报。
- 初始 v1 不调用外部模型、不发送代码。2026-09-23 07:59 UTC 用户更新目标，明确授权少量必要的 LLM 辅助及向 `.env` provider 发送数据；之后仅局部语义契约判断可使用模型，仍不发送隐藏 verifier、人工目标、参考补丁或凭据。所有版本使用 Git，旧结果保留。

初始生成操作由可复用的表示/结构语义决定：结构化字符串因子组合、文件路径引用运输、容器/闭包上下文提升、递归有限展开。每种操作需要独立的合成例子验证适用条件；不使用 pilot ID、目标行号或测试名称的特例。

必须警惕：这些操作是语言/协议适配器，不得将七个手写触发程序包进统一接口后声称自动生成。最终报告应明确区分自动提取、固定语义先验、人工选择和尚不支持的部分。
