# 固定检索入口的模型生成对照

2026-09-23，本计划在对照请求和执行之前固定。已有源码类比变体未确认有效缺陷，因此增加一个简单对照，检查其构造限制是否是主要瓶颈。它是独立基线，不作为测试类比方格的实现或效果。

- 输入固定为 `results/generic_observation_priority/batch2/pilot/P1` 至 `P7` 的冻结 corpus、issue 和 production context。每例统一选择 `retrieval_rank <= 10` 的父测试，按 rank 和 ID 排序；不根据已知目标或旧实验结果选择测试。
- 模型看到所选父测试、已有静态事实和原有生产上下文；生产代码明确可能包含缺陷。源测试展示集合与原候选准入请求不同，因为后者只包含已构造候选的来源，零候选时会为空。因此不是完全相同 prompt 的消融。
- 使用用户指定的 `deepseek-v4-flash` 和更新后的 `.env` provider。每例预先指定 r1、r2 两次请求，每轮最多 3 个完整父测试 body 替换、最多 10,000 输出 tokens。两轮分别冻结、分别执行，不合并后挑选最佳轮次。
- 输出只有已有 parent ID 和代码。模型可以构造输入及断言；不要求它填写自然语言意图或 oracle 证明。固定语法及父作用域检查失败的项保留为无效生成，不自动修正或重试。
- 不向模型提供先前候选、执行结果、参考实现、隐藏 verifier、人工目标或封存评价真值。不用待修代码的运行输出补写 expected。
- 保留源测试控制。评价者先独立审计输入适用性和断言依据，再进行参考差分；原测试失败、编译失败、错误 oracle 和 unknown 都不计有效检出。

主要报告两轮各自的目标命中、错误/未知报警、无效生成和成本。每轮 3 个模型直接生成项与每轮最多 128 个类比候选具有不同的生成能力和预算，不能把结果差异仅归因于程序分析或模型能力。此对照也不是新颖方法的验证；根代理已经看过此前结果，七例仍属于开发集。
