# 17 trial 时间盒实验：结果与方法边界

本轮目标是在 2026-09-28 02:34:25–07:34:25 UTC 的五小时内，自动构造正确组合测试并检出全部 17 个目标缺陷。**目前没有达到 17/17。** 本文先记录已经核验的结果，第七批断言恢复消融仍在运行。

17 个 trial 对应 14 个不同 task，全部属于已见开发集。程序规则没有按 case ID、目标测试名或目标答案分支，但规则的选择和改进受开发集诊断影响；独立小程序测试不能替代未见任务评价，也不能证明没有过拟合。

第二至第六批每例最多两次模型请求。第五批起，执行上限从每例 64 增至 192，不能把所有改进都称为等总预算改进。各批静态池、实际提供条数与物化条数也有差异。细节和复核命令见各批报告。

## 实际改进在哪里

程序从源验证恢复输入坐标、对象来源、调用顺序和已有观察。字段/下标路径现在属于坐标身份，避免把同一参数中的字符串字段和布尔字段混为同一位置。解析输入可沿源码正则 capture、辅助函数传参和 `split` 继续细分；字段原本不存在时，单纯交换已有值不够，需要恢复源码语法支持的可选片段。

原断言候选不再被模型的接受/拒绝直接删除。模型只补充受限的期望修改，输入和操作仍由程序产生。此变化恢复了 N10 已经构造、却被准入阶段遗漏的见证。它没有让原断言自动变得正确：N05 的宽度变化形成了所需输入，但旧期望仍要求截断结果。

历史测试的恢复也更可靠。Python 脚本保留晚出现的 import 执行顺序；Go helper 和导入名称依据真实依赖包声明恢复，控制与组合测试采用相同物化规则。N02 从三个有效历史候选增加到八个有效候选，仍只计一个 trial。N07 的正确重叠场景从编译受阻变为真实目标失败。这些属于实现可靠性改进，不各自包装为学术贡献。

第六批的 14 个漏检可以定位为：11 例在实际物化候选中没有目标关系，P3/N05 两例已经形成目标关系但期望错误，P2 一例期望正确却观察太弱。这里的 11 例不意味着静态池所有未提供候选都已被证明无效，也不意味着无限预算下无法构造；它包含关系表达、构造和候选预算选择的共同限制。静态恢复目标原测试已达 17/17，因此继续提高原测试名召回率本身不足以解决主要瓶颈。

## 目前能够支持的学术判断

**关系与观察必须共同构造。** P2 提供了明确反例：目标输入关系已经出现，正确的 key 断言也存在，但 character 错误完全不可见。因此，“有效期望”与“足以检出目标”不同。第七批统一恢复原观察，保持每一项输入、操作和异常 guard 的源码编辑不变，检验断言切片是否造成额外漏检；动态执行轨迹可能因恢复前置断言而改变。P2 的输入 `ESC[65;4;97u` 在第六批通过 `key == "alt+shift+a"`；恢复原来的 `character is None` 后，实际 `'a'` 使其失败，两个完整原控制通过。它证明这一实例的漏检确实来自观察选择，不证明单个观察的抽象普遍劣于完整测试。

完整观察也有代价。P3 恢复的旧 Ctrl 期望会更早失败；P4 在源操作已经改变后恢复旧代码内容断言，得到错误期望造成的失败。消融还会产生新的测试 ID 和组内排序；例如 P6 函数内容不变，仍因组内 panic 前可执行数量不同而改变具名结果数量。因此不能把所有通过/失败数变化都归因于观察恢复，更不能先验认为保留全部断言一定更好。

**坐标必须体现对象、字段和阶段。** 同一参数不等于同一字段，同名表不等于同一数据库中的表，同样的 `get` 不等于同一个执行阶段。N04、N09 表明，仅有 may-dependence 或同名调用不是组合适用性的充分证据。

**边界是关系表达式，不一定是常量的邻居。** N08 的目标是由多个状态修改共同确定的排他上界。取已有数值的 `±1` 可以生成邻近输入，却没有自动求出这个上界。整数类型依据排除了已识别非整数类型导致的一类非法构造，不是完整类型检查，也不解决动态端点恢复。

这些是开发集支持的观察，不是已经验证的新定理。当前 `(q, ρ)` 是明确的研究单位，但实现仍依赖多个有界关系域适配器；有限单元闭包尚未统一解决上述对象、树、递归和动态边界关系。不能因为有大量规则、单元测试和执行设施，就把它宣称为成熟的统一算法。

## 误报、漏报与 issue resolution rate

已有确认检出意味着部分已知目标不再被该验证策略漏检；仍未检出的 trial 必须保留在分母中。它不意味着候选补丁已被修复，也不意味着所有缺陷都被覆盖。

误报尚未完成穷尽标注。已确认过时期望和错误组合，同时有大量失败的 oracle 仍为 unknown。抽查到的错误条数变化不能用来计算整体 precision 或宣称误报率下降。

本轮只评价组合测试能否检出候选补丁中的目标缺陷，没有进行“相同修复代理、有/无组合测试反馈”的配对修复实验。因此，**尚无 issue resolution rate 提升的实验证据**。
