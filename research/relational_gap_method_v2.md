# 从验证见证补齐关系，而不是拼接完整测试

本轮核心抽象是 **带观察的关系单元 `(q, ρ)`**。`q` 是已有验证中真正观察程序状态的表达式；`ρ` 是可控输入、对象和操作之间的一种关系。目标是构造一个新测试，使它在同一次执行中实现 `ρ` 并检查 `q`。关系构造与正确期望是两个独立问题。

例如，已有测试分别使用 `f(1, 10)` 和 `f(2, 20)`，观察相同的结果字段。程序可以发现 `(1, 20)` 尚未在这个观察下出现，并以一次参数编辑构造见证。若已有测试分别使用两个不同对象，程序可以构造两个参数引用同一对象的关系。若源码比较 `target < high`，程序可以求 `target = high` 的输入。它们共享的操作是：**划分关系空间、找未见单元、构造短见证**，具体 API 的名字不参与定义。

## 为什么需要这个抽象

新增十条轨迹的分析见 [发现集报告](expanded_trials_20260926/README.md)，逐例关系、证据边界及论文来源见 [研究假说](expanded_trials_20260926/abstraction.md)。这些案例说明三件事：

1. **同样的两个操作可以形成不同关系。** “两次修改”既可能分离、重合，也可能部分重叠；只统计操作是否出现无法区分它们。
2. **关系必须绑定到具体对象和观察阶段。** 内存解码异常与正常流关闭分别通过，不说明同一个真实流在异常时会关闭；flush 后的观察不能代替 flush 前的观察。
3. **组合可以已经发生，却没有改变断言能看见的状态。** UPDATE name 与 COUNT invariant 同时运行，对检查字段约束是否会拒绝非法写入几乎没有信息。

因此，研究单位应是 `(q, ρ)`，不是“test A 加 test B”，也不是模型自由生成的一组自然语言 feature。程序依赖用于定位关系的参与者、恢复构造和保持对象绑定；不能把 may-dependence 当作应有行为，更不能因为 buggy candidate 缺少传播边就拒绝构造测试。

## 算法的核心

设 `Vq` 是与观察相关的输入位置，`Rq` 是可从源码和已有验证恢复的有限关系域。测试为这些位置提供值、对象绑定和动作顺序。有限域内尚无源见证的关系单元是新的搜索目标：

```text
for q in existing_observations:
    relations = recover_relations(q, source, validations)
    for rho in unseen_cells(relations):
        t = construct_small_witness(q, rho)
        if an independent expected result can be justified:
            execute t with unchanged source controls
```

`unseen` 在当前实现中首先指**静态源验证中未见**，不是已经计算出完整的 `Checked_P(q)`。历史测试未在最终候选重放，不能直接当作当前覆盖；存在断言，也不证明该断言在新场景中正确。源码编辑可构造，也不证明运行一定实现目标关系。三个层次在实验中分别记录。

[closure.py](../relational_gap/closure.py) 实现有限单元枚举和最少坐标修改的见证选择；[cells.py](../relational_gap/cells.py) 将源调用位置及观察映射到这些坐标。其余前端和测试框架适配用于恢复、物化和执行见证，不作为额外的学术贡献。

## 程序负责的工作

**恢复验证。** 从最终仓库与 trajectory 恢复测试、临时脚本及不同文件版本，区分覆盖写和追加写。Python 编辑脚本生成的测试源码可以静态恢复，编辑脚本自身不因此成为运行验证。历史 Go 文件重命名以减少符号冲突，仍必须通过编译与原控制重放。Python/TS 脚本可以转为标准测试入口；打印是观察，不自动成为正确断言。

**恢复局部程序关系。** AST、局部 def-use、实际参数到形式参数的传递、构造对象来源、显式 import/reexport 和调用顺序共同定位关系。先补齐有界 import 依赖再建立索引，避免只因文件检索预算而漏掉未修改的接口包装层。调用同名只能产生弱假设，不能升级成已经证明的同一方法。报错消息和测试框架诊断参数不是被测输入。

**构造关系见证。** 当前支持的是有限的子集：源参数值形成的联合单元、record 字段存在性、源码默认值对应的省略、可代换的数值比较边界、同一对象引用、源字符串片段编辑、异常出口的已有观察、同一 receiver 的一至两步源操作，以及简单 SQL 读谓词与写字段的交互。复杂别名、一般区间反求、任意嵌入语言和并发时序没有被这些规则自动解决。

各关系域按固定预算轮换；相同观察/绑定下已经存在的值组合降级为低优先级。源码字段默认值是比普通 record 子集更强的依据。语义未知的合法构造仍可保留为假设，交独立期望判断与执行，不把未知直接等同不可行。

**选择一个观察。** 新见证可只保留程序选定的 `q`，中和其他断言的失败机制，同时保留其必要表达式求值、动作、上下文管理和清理。完整原测试作为对照运行。这里的支持范围有限，无法保留求值语义的复杂断言会退回完整测试候选，不宣称任意断言都能安全切片。

## 少量 LLM 的职责

模型看到 issue、必要源码、源测试和程序已经提出的编辑。它可以判断局部期望的适用性，并在程序指定的期望位置给出纯表达式；不能自由修改测试输入、动作、观察位置或生成完整测试。纯表达式只使用已有期望、静态输入和有限运算，先在本地求值成常量，再写入测试；不能调用被测程序获取答案。

第二版使用请求内短编号，源测试只发送一次，模型只返回选择和局部期望。每例最多两次请求，每次最多展示 64 项、接受 32 项，单请求源码与提案上限 80 KB。单个格式错误只拒绝对应条目。请求、原始响应、解释器结果、代码哈希和所有运行均保存，缓存重放与重新请求分开。

这些限制使模型的修改范围可复现，并不使其语义判断可靠。模型保留一个错误旧断言，仍会制造误报；因此“模型接受”“测试失败”和“确认目标缺陷”必须分开。

## 如何评价

17 条 trial 全部是已见发现集，实际涉及 14 个 task。不能把它们当作独立盲测。

| 层次 | 成功含义 |
|---|---|
| 源测试恢复 | 目标验证的源码、输入与观察进入分析范围 |
| 候选来源命中 | 候选使用了目标源测试；不代表形成了目标关系 |
| 场景命中 | 生成测试确实实现目标 `ρ`，对象和阶段正确 |
| 正确 oracle | 对 `q` 的要求有独立依据，适用于该场景 |
| 目标缺陷检出 | 原控制通过，新测试执行并因目标缺陷失败 |

首批完整结果是 **0/17 目标检出、15/17 源测试及候选来源命中**，并已确认部分错误 oracle。见 [首批独立评价](relational_gap_batch1_evaluation.md)。[第二批](relational_gap_batch2_evaluation.md)恢复目标源测试及候选来源 **17/17**，正确组合并检出 **1/17**，唯一确认案例是 N10。其输入编辑是把显式 `parser({ mode: 'put' })` 改成 `parser({})`，沿源码两层调用找到默认值仍为 `put`，保留已有缺失条件必填字段应抛错的断言；完整原控制通过，新测试因未抛错失败。

第二批共 830 项模型获准候选；272 项失败有通过的原控制，其中只有上述一项已确认为目标缺陷，另有四项已确认错误 oracle，267 项的 oracle 未定。不能把其余失败都计作缺陷，也不能据此声称精确率或误报率已改善。34 次请求全部完成且无协议错误，仅说明通信和格式恢复有效。

第三批完整评价仍为 **1/17**，唯一确认目标仍是 N10，见 [第三批评价](relational_gap_batch3_evaluation.md)。809 项获准候选中，256 项失败有通过的原控制：1 项目标、1 项已核验错误 oracle、254 项未定。错误 oracle 只进行了有限抽查，不能用“4 项变 1 项”宣称误报减少。新增数值规则还暴露出将指针比较错误当作整数边界的问题；后续批次要求整数类型或源整数表达式依据。布尔断言的隐式 True/False 期望成为受限孔，程序仍保留原观察表达式并只改变极性。

第四批在冻结准备中补充下列源关系载体：解析器正则捕获字段、源码调用上下文 `C[f(x)]`、三份源字符串对应的行编辑区间、惰性生成器的字面量 yield 坐标。它们分别提供有限字段联合、调用项嵌套、Allen 区间关系和异常出口关系的可编辑位置；只生成假设，不声称这些位置自动具有正确语义。现有 256 个种子内部增加基于已解析调用路径的排序：其结果流入断言且能到达修改函数的调用优先，然后是未被断言观察的相关调用，再保留未解析者的原顺序。未解析调用不被删掉。这些都是关系见证的前端支持，不各自宣称新的学术贡献，也不能把独立小程序的成功计入 17 例结果。

这一抽象是否有论文价值，仍需验证它是否优于等预算的随机源片段组合、普通 pairwise 与分支/边界生成。程序关系分析、组合覆盖和可观察性各自都已有研究；不能把它们列成一个流程就当作创新。可检验的主张是：**从 agent 的实际验证恢复观察相关的关系域，能否在没有人工 feature model 的条件下，以较少见证发现已有验证遗漏的真实缺陷。**
