**正式流程的输出**

- `targets.json`：D 的候选范围、查询位置和完整 B。F 复用查询位置，避免重新读取和解码 Patch 源码。
- `slices/`、`views/`、`graphs/`、`episodes/`：各入口的原始端口与程序起点、共享程序视图、源码依赖图和按需展开的轨迹起点。调用参数对应、注释、测试属性和内嵌程序分析继续保留。
- `material_entries.json`：选中动作的原因、数据文件来源和 B 记录 ID。保留 JSON/XML 读取、相关 `git diff/show`、独立验证及其 snapshot；原文仍由已有材料持有。

实际未执行的源码使用其创建时或所属快照，恢复该状态下的 helper、setup 和调用者。没有可绑定文件版本的命令字面量按单份源码分析，保留其命令来源。

**独立 Codex 审查及处理**

启动了两个 `fork_turns="none"` 的 Codex 线程：`joint_alignment_function_review` 和 `joint_alignment_prototype_review`。它们分别检查功能与来源对应，以及原型简洁性、效率与输出规模；均只读审查。主线程确认问题后修改，并请原审查线程复核。

|确认的问题|处理|
|---|---|
|结构化读取先被扩展名筛掉；`git diff/show` 及 `revision:path` 漏选|在读取识别中标记结构化内容，保留源码变化读取与正确文件路径|
|未命中程序查询的独立验证缺少邻接 snapshot|将选中验证动作提及的目录纳入 snapshot 关联|
|Python 编码声明被重复处理，测试边界和非 ASCII 调用者错位|源码在读取边界规范化；测试发现和调用者检索共用规范化内容|
|未执行测试只能看单文件，缺少 helper/setup/跨文件调用者|按材料创建时或所属快照建立静态上下文|
|批量入口漏掉内嵌程序，静态导出漏掉未解原因和状态依赖|共同切片统一导出已有分析结果|
|同一进程中不同实现或 fixture 版本被同时确认为依赖|保留 `version_alternatives` 和未解原因，停止生成混合版本的确定调用/setup 边|
|Python `*args`、keyword-only、`**kwargs` 参数对应错误|按形参类别建立对应；无法确定的展开参数保留未解信息|
|不可解码的 Patch 源码使 F 终止|F 复用 D 查询；编码和语法问题作为有原因的未解析源码保留|
|轨迹重复加载、重复测试发现、相同视图因入口不同而重复保存|共享已加载轨迹和内容版本缓存；程序起点留在入口组，视图主体共享|

多版本问题采用保留候选的方式处理。现有 IO 记录不能给每一次函数调用确定具体源码版本，因此没有枚举版本组合。候选版本仍能从共享 trajectory 回读。

复核确认上述问题已关闭。独立效率检查确认轨迹 JSON 由三次读取降为一次，同一源码的测试发现只执行一次；最后一轮未发现新的必须修复项或明显过度设计。
