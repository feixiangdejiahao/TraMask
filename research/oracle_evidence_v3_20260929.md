# 候选输入变化的程序证据整理

输入侧算法现在对**修改后的测试重新解析和绑定调用**，再把与输入编辑、受影响观察有关的完整声明与原测试交给模型。程序不生成行为解释或正确预期；模型仍然只处理本次候选的预期是否需要改变。入口是 `relation_search.oracle_evidence.build_evidence(corpus, frontend, candidate)`。

## 程序具体做什么

1. 用发射器同一套 `_program_edits` 恢复业务编辑，去掉运行探针，核对每处原源码并应用编辑。候选中的新增导入别名按其来源文件解析；跨目录的相对导入先重定位。
2. 对修改后源文件重建 frontend，重新计算调用目标、直接实参到形参、局部绑定和调用到观察的 may 依赖。换了 callee 或 receiver 时，不沿用原图的绑定。Go 导入还要求显式 module 路径相符，单凭 package 同名不够。
3. 以编辑位置、编辑值的 use、编辑局部绑定为起点，找到相关调用和观察。对 `box.value = ...` 这类堆写，补上同一个局部绑定在后面被 receiver/实参使用的 may 边；不同变量或重新赋值后的对象不因字段同名而混为一谈。这里的“后面”只表示源码顺序。
4. 提供相关调用的完整声明。输入直接关联的 callee 向下一层展开；同一观察的其它生产者提供直接声明。外部 API 接收本地函数值时，也展示那个函数的真实声明，同时注明 callback 的调用时机未知。
5. 提供 candidate 已记录的来源测试，并检索“解析为同一 callee、具有同一修改后实参”的原测试作为直接证据。每次匹配最多取两个完整原测试；原测试的预期仍不自动成为正确规范。
6. 如果排序器传入 `impact_evidence`，附上原图中“编辑影响 actual，而 expected 没有相同编辑依赖”的观察义务。原图和修改后图坐标明确区分。

输出既有本地完整 JSON 事实，也有给模型的 `rendered` 文本。JSON 中的关系来自程序，不要求模型填写关系 schema。调用、观察、源码路径和共享依赖路径使用局部短引用；每个原图节点和每个完整源码段只展示一次。长 actual 表达式用 source span 指回同时提供的完整 modified test 或声明，没有截掉函数尾部或测试断言。无解析依据的调用、动态时序、字段副作用、深度边界保持显式 unknown。

默认 48,000 字节是诊断阈值，超过时标记 `over_budget` 并保留文本。它不意味着断言无需修改，也不意味着候选没有 gap。完整 modified test 和 issue 由 oracle 请求层单独保留。

## 不使用评价标签的 17 任务检查

从固定库存 `candidate_inventory_v1` 的每个任务按 `SHA256(candidate.id)` 排序取前 8 个非 source profile 候选，共 136 个。没有读取目标测试标签、隐藏 verifier、Oracle 回答缓存，没有调用模型或执行 subject。源码输入、算法快照、抽样方法和结果均封存。

原始事实采集：`results/relation_search_20260929/oracle_evidence_v3_census_final/`。

| 程序证据 | 候选数 / 136 |
| --- | ---: |
| 无分析异常 | 136 |
| 找到修改输入到调用的连接 | 133 |
| 找到相关观察 | 122 |
| 找到至少一个真实 callee 声明 | 104 |
| 找到完整来源控制测试 | 79 |

覆盖数字表示存在静态证据，不是 combination-gap recall，也不是这些候选的预期已经正确。新补充的字段写连接在独立 toy 中验证；这个 136 条样本中没有新增这种边。

事实采集累计约 239 秒，包含完整输入侧再分析。缓存原始 Source 的解析树，每次仅重新解析被修改的源文件；目前仍为每个获选语义候选重建一个仓库索引，所以此步骤仅应用到实际准备送模型的少量候选，不用于全部候选池排序。较大仓库约数秒每条。

进一步对同一 136 个完整 JSON **只重新渲染**，压缩重复边和路径，没有重新选样或改分析事实。最终 prompt 辅助文本保存在 `oracle_evidence_v3_rendered_final_v2/`，每条都指回原事实 JSON 的 SHA256：

- 中位 8,587 字节；最小 1,131，最大 67,275。
- 135/136 小于等于 48,000 字节；余下 1 条仍完整保留。
- 总字节 2,434,739 → 1,489,100，主要减少重复 call→observation 边、长哈希和路径。

另一个未使用目标标签的复杂样本按固定 N04 库存中“程序义务 JSON 最大”选出，包含 13 个义务、71 个唯一原图节点。将完整义务重复 JSON 改为共享节点/路径引用后，辅助文本由 116,395 降到 40,947 字节；13 个义务和完整声明均保留。它是表示体积检查，不是方法命中目标的实验。

## 验证与边界

新增 21 个测试覆盖 Python/Go/TypeScript 数据依赖与实参形参、改 callee、改 receiver、新导入、跨目录导入、字段写、不同对象、重复赋值、callback、完整来源测试、显式超预算、探针去除、共享图渲染等；与已有 frontend/evidence 相关测试合计 **66 passed**。

独立评价 agent 对原 136 份事实核对了 2,160 个调用、518 个观察和 847 个声明：记录的完整代码与修改后源码字节一致。对 428 个支持的 Python 直接实参形参绑定用独立 AST 复算一致；其余 1,055 个其它语言或不支持形式的映射只检查来源，没有据此声称它们全部得到独立语义证明。

这批检查没有测量 LLM 正确率、误报率或 gap 检出提升。动态 dispatch、反射、外部实现、闭包执行时机、跨线程 happens-before 和精确 heap alias 仍不完备；源码可达也不等于路径可执行。后续模型实验应固定候选、预算和随机条件，再比较是否提供这些证据。
