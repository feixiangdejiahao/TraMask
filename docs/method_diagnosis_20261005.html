1. 当前问题抽象与真实算法

早期抽象把问题称为“已有测试没有覆盖行为组合”。这个表述指出了现象，却没有定义可计算的缺口。同一 API 对可以作用于不同对象、不同键或不同执行阶段。调用都出现过，也不代表测试观察了它们的共同后果。既有探索记录。

初始状态、动作序列、对象及参数绑定、观察阶段和正确性依据，可组成测试有效性检查表。这五项本身尚未定义研究缺口。它们也适用于许多已有测试方法。

更有辨识力的问题是：原输入能否区分不同实现行为？原观察能否检查相应契约后果？前者需要输入细化，后者需要观察补全。一个方法可以处理两者，但必须分别说明必要机制。

当前实现按固定顺序组合多个受限构造。它使用文档默认值、值包装与还原、异常路径收尾、语义筛选和声明顺序变化。后续组件加入量值上界、字段 null、CSI 输入域修复和单行重组。最新组件加入 SQL 谓词改写与 Unicode 字符串细化。各分支仍依赖特定语言或源码形态。

2. 最近一年论文怎样设计 idea

本节选择 2025-10-05 至 2026-10-05 期间相关顶会论文与已录用论文。它是面向当前问题的定向比较，不是完整系统综述。下表使用官方会议页和作者原稿。预印本日期与会议年份分别标明，不把 arXiv 上传等同于正式发表。

这些论文先确定一个具体缺口，再选择软件工程结构来约束搜索。它们把大模型用于语义理解、补全或选择。程序负责可检查的事实。有效的 idea 因此需要回答：缺少什么证据，哪个机制能补上它，以及何种实验能证明该机制必需。这个归纳来自下表，不是对所有顶会论文的统计结论。

3. 新颖性应怎样判断

已有论文使用相似组件，不足以否定 novelty。问题抽象、算法目的、必要机制和新增能力共同决定贡献。反过来，更换术语或加入一个分析模块，也不足以证明贡献。必须展示该模块改变了哪些可构造测试，并解释为何这些变化能发现原方法漏掉的错误。

当前更值得投入的主线是：公开契约约束下的输入细化。已有完整测试提供性质。方法寻找新的合法输入，使实现采用不同的处理方式，同时检查原性质仍然适用。这里保留的是测试性质，不要求输入内容或全部输出相等。

R24 与 R25 支持这条主线。两者都保留了足够的原断言。检出来自新的区分输入。N09 的默认值假设也需要不同输入；其跨实体级联假设则需要新的观察。后者应作为另一条待验证分支，不能用来证明前一机制。

潜在贡献不在于首次使用 SQL 重写、Unicode 边界或大模型。贡献可能在于自动绑定公开契约、实际输入位置和完整测试性质，从而构造有效区分输入。当前窄构造只证明存在这种机会。它们还没有证明统一的自动机制。

当前输入还包含较完整的公开需求。它直接列出了若干交互规则和边界条件。因此，不能仅凭算法提取出这些关系，就宣称它自动发现了未知意图。直接使用同一需求的大模型基线必须获得相同语义信息。只有构造成功率、有效检出或成本出现稳定差异，才支持方法贡献。

问题层面的贡献还需要发生频率证据。应在独立项目中测量：多少缺陷已经覆盖相关代码，却缺少合法组合或足够观察。若大部分失败仅来自生成器的类型错误与旧预期，研究重点就应转向可靠测试构造，而非提出新的覆盖概念。

必要机制应围绕构造障碍设计。程序确定可编辑位置和作用域。公开契约确定输入域及保留性质。大模型提出解释并选择源码依据。程序执行受限编辑，再独立审查完整测试。源码引用证明出处，不证明解释必然正确。

目前应把 novelty 写成待验证假设。统一规则不等于没有开发过拟合。即使代码没有任务白名单，人仍可能根据已见缺陷选择变换族。若每个新项目都需要人工新增规则，现有结果就不足以支持可推广的构造算法。

与 MR-Coupler 比较时，应检查已有完整性质是否减少了关系构造需求。与 STARS 比较时，应区分改变输入和增加观察。与 IntentionTest 比较时，应固定目标、前提和预期的可用信息。相似组件不能代替这些问题层面的比较。

4. 方法探索为何停滞

主要问题是优化目标多次偏离有效缺陷检测。候选更多、请求成功率更高和测试失败更多，都可能只表示产生了更多错误测试。此前对 136 个首个受控失败的审计得到 10 个有效、117 个无效和 9 个未定。该有界样本不是全体候选的误报率估计。完整审计。

早期反馈没有充分进入生成规则。错误角色绑定和旧预期反复出现。近期规则已固化部分输入域与完整性质约束。当前主要缺口转为：这些规则如何自动选择，以及它们能否适用于未见任务。继续增加审计设施不能替代这个问题。

部分探索过早开发了复杂搜索。地址连接原型没有产生真实候选；观察跨边界原型也没有契约支持的机会。先统计源码是否提供必要原料，可以更早否证构造假设。零候选说明本次规则和源码提取没有找到适用项，不能解释成规则精确率高。地址连接记录；跨边界记录。

N08 暴露了更深的 oracle 问题。公开注释说明 Batch.SeqNum() 返回首条记录的序号。两条记录的序号应为 s 和 s+1。原测试却要求最高已持久化序号至少为 s+2。保留完整原测试，也会保留这个缺乏契约支持的断言。原文、字节位置与 SHA 审计。

同一审计发现，实现把排他上界用于最高持久化序号，并允许等待该边界。因此，“查询返回值再等待该值”可能通过，同时两个 API 共享错误。这里的通过判断是源码推断，不是新增实验结果。必须从记录数量与公开边界语义建立独立预期。超时本身也不能证明功能缺陷。

5. 优先探索方向与证伪标准

第一优先级是验证一个窄而明确的构造假设：当原测试已有足够观察时，契约约束的输入细化能否增加有效见证。分别记录输入域、保留性质和完整断言依据。跨实体观察作为独立分支评估。

关键对照使用相同模型、原测试、源码、公开文档和格式事实。直接 LLM 也获得相同变换规则说明，并可一次生成一个候选。两组共享审查与执行流程。固定总 tokens、候选数和原生执行预算。若补齐信息后直接生成达到相同效果，就不能把增益归因于专门构造器。

上下文恢复应先排除比较混杂。N08 原目录检索 163 条，实际纳入 23 条，省略 140 条。增加同名声明又引入大量无关项。受限声明 ID 选择将让模型选择源码条目，再由程序提取完整文档。该检索步骤本身尚无检测收益证据。统一普查与负结果。

源码普查应先检查新增构造是否能改变判别能力。round19 发现对象方法绑定扩展预计新增七个空值候选。但这些候选只来自一个任务族，且源码已经正确拒绝非聚合条件的 null 结果。目前没有新增检测证据，因此暂缓开发。该计数是源码投影，不是新生成器的实测结果。完整普查。

第二优先级是研究独立 oracle 的来源。为候选记录契约前提、期望关系和完整断言依赖。显式检查原测试是否已编码实现错误。优先研究能从公开数量、边界或规范状态导出预期的场景。如果预期只能由当前实现或相互依赖的 API 给出，应标记未定并停止该构造。

一个较窄的独立 oracle 家族已有两个项目的源码机会：完成 n 个单位操作后，数量或序号边界由契约确定。N08 的同步提交与首序号可推出末序号 s+n−1。P4 的回放契约可推出执行计数的增量。P4 原测试已有对应检查，因此不能据此宣称增益。先用直接生成基线检验这类关系，再决定是否值得设计专门构造器。源码收据与反例。

第三优先级是先做小规模契约机会普查，再选择一个构造机制。N03、N04、N09 不能简单合并成“前后相等”。dry-run 需要已有可读状态；回滚需要真实失败；延迟执行需要明确的实体等价语义。它们是否共享可执行条件，应先由源码与契约决定。

观察补全的最小假设是：从公开契约选择标量观察 Q，在已有动作前后检查规定关系。原 R06 只能迁移已存在的 Q，因此没有有效候选。后续普查应检查能否从原对象和参数构造正确观察，并证明表达式有定义且只读。无适用宿主时停止扩展。

后续实验应预先固定一个新机制、候选顺序和预算。在开发任务上检查适用性，在未见项目或任务族上检查泛化。比较直接 LLM、检索编辑、同预算的关系生成，以及去掉绑定或阶段约束的版本。除有效检出，还应报告完整测试有效率、弃权率、候选数和实际成本。

评估集也应包含没有目标缺陷的版本。当前已核验组合的十四个有效告警只支持这批告警的正确性，不能估计任意项目上的误报风险。按项目或任务族划分数据，避免同一任务的多个试验同时进入开发集与测试集。

成本应分别记录源码普查、模型调用、原生执行和独立审计。保留实测 tokens 与缺失用量的预留值。回放成本不能代替重新运行的成本。这样才能判断改进来自更好的约束，还是更长的搜索时间。

应预先规定停止条件。若方法只对已见任务有效，或依赖人工挑选实例，就不主张可推广机制。若增益只来自更多执行，或去掉核心约束后结果不变，就拒绝该因果解释。若新增关系只复现已知检出，便不宣称新增检测能力。这些标准是未来实验建议，不是已满足的结果。
