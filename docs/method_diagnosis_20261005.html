问题有研究价值。当前证据尚未证明一个具有稳定增量能力的统一算法。主要缺口在于：方法没有持续把失败原因转成可执行的构造约束。近期实验获得三类新增见证。声明顺序变换揭示了错误的全局槽位绑定。量值上界发现了超长 tail 未受宽度约束的问题。字段 null 变换发现了缺失字段与显式 null 被合并的问题。这些结果尚未证明统一机制的泛化能力。

1. 当前问题抽象与真实算法

早期抽象把问题称为“已有测试没有覆盖行为组合”。这个表述指出了现象，却没有定义可计算的缺口。同一 API 对可以作用于不同对象、不同键或不同执行阶段。调用都出现过，也不代表测试观察了它们的共同后果。既有探索记录。

建议用五项描述一个待验证义务：初始状态、动作序列、对象及参数绑定、观察阶段、正确性依据。只有这五项同时成立，测试失败才可能支持缺陷结论。行覆盖、类型兼容和方法名相似只能提供局部证据。

当前保留实现采用固定顺序的构造分支。程序先尝试文档默认值，再尝试值包装与还原，再检查异常路径收尾，再使用语义筛选和声明顺序变换。此后，组合按顺序加入量值上界、字段 null 构造与历史候选审查。各分支仍依赖有限的语言和源代码形态。不能把它概括成已经解决任意行为组合的通用搜索。

3. 新颖性应怎样判断

已有论文使用相似组件，不足以否定 novelty。问题抽象、算法目的、必要机制和新增能力共同决定贡献。反过来，更换术语或加入一个分析模块，也不足以证明贡献。必须展示该模块改变了哪些可构造测试，并解释为何这些变化能发现原方法漏掉的错误。

当前最值得验证的主张是：已有测试包含相关行为，却没有在正确对象和阶段上检查契约要求的后果。这个主张比“增加行为组合”更具体。它也可能与现有方法重叠。需要用相同输入、模型与预算比较，不能仅凭论文摘要宣布别人无法处理。

当前输入还包含较完整的公开需求。它直接列出了若干交互规则和边界条件。因此，不能仅凭算法提取出这些关系，就宣称它自动发现了未知意图。直接使用同一需求的大模型基线必须获得相同语义信息。只有构造成功率、有效检出或成本出现稳定差异，才支持方法贡献。

问题层面的贡献还需要发生频率证据。应在独立项目中测量：多少缺陷已经覆盖相关代码，却缺少合法组合或足够观察。若大部分失败仅来自生成器的类型错误与旧预期，研究重点就应转向可靠测试构造，而非提出新的覆盖概念。

潜在必要机制是带条件的测试构造。源码确定作用域、类型、值流和插入点。公开契约决定操作能否组合、观察应在何时成立，以及新增动作是否破坏原断言。大模型提出契约解释并给出出处。程序把解释变成有限编辑。源码引用只能证明出处，不能证明解释正确。

目前的结论应是“贡献假设尚待验证”。round03 没有增加检出。round04 与 round06 没有生成候选。round05 则检出了 round03 漏掉的 P6。round08 又从公开量值契约构造了新见证。round09 还区分了字段缺失与字段值为 null。原测试没有直接调用该 API。这些结果支持分别研究表示条件与 oracle 来源，但尚未证明跨项目的稳定收益。直接把多个窄适配器包装成统一框架，会掩盖尚未解决的构造缺口。

4. 方法探索为何停滞

主要问题是优化目标多次偏离有效缺陷检测。候选更多、请求成功率更高和测试失败更多，都可能只表示产生了更多错误测试。此前对 136 个首个受控失败的审计得到 10 个有效、117 个无效和 9 个未定。该有界样本不是全体候选的误报率估计。完整审计。

反馈没有充分进入生成规则。修改输入后保留旧预期、把同类型值放进错误角色、把同名方法绑定到错误对象，这些问题反复出现。仅把审计结论放进下一轮提示，难以阻止同类错误。应把已确认的错误模式转成可检查的前提，但不得把评估标签或隐藏测试反输给生成器。

部分探索过早开发了复杂搜索。地址连接原型没有产生真实候选；观察跨边界原型也没有契约支持的机会。先统计源码是否提供必要原料，可以更早否证构造假设。零候选说明当前规则没有适用空间，不能解释成规则精确率高。地址连接记录；跨边界记录。

N08 暴露了更深的 oracle 问题。公开注释说明 Batch.SeqNum() 返回首条记录的序号。两条记录的序号应为 s 和 s+1。原测试却要求最高已持久化序号至少为 s+2。保留完整原测试，也会保留这个缺乏契约支持的断言。原文、字节位置与 SHA 审计。

同一审计发现，实现把排他上界用于最高持久化序号，并允许等待该边界。因此，“查询返回值再等待该值”可能通过，同时两个 API 共享错误。这里的通过判断是源码推断，不是新增实验结果。必须从记录数量与公开边界语义建立独立预期。超时本身也不能证明功能缺陷。

N09候选混淆 Trait 与 Relation；新原型的 world.has 不符合 Entity.has/get 契约范围。需要确认 owner、entity 与执行阶段。部分原测试已经检查 flush 前后；不能统称为缺观察位置。
P1输入去掉 CSI 事件子参数，却保留释放事件预期。编码字段决定事件阶段。需要从协议导出预期，不能沿用旧常量。
P2新审查采用的 CSI 输入把大写字母作为主键码。公开 Kitty 协议要求未 Shift 的主键码，并明确禁止该形式。这是不合法输入，不是已确认目标缺陷。原测试也使用该形式；原控制通过不能证明输入有效。
P4旧候选误用 POSIX 引号规则。新 null 候选又假设“字段必须存在”意味着“字段可为 null”。两个假设均缺少公开依据。异常模板消融已对成功测试中的 null 变换弃权；这不等于目标缺陷已解决。

P6 已从漏检表移除。迁移函数保留源槽位编号，却切换到目标全局数组。原测试让两个实例的被读变量占据相同槽位，因此遮蔽错误。新测试交换目标声明顺序后，在函数调用处失败。后面的源隔离断言尚未执行，不能将它们报告为动态通过。完整证据。

5. 优先探索方向与证伪标准

第一优先级是建立失败原因账本。对每项记录“无原料、绑定失败、无法构造、未执行、契约未定、有效执行但未检出”。先完成现有队列，冻结一次共同输入与预算。若所谓改进只改变解析、缓存或执行机会，应报告工程改进，不归因于新语义机制。

第二优先级是研究独立 oracle 的来源。为候选记录契约前提、期望关系和完整断言依赖。显式检查原测试是否已编码实现错误。优先研究能从公开数量、边界或规范状态导出预期的场景。如果预期只能由当前实现或相互依赖的 API 给出，应标记未定并停止该构造。

第三优先级是先做小规模契约机会普查，再选择一个构造机制。N03、N04、N09 不能简单合并成“前后相等”。dry-run 需要已有可读状态；回滚需要真实失败；延迟执行需要明确的实体等价语义。它们是否共享可执行条件，应先由源码与契约决定。

可检验的最小构造是：从同一完整测试选出动作 B 和标量观察 Q；确认 Q 在前后都定义、只读且由契约保证不变；保存动作前的 Q；执行原动作及原断言；再比较 Q。绑定检查不能证明堆隔离。当前 TypeScript 原型在此规则下没有候选，应保留负结果，停止扩展该原型。

后续实验应预先固定一个新机制、候选顺序和预算。在开发任务上检查适用性，在未见项目或任务族上检查泛化。比较直接 LLM、检索编辑、同预算的关系生成，以及去掉绑定或阶段约束的版本。除有效检出，还应报告完整测试有效率、弃权率、候选数和实际成本。

评估集也应包含没有目标缺陷的版本。当前已核验组合的十个有效告警只支持这批告警的正确性，不能估计任意项目上的误报风险。按项目或任务族划分数据，避免同一任务的多个试验同时进入开发集与测试集。

成本应分别记录源码普查、模型调用、原生执行和独立审计。保留实测 tokens 与缺失用量的预留值。回放成本不能代替重新运行的成本。这样才能判断改进来自更好的约束，还是更长的搜索时间。

应预先规定停止条件。若方法只对已见任务有效，或依赖人工挑选实例，就不主张可推广机制。若增益只来自更多执行，或去掉核心约束后结果不变，就拒绝该因果解释。若新增关系只复现已知检出，便不宣称新增检测能力。这些标准是未来实验建议，不是已满足的结果。
