研究问题和当前抽象

开发智能体可能分别测试两个功能，却没有检查它们同时发生时的结果。例如，正常流读完后会关闭，坏 JSON 会报错。两项测试都通过，仍不能证明流在解析报错后也会关闭。

我们把这类遗漏称为组合验证缺口。它需要对应任务需求或已有接口约定。有效联合测试需要让相关条件作用于正确的对象，并检查联合操作的结果。仅让两个函数出现在同一个测试中还不够。

验证缺口说明测试缺少什么。实现错误说明程序违反了什么要求。补上缺失检查后，测试可能通过。测试失败时，我们需要核对实际失败的检查是否有依据。

本文另设完整测试的计分标准。只有输入合法、全部期望有依据且失败可复现的完整测试，才计入有效检出成绩。如果已执行部分揭示了错误，但后续期望未定，报告保留前面的证据，整个测试不计入该成绩。

开发记录对应 trajectory。它包含智能体阅读代码、修改文件、选择测试和执行命令的过程。记录中的运行结果可能来自旧代码版本。它不能直接证明最终补丁正确。

本轮程序分析把缺口表示为若干语法和历史线索。模型再从测试、源码和开发步骤中确定具体补测内容。程序尚未可靠建立对象、字段、资源和代码版本之间的全部关系。这限制了当前算法。

P2：Textual，区分快捷键和文本输入。已有不带文本的快捷键，以及仅报告文本的消息。同一字母按键消息包含 Alt 等修饰键和附带文本。检查快捷键名称，以及可输入字符应为空。
P7：Valibot，递归数据检查与值转换。运行测试使用 readonly，检查输出等于输入。另有测试检查转换前后的类型。在递归数据检查中加入真正改变值的转换。实际解析树，并按转换位置检查正确结果。事先没有限定必须使用外层转换。

上述补测内容在生成之前保存，只用于评价。模型不接收手选理由和目标标签。模型仍需从原材料自行确定遗漏检查，并构造测试。

有些目标仍含需求解释。N01 的原需求要求流式 JSON 迭代关闭响应，但没有逐字列举解析异常路径。本次评价把关闭要求用于已经开始迭代后的解析异常。N08 的边界和同步时序依据仍不足，不能把该假设当作已确认错误。

P7 的数据检查规则描述节点字段及子节点结构。readonly 只提供类型层面的只读说明，不改变实际值。transform 会执行给定函数并改变值。把转换放在单个字段内部，与放在整个节点规则之后，会经过不同执行路径。

P7 事先选定的范围是递归输入中的实际值转换。它没有限定转换位置。第二次发现错误的测试把转换放在整个节点规则之后。报告将这个具体发现与较宽的事先范围分开。

N08 的持久化是指确认数据已经可靠保存到磁盘。NoSync 表示本次写入不主动要求同步。它不能保证其他操作之后也不触发同步。因此，等待一段时间是否收到通知，必须结合具体执行时序判断。

第二部分的方法：模型如何生成和执行测试

A 组读取公开需求、手选完整原测试和相关源码。B 组读取完全相同的材料，再增加手选原始步骤。每对输入只差开发步骤。手选目标、后续生成测试、隐藏测试和参考实现没有进入提示词。

两组的请求次数和每次生成数量上限相同。B 组增加开发步骤，输入更长。这个对照同时改变信息内容和上下文长度，没有把两者的作用分开。

B 组使用保存的 28 条完整原始步骤。其中 23 条带有非空 reasoning_content，即原智能体的私有推理记录。这些字段进入了本次输入。P7 的 4 条步骤不含非空私有推理。因此，本文不能直接说明只使用普遍可获得的公开记录会得到什么效果。后续自动流程已将这些私有字段排除。

每次模型请求最多返回两个完整测试。模型可以改写测试内部代码。它保留测试框架识别该测试的定义部分，包括函数名和参数。程序检查结构和导入来源，再为接受的新测试另取名称。完整原测试继续保留。

写入测试的程序只检查代码结构、导入来源和修改范围。它不检查期望结果是否正确。这项判断由实验评价中的逐项审查完成。

P7 可以使用从原仓库确认存在的 transform 导入。模型不能修改产品代码。

程序执行所有通过结构检查的新测试，没有用另一个模型提前筛除它们。它同时执行完整原测试作为环境对照。任何失败都会再运行一次。程序不把新失败日志返回给模型修改断言。

输出格式问题如何处理

第一次的 16 次请求中，7 次因提示词没有出现 JSON 字样而被接口拒绝，1 次回答截断。我们保存结果，再对全部输入统一增加同一条格式说明。第二次仍有 1 次截断，来自 N08 的 A 组。

代码检查程序还拒绝了一些不改变含义的格式差异。我们统一处理生成测试的末尾空白和导入名称表示。对于仅省略末尾分号、其余结构符合要求的 TypeScript 新测试，我们补回分号。处理没有修改测试输入、操作或断言，也没有修改原测试。

第一次恢复 1 个测试，第二次恢复 7 个。下文分别给出未进行格式修复时，以及统一修复后的结果，避免把输出格式失败和测试思路失败混为一谈。

如何处理误报和漏报

测试中的自动结果检查称为断言。分析助手先核对输入是否合法，以及全部断言是否有需求或接口依据，再查看运行结果。测试通过不证明断言正确。某个早期断言有效失败，也不能使后续无依据的断言变得有效。

本轮允许程序保留无关材料，也允许所有可执行测试进入运行，以观察模型生成了什么。报告只把完整测试有依据且两次失败的结果计入有效检出成绩。输入错误或期望错误属于无效测试；无法确认的期望单列为未定。

完整测试未定，不表示其已执行部分没有价值。我们核对实际失败位置，保留有依据的失败观察，同时标明哪些后续检查没有执行。这两个判断分别报告。

这种审查减少报告中的错误告警，但不能保证自动方法没有误报。自动程序没有完成最后的输入和期望核对。

八个手选目标没有覆盖所有可能缺口。因此，本文不能计算整个问题范围的误报率或漏报率。

模型未揭示指定问题时，我们分别记录输出失败、错误输入、无依据期望、补测方向偏移和目标未进入测试。它们都没有完成本次目标，但原因不同。

N04：真实失败证据与完整测试成绩为何不同

A 组先注册“姓名不能为 Bad”的约束，再执行把一行姓名改为 Bad 的更新。任务要求拒绝更新。两次运行都返回退出码 0，即报告成功。有依据的“退出码应非零”检查两次失败。这提供了更新未执行约束检查的错误证据。

同一个测试还要求最终两行数据按固定顺序返回。接口没有保证这一顺序，所以该期望仍未定。这项检查位于失败断言之后，实际没有执行。报告不能把数据恢复也算作已经观察的结果。

因此，N04 提供一项有依据的失败观察，但没有提供全部期望均可靠的完整测试。它不计入完整测试检出分数。我们没有在看到失败后删除或修改后面的期望。

P7 的有效失败实际证明了什么

A 组把外层转换设为大写转换，再实际解析树。原测试两次通过，新测试两次失败。日志明确显示根节点值仍为 a，而测试要求 A。

源码显示，递归规则的解析准备代码覆盖了组合规则的运行函数，丢失外层转换动作。这为根节点失败提供实现依据。日志省略子节点，所以本报告不声称动态确认了子节点差异。首个断言失败之后的 safeParse 检查也没有执行。

这个新测试只因缺少末尾分号而被格式检查拒绝。因此，未进行格式修复时的有效检出为 0，统一恢复分号后才得到 1。两种成绩都需要保留。

第一次的 B 组把每个节点的字符串字段转换为字符串长度。输入是三层树，字段分别为 aa、bbb 和 c。测试检查输出分别为 2、3 和 1，实际运行通过。它补到了事先指定的递归值转换检查。

该测试的转换位于字段内部，没有经过后来发现错误的外层转换位置。它增加了有效验证，但没有揭示那个实现错误。我们不能因它通过，就把它改判为偏离事先目标。

这个测试起初因新增导入的文本格式被程序拒绝。统一修复格式后，它才进入执行并通过。报告保留两种处理结果，且没有把通过测试计为错误检出。

未揭示目标的原因和研究新意

材料提取的主要问题是关系不够准确。路径和调用名称可以定位材料，却不能确认操作与结果属于同一对象，也不能确认历史验证对应最终代码。

记录显示，模型多次选择了预选目标之外的检查。它仍生成单独功能、类型要求或其他状态检查。B 组收到历史添加与文本修改脚本，却没有恢复该联合检查。但第一次 B 组的 P7 测试补到了递归值转换，说明目标选择并非总是失败。

现有实验没有分开测量目标发现、目标排序和代码生成的作用。因此，我们把目标偏移记为直接观察，将“目标选择是主要瓶颈”保留为待验证的解释。

另一问题是模型增加了无依据的要求。修饰键编码、解析器生命周期、数据库返回顺序和同步时序都需要接口知识。增加更多断言可能增加误报，而非提高有效验证。

记录支持这些可观察的原因，却不能直接证明原智能体遗忘逻辑或只追求代码覆盖率。分析应记录读过什么、改过什么、运行过什么，以及哪些结果未被检查，再区分事实和原因推测。

本方法潜在的学术新意在于：从开发过程恢复一项遗漏或失效的联合检查，再用程序关系指导补测。其他论文使用过程序分析、测试变异或大模型，不能单独否定这个研究目的的新意。

当前实验尚未证明新的有效算法。论文需要展示，恢复对象、条件、结果和版本关系能稳定改善补测。仅把开发记录交给模型，再让模型自己发现问题，仍缺少这项证据。

下一步的小规模实验

下一步可以把每项待补测检查写成六项事实：需求依据、前提条件、操作、结果检查、对象或资源，以及代码版本。每项事实链接原测试或开发步骤。程序负责恢复可核对的关系，模型负责确认遗漏并实现测试。

先检查的问题程序分析需要恢复什么提供给模型的具体补测要求判断是否成功
N06：恢复已有验证临时脚本、它调用的实现、后续修改和再次执行情况。保留添加与文本修改的原组合，按需求加入结果断言。实际恢复联合验证，并单列为历史验证恢复。
N04：让更新真正检验约束同一数据库和表；约束读取哪些字段；更新修改哪些字段。让合法更新破坏约束。检查拒绝和最终数据，不依赖未承诺的行顺序。完整测试有依据，并能区分约束生效与未生效。
P7：区分类型检查和实际值检查数据检查规则的结构、转换位置，以及测试实际检查的结果。将转换放在整个节点规则之后，分别检查根和子节点的具体值。实际执行转换结果断言，不用只读类型代替运行结果。

先用分析助手整理的事实检查这种表示是否有帮助，再让固定程序自动生成同样内容。两步应分别评价，避免把手选目标的帮助记为自动能力。

比较时可使用三种输入：原源码材料、同样材料加原始开发步骤，以及同样材料加结构化事实和证据。三组使用相同模型和调用次数。先检查目标是否进入测试，再比较完整测试有效性和有效错误证据。

N08 应先确认边界和同步时序的期望。仅等待超时或观察通知返回，不能在前提不足时证明持久化错误。其余扩展也应先恢复对象和条件关系，再生成测试。

结论的适用范围和复核材料

本实验使用已经研究过的小样本，材料选择和最终审查依赖分析助手。它适合定位方法问题，不能证明新任务上的普遍效果。它没有评价补丁修复、最终任务解决率或自动零误报。
