组合测试补强 v3：实现与验证

2026-10-09。本次完成算法修改，并运行本地回归测试。另对上一轮实验的查询、候选和执行记录做回放。本次没有调用 DeepSeek，也没有重新运行 benchmark 或修复原补丁。

核心变化是：程序先说明条件如何影响操作及观察结果，再检查生成测试是否保留这些条件。模型负责解释需求、判断缺口和编写测试。程序不再只提供函数名与关系名。

问题抽象

一个候选包含三项内容：相关输入或状态条件；受这些条件影响的具体操作；测试应观察的结果。原测试也按一次调用组织。程序保留该调用的条件取值和断言，不把多个独立调用拼成一个联合检查。

组合缺口仍然是待检验假设。要确认一个能够揭示错误的缺口，测试必须满足关键条件，并使用需求支持的断言。断言还需区分错误实现和正确实现。源码中的联合条件未被检查，并不证明原补丁有错误。

程序现在提供什么

分析对象提供的具体证据保留的限制
条件控制后续操作条件表达式、候选取值、受控语句和源码位置。程序代入能确定的布尔条件，说明分支允许或排除哪些操作。分支成立不证明整个路径可执行。更早的退出、异常和调度仍可能阻止执行。
提前退出影响继续处理退出条件、退出语句、可能被跳过的后续调用。T10 的证据连接缓存预热、退出和结果输出。后续操作被阻止可能就是缺陷。程序不会要求错误实现必须先执行到后续操作，才承认这个目标有效。
局部默认值传递原对象字段、局部变量、默认值、继续传递的实参，以及下游读取该字段的条件。局部赋值不等于修改原对象。程序也不会仅凭这条联系排除中间写入。模型需要核查源码和需求。
原测试范围同一次调用中的已知条件、未知条件和断言。未知值单独列出。源码位置支持进一步查阅。这些记录不证明测试已经执行，也不证明断言足以发现错误。

例如，程序可以连接“省略 mode”“局部 mode 采用默认值”和“下游继续读取原 options.mode”。模型据此判断省略参数与显式默认值是否应产生相同结果。模型仍需从需求确定正确断言。

已修正的流程

测试查询现在真正使用 path、start_line 和 end_line。给出路径时，程序搜索快照中的全部已索引测试。不给路径或测试标识时，程序才查询当前候选的测试。分页只作用于匹配结果。没有匹配结果时，程序返回明确状态。

生成提示现在明确说明追加位置。append 会把代码加入完整文件末尾。新代码位于文件顶层。模型不能直接使用另一个测试函数或测试组内部的局部变量。提示还要求模型查看导入和文件末尾。

查阅预算与反馈预算已经分开。默认最多用三次模型调用查阅材料和生成首版测试。首次生成后，另有两次调用检查结果和修正。即使第三次调用才生成测试，反馈机会仍然存在。测试执行上限仍为两次。所有调用仍受总 token 预算约束。

执行反馈先展示失败和错误，再展示通过或跳过的测试。程序会读取完整结果文件，避免失败记录被前面的跳过记录挤掉。Go 的结构化输出也会进入反馈。因此，缺少导入等编译错误可以传给模型。

候选如何选择

程序同时考虑需求相关性、具体条件、直接的行为影响，以及修改与原有行为之间的联系。它会降低大范围代码因词语多而获得的额外优势。它也会降低与已选候选高度重合的证据。提取阶段和模型处理前都使用这套排序。

排序只读取公开需求、原补丁和程序分析结果。它不读取 gold patch、benchmark 失败或目标标签。每项评分都保存在结果中。这些权重目前是启发式选择。它们还没有经过独立数据验证。

如何防止测试丢失关键条件

程序从现有条件维度中提出有限的取值组合。模型可以选择或调整目标。流程会在后续调用中保留目标。生成过测试后，模型若要改变条件，必须说明原因。查询失败不会自动取消原目标。

生成后，程序重新解析新增测试，并追踪实参到目标条件所在函数。中间函数仍参与实参传递，但不占用目标条件的记录额度。程序检查同一次调用是否满足目标条件。对于追加测试，检查只使用新增测试定义。旧测试不能替新增测试提供证据。

检查结果含义
源码支持一次调用中的已知条件符合目标。它不证明测试实际执行或断言正确。
未保留分析得到的相关调用都与至少一个目标条件冲突。例如，目标要求省略参数，但测试显式填写了该参数。
未知程序不能确定必要条件，或者调用关系不完整。它不会把未知当成条件已经满足。

当前检查主要覆盖简单布尔条件、对象字段存在性和可求值的简单值类别。共享对象身份、跨异步阶段和复杂动态调用仍可能返回未知。当前实现没有自动证明测试经过真实配置校验，也没有完整解决解释器宿主语言与被解释语言的区别。

验证设置和结果

本地回归使用可控的小型 Python、TypeScript 和 Go 源码。模型调用由预定动作替代。部分测试会在临时仓库中运行 Python 测试，以检验错误反馈和修正机会。这些结果验证实现行为，不测量模型能力。

78 项回归测试通过。其中包括路径和行号查询、追加作用域提示、最后一次查阅后的修正机会、目标更换检查，以及关键条件保留检查。

关键条件回归覆盖三种情况：显式默认值不能替代省略参数；两次独立调用不能替代一次联合调用；追加文件中的旧测试不能替新增测试满足条件。另一个回归检查确认：共享身份无法确定时，程序保留未知。

研究意义与尚未证明的部分

值得验证的研究主张是：让分析结果在“候选选择、原测试范围、模型输入、生成后检查”之间保持相同的条件含义。这样可以追踪一个行为区别是否在补测中丢失。测试查询和预算修正是实现基础，本身不是核心学术贡献。

当前实现形成了可检验的原型。它还没有证明这种表示能提高错误检出率，也没有证明启发式排序优于其他选择方法。后续模型实验应沿用已有的错误检出标准，并单独记录条件未知的比例。不能把通过回归测试解释为论文效果已经成立。
