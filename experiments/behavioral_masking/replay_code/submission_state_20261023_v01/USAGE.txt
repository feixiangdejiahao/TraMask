TraMask submission-state replay code snapshot

This directory preserves the replay implementation used for the 2026-10-23
state audit. replay_code.tar.gz contains 17 source/test/tool-semantics files,
at their original repository-relative paths. manifest.json records every SHA-256;
the archive contents were read back and checked against these hashes.

Working source remains in src/tramask_pilot/ and scripts/. The two reviewed
case-specific runners remain under:
results/behavioral_masking/20261023_tramask_replay_n40_r01/submission_state_audit/full_replay_v02/

Keep this snapshot unchanged. Later code changes should receive a new snapshot
version, and later experiments should write into a new run directory.

Requirements
------------
Host Python >= 3.11; the replay implementation uses the Python standard library.
Docker CLI/daemon are needed to execute subjects. Tests additionally use pytest.
The existing workspace .venv satisfies the Python requirements.
The subject images provide their own Python, Git, shell and language toolchains.

Reuse a verified submission filesystem
-------------------------------------
verified_checkpoints.json lists all 40 selected checkpoint image IDs, final HEADs,
source trajectory/patch hashes, and state-validation receipts. F004, F027 and
S026 select their corrected v02 checkpoints; the other 37 select v01.

Run from the repository root. Example for a NEW experiment directory:

PYTHONPATH=src .venv/bin/python - <<'PY'
from pathlib import Path
from tramask_pilot.corpus import read
from tramask_pilot.runtime import Container
from tramask_pilot.submission_replay import state_directory

directory = state_directory('F023')
summary = read(directory / 'summary.json')
validation = read(directory / 'validation_v03/report.json')
checkpoint = summary['checkpoint']
assert validation['submission_state_status'] == 'matched'
assert validation['image_id'] == checkpoint['image_id']
output = Path('results/behavioral_masking/new_experiment/F023/runtime')
if output.exists():
    raise FileExistsError('Choose a new experiment output directory')
with Container(checkpoint['image_id'], output, checkpoint['head']) as subject:
    print('Verified initial filesystem:', subject.image_id)
    # Run the next experiment's subject commands inside this context.
PY

Reconstruct from the original trajectory
----------------------------------------
The common engine is submission_replay.replay_submission(case, output=NEW_PATH).
Its input files still come from the archived run's inputs/<case_id>/ directory.
It executes the complete trajectory to the final submission marker, using
/bin/sh, a 30-second action timeout, and process-group cleanup.

The current scripts/replay_tramask_submission.py CLI has a fixed v01 output.
Do not use that fixed output for a new experiment or delete old results to make
it rerun. Use a new output directory through the Python API or add a separately
versioned entrypoint for the new experiment.

The common engine alone DOES NOT include these reviewed corrections:
* F004: run_f004.py applies a build-only CPU-visibility shim at s37, preserving
  the recorded command and historical source version, and verifies dist files.
* F027: run_process_cases.py binds the recorded kill PID to the corresponding
  newly launched webhook process, recording the effective command separately.
* S026: run_process_cases.py records background-test completion and checks the
  terminal process group. The accepted v02 run naturally completed at s41;
  its later completion barrier did not wait or terminate anything.
These original runners intentionally have fixed case/output paths. Preserve
them as executed evidence; adapt a NEW copy and output path for later reruns.

Preserved data and limits
-------------------------
The input trajectories, model patches, cohort manifests, original results,
corrected results, and review receipts remain in the original result directory.
manifest.json and verified_checkpoints.json reference them by path and hash.
The local Docker checkpoint images have been retained; this small code archive
does not contain Docker image bytes or duplicate the trajectory dataset.
Checkpoint images restore filesystem state, not live process memory.

Verification commands (read-only with respect to subject sources)
---------------------------------------------------------------
PYTHONPATH=src .venv/bin/python -m pytest tests/tramask_pilot/test_submission_state.py tests/tramask_pilot/test_runtime.py -q

.venv/bin/python scripts/verify_tramask_submission_state.py --output NEW_JSON_PATH verifies the
selected historical receipts. It does not rerun subjects or call a model.
The final historical verification is submission_state_audit/verification_v01.json.

This snapshot is for replay reuse. It does not mean that the old pilot's masking
and downstream conclusions have been rerun on these submission checkpoints.
