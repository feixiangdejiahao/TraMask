# 对修改后的测试重新计算观察依赖

2026-09-29。本次是分析输入正确性的独立静态原型，尚未接入主实验、调用模型或执行目标仓库。它修正一个基础问题：候选已经插入调用或换了接收对象，分析却仍在原测试的依赖图上寻找影响。

## 一个简单例子

原测试为 `value = 10; assert value == 10`。组合候选在断言之前插入 `value = f(g(value))`。原图没有 `f`、`g`，插入点也没有一个原来的输入表达式，因此可能找不到任何影响。新分析先把编辑应用到原测试，再解析实际将要运行的测试：现在能沿 `f(g(value)) → value → assert` 找到观察。断言右侧仍是常数 `10`，没有随新操作一起变化，于是把这个观察作为值得检查预期的候选。

相反，若把 `first.read()` 改为 `second.read()`，同时修改 `first.value`，新图应去掉“`first.value` 能影响此次 read”的旧连接。若断言为 `assert result == value`，输入修改同时到达 actual 和 expected，则不把它当作单侧未同步预期。这些事实都不证明断言正确或错误，只帮助模型定位真正发生改变的观察。

## 原型算法

接口为 `experimental.modified_observation_impact.select(corpus, frontend, candidates, budget=16)`，保留现有选择器的输出结构。每个候选执行以下步骤：

1. 清理运行探针，只应用真实的程序编辑。复用 `oracle_evidence._modified_sources` 校验编辑原文、处理导入和生成完整修改后源码。
2. 只为被编辑的源码文件建立局部索引，为对应测试建立新的变量、接收对象状态和调用依赖图。不会把原图的节点或 callee 绑定搬到新图中。
3. 通过精确 UTF-8 编辑偏移将原来的未改断言对齐到新源码。观察身份始终使用原断言 ID；同一文本在两个不同调用阶段出现，也仍是两个观察。编辑端口身份固定为原测试、原编辑路径和起止位置及角色，修改后字节偏移和不同长度的字面量不会创造新的端口。v2 同样对齐函数定义起点，以应对多行装饰器变短后函数行号改变；不根据相同名字猜测测试身份。
4. 用修改后的编辑位置找依赖种子。计算 actual 的后向切片，并减去 expected 的值依赖切片。剩余路径表示“输入编辑可能影响 actual，却没有沿同一编辑影响 expected”，作为原来的观察检查义务。记录完整路径及原、新坐标。
5. 完全沿用原 greedy 排序：先增加未覆盖的观察，再增加未覆盖的观察—编辑端口，每第四个位置按原 shape 排名探索。仍然每 case 只选最多 16 个候选。

删除导致没有修改后值、语法失败、断言对齐失败、跨文件 callee 未解析都显式记录为 unknown；这些候选仍保留，并可由原有探索次序选中。没有依赖路径不等于证明独立。控制依赖只表示可能受影响，不证明路径可行；共享输入的 expected 也不自动成为正确 oracle。

## 对照与成本

程序和通用 toy 冻结后，读取 `results/relation_search_20260929/candidate_inventory_v1` 的全部 17 个旧候选池。三个静态臂均使用相同候选池和每 case 16 个预算：

| 臂 | 依赖图 | 用途 |
| --- | --- | --- |
| `production_original` | 已有选择器的原图 | 当前实现参照 |
| `owner_original` | 单个源码文件的原图 | 与新原型相同的文件范围、观察与端口身份 |
| `owner_modified` | 同一文件的修改后图 | 仅替换依赖证据的实验臂 |

后两个臂才是重解析收益的严格比较。原生产版本还使用不同的旧端口身份，以及包含多个测试文件的索引范围，不能把它与新原型的所有差异都归于修改后图。

图成本约为每个候选一次修改后文件解析和对应测试的局部数据流计算，不逐候选建立仓库索引。原源码解析缓存共享；候选图使用最多八项的 LRU 缓存。跨文件函数效果摘要没有导入本原型，因此速度、覆盖和定位能力仍需后续实测，而不能把局部 may-dependence 当成完整程序语义。

尚未直接接入当前模型 prompt。原型证据中的观察 ID、`assertion_span` 和编辑端口使用原坐标，而 `path`、`modified_*` 使用修改后坐标。现有 renderer 的固定文案仍称其为 “Original-source unpaired impacts”；未来集成必须显式区分两种坐标，不能把新图路径直接塞进这个原图标题下。

## 验证范围

v1 的 13 个新增通用 toy 覆盖 Python、Go、TypeScript 的嵌套调用插入，callee 和接收对象替换，失效旧接收对象依赖的删除，同输入影响 expected，无关插入，重复断言的阶段身份，UTF-8 字节偏移，控制依赖，删除及语法未知，输入顺序与无关标签标注不变性，以及原/改图使用相同观察和端口。与 45 个相关既有测试合计 58 通过。v2 加入多行装饰器缩短且存在两个同名测试、定义起点被替换时明确 unknown 两个 toy，合计 60 通过。

静态全池 census 的代码、输入及输出 SHA 记录在 `results/relation_search_20260929_v3/modified_observation_impact_v1`。生成端不读取目标标签或模型缓存；封存后的目标曝光评价由独立评价端进行。依赖数或目标材料曝光的变化均不能直接当成正确组合测试、误报漏报或 issue resolution 的变化。

## v1 的盲静态结果与坐标修复

三臂均完整保留 4,502 个候选，其中 2,870 个符合当前断言审查接口，各选出 272 个候选，即每 case 16 个。

| 静态量，17 case 合计 | 生产原图 | 同范围原图 | 修改后图 v1 |
| --- | ---: | ---: | ---: |
| 至少有一个观察义务的候选 | 2,007 | 2,007 | 2,078 |
| 观察义务 | 6,306 | 6,306 | 6,506 |
| actual 与 expected 共依赖的观察，逐候选计 | 341 | 341 | 349 |
| census 计算秒数，含结果序列化 | 74.966 | 128.482 | 150.322 |

严格对照中，146 个候选获得此前没有的观察—端口义务，47 个失去部分原义务，两类可以重合；选入前 16 的候选合计替换 21 个。修改后图既可补依赖，也可撤销失效依赖，这不等于义务越多越好。

不读取评价目标的源码审计发现，六个候选将多行参数装饰器缩短。原型 v1 按含函数行号的旧 Unit.id 查找修改后函数，因此明确报 `modified_owner_identity_not_recovered`，没有沿用旧图冒充新绑定。为修复这个一般坐标问题，v2 使用未被编辑覆盖的原函数定义起点字节映射到新源码，且必须唯一匹配实际解析到的函数节点。起点被编辑替换或匹配不唯一则仍为 unknown。原断言和原端口身份不变，v1 结果保留，v2 全池独立重新封存；这一步在接收任何目标曝光评分之前完成。

独立评价端已经验证 v1 三臂候选完整性、资格和预算、owner 两臂完整 greedy 次序、26,367 个断言原 ID 与源码字节对齐、6,743 个原编辑端口、12,812 个义务以及 148,273 个路径节点源码跨度，未发现结构错误。这只验证证据与程序出处一致，不证明依赖模型的语义完备性。

## v2 封存结果

`results/relation_search_20260929_v3/modified_observation_impact_v2/seal.json` 已封存全部 17 个 case 和三臂完整排序。v2 恢复上述六个候选的函数身份，其他分析规则没有变化；最终仍有 4,502 个候选、2,870 个可审查候选和每臂 272 个选中候选。

| 静态量，17 case 合计 | 同范围原图 | 修改后图 v2 |
| --- | ---: | ---: |
| 至少有一个观察义务的候选 | 2,007 | 2,084 |
| 观察义务 | 6,306 | 6,530 |
| actual 与 expected 共依赖的观察，逐候选计 | 341 | 349 |
| census 计算秒数，含结果序列化 | 128.141 | 149.249 |

146 个候选新增义务、41 个候选丢失部分原义务，选入前 16 的候选合计替换 20/272 个。生产原图参照本轮约 75.408 秒；它与同范围原图的义务总数相同，但选中集合仍有一个候选差异，再次说明不能忽略端口身份和索引范围这两个控制变量。

当前结论是：重解析能够修复已插入操作没有原节点、调用绑定改变仍使用旧连接等具体分析问题，实际全池的排序变化有限。尚未测量它是否提高模型预期修订的正确率、完整组合测试生成率或最终 issue resolution。不能仅根据目标材料曝光成绩挑选是否保留这一分析正确性修复；后续如接入，应固定规则后进行相同模型、候选预算和执行条件的对照。
