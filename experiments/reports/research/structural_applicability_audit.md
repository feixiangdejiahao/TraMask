# 结构适配器的适用前提与泛化检查

本次审计只使用生成器、候选源码和 synthetic tests，没有读取参考补丁，也没有据参考结果调整关系。它补充 `structural_execution_audit.md` 的当前样本执行结论，不把三个 pilot 的成功推广成任意程序的零误报、零漏报。

## 四个需要区分的前提

| 关系 | 必须成立的前提 | 当前怎样检查 | 尚未解决的边界 |
|---|---|---|---|
| 工厂作用域提升 | 新构造的脚本是合法输入；host/guest 执行同一脚本 | 提升源码相同，guest 初始化成功，原始场景控制通过，缺失外部绑定明确拒绝 | 词法提取不等于完整 Tengo 名字解析；模块、外部回调尚未重建 |
| host/guest 结果相等 | 同参调用的值语义一致，初始状态可重放 | 独立初始化，同一参数及访问路径，类型和值或错误类别比较 | 默认整数参数、有限返回探索不能覆盖所有行为；函数身份不是完整行为观察 |
| clone/fresh 结果相等 | 初始脚本确定；clone 保留内部共享且与源隔离 | 对克隆和同源新实例施加相同序列，同时读取源实例前后状态 | 程序依赖 map 遍历顺序等不确定性时，新实例不能自动充当确定 oracle |
| recursive/unfold 结果相等 | builder 是确定的结构构造；有限展开确实未到边界 | 闭合 AST 构造表达式、仓库工厂纯度注解、底部访问标记、identity 控制、非恒等性检查 | 注解是契约证据，不是对任意库实现的形式化纯度证明；有状态 callback 和未知构造器不适用 |

工厂提升会把 global 变为 local capture，因此不能笼统宣称“提升前后程序语义永远不变”。当前缺陷断言实际比较的是**提升后的同一程序**通过 host 与 guest 执行；提升前测试只是适用控制。新程序改变了存储位置，但该程序本身应满足 issue 所承诺的 host/guest 一致性。没有把原测试的固定输出直接搬到新程序中。

Go 参数目前全部为 `Int(1)`，没有进行有损 JSON 参数转换。普通 map 结果转成结构化 map 后使用 `reflect.DeepEqual` 比较，返回容器枚举按键排序；这两处不受 Go map 的显示顺序影响。程序自己把 map 遍历结果拼成字符串则可能不确定，这与观察器排序不同。当前 pilot 种子没有这种模式；不能据此声称一般程序都满足确定性。

克隆 oracle 也没有要求两个独立实例共享地址。它比较相同调用序列的值，并验证源实例未被改变。相反，克隆内部原本共享的 capture 必须继续共享，所以生成第二个观察闭包是必要的。返回闭包在探索边界之外统一显示为 callable 会造成漏报，不是完整的对象等价证明。

## 本次发现并修复的两个具体缺陷

**文本替换错误。** 旧代码用正则替换表达式中的 `Recur`，会修改同名属性和字符串；还会把字符串中的 `fake(` 当作 import。最小例子为 `object({Recur: array(Recur), tag: literal('Recur fake(')})`。现已改为替换 Tree-sitter 的表达式 identifier 节点，同时保留属性键、字符串和 shorthand 的键。import 只从真实调用节点收集。Regression 在修复前失败、修复后通过。该修复没有改变现有三个 pilot 的生成文件。

**展开边界错误。** 旧代码把 `F^8(never)` 解析成功当作未访问 bottom 的证据。`fallback` 可消化 `never` 的错误，因此这个推断一般不成立。现在给底部 schema 的 `~run` 增加访问标记；即使 wrapper 最终恢复为成功，只要底部被访问，该义务就记录为展开界限不足，不能报缺陷。独立 Node synthetic runtime 检查了“fallback 恢复成功但 bottom 已访问”和“合法终止且 bottom 未访问”两种情况。

此外，生成器现在只接受闭合的 schema 构造表达式。赋值、自增、成员访问/调用、外部捕获和 callback 等未证明情形被明确拒绝；直接构造器的允许集合从仓库 `@__NO_SIDE_EFFECTS__` 工厂声明提取，不按 pilot API 手写。迁移 donor 仍使用独立的“对象展开后写入常量属性”规则。八个现有 schema 种子均仍适用。

## 少量 synthetic 证据应该支持什么声明

当前 `tests/test_structural_generation.py` 共 10 项测试，支持以下有限声明：

- 变量、测试、输入和属性换名后，提取依据仍是声明、调用和 AST 位置，而非目标名称。
- 嵌套声明、注释和字符串中的伪代码不会被当作顶层绑定；外部 callback 被识别为缺失前提。
- 使用不同模块路径、不同标量初值和不同属性名，不需要改生成模板中的预期输出。
- `array(array(Recur))` 等不同容器层级仍属于闭合构造表达式；这项检查验证构造适用性，不等于执行了所有深度。
- identity/nonidentity 义务有明确控制关联；有副作用和不适用 donor 不迁移；边界吞错不会成为缺陷报警。

这些测试验证了规则不是按目标名称、行号或预期值写死，不能证明对未见仓库或未见缺陷类别的泛化效果。后者需要预先固定适配器后，在独立案例上评价。当前最小而有价值的运行检查仍是：对冻结生成物重复执行，比较义务集合、控制结果与报警集合；不需要为了数量增加大量与实现同形的单元测试。
