# 组合生成、oracle 与缺陷检出实验

2026-09-23。统一版本 `contract_v6` 在七个已知 pilot 上生成并执行了 263 个组合检查，检出了 **7/7 个目标缺陷**。49 条候选报警均有参考通过的受控差分证据；独立语义审计没有发现错误 oracle。另有 **3 条参考实现报警**，审计认为它们与 issue 支持的语义冲突，保留原始结果，不删除测试使计数归零。

这里的“没有发现误报”是对本轮实际报警的人工审计结论。七例来自四个 issue 家族，参与了方法开发；不是未见案例评价，也不是对所有可能组合的正确性证明。尚未运行修复 agent，不能报告 issue resolution rate 提升。三个完整实验的计数及实现哈希见 [精简结果](../../../research/experiments/combination_generation_final.json)。

## 方法与实现

核心是**保持观察的上下文提升**：选择已有观察 a，程序构造新上下文 C 及基准 B，在适用条件 g 成立时检查 `O(C[t]) ≡a O(B[t])`。程序依赖用于定位值得组合的观察和操作，不直接证明语义保持。

1. 观察前沿从已有测试和 trajectory 提取输入、调用、状态操作与断言，取前十个入口。
2. AST 改写保持绑定，构造路径表示、作用域/捕获、clone、递归动作或协议坐标组合。
3. oracle 来自原断言，或同一输入的独立构造路径，例如递归与有限展开、clone 与 fresh、host 与 guest。
4. 协议分支每个 case 用一次模型调用提出纯布尔保持条件；程序做受限解释、已有事实反证和支持输入域检查，最多采样 128 个提案。模型输出不修改原 expected，但保持条件仍承担部分输出语义推断，并非已证明的契约。
5. 测试冻结后执行。候选报警只依赖候选执行及自身控制；参考实现随后用于评价，不参与生成。

完整算法及论文依据见 [method_design.md](method_design.md)。核心代码是 [contracts.py](../../../combination_testing/contracts.py)、[paths.py](../../../combination_testing/paths.py)、[structural.py](../../../combination_testing/structural.py)；[runner.py](../../../combination_testing/runner.py) 和 [evaluate.py](../../../combination_testing/evaluate.py) 分别负责隔离执行与评价。

## 统一实验结果

| Case | 目标交互 | 组合检查 | 控制 | 候选报警 | 参考报警 | 目标检出 |
|---|---|---:|---:|---:|---:|---|
| P1 | 功能键编码 × repeat/release | 98 | 40 | 21 | 2 | 是 |
| P2 | 非 shift 快捷键 × associated text | 90 | 45 | 1 | 1 | 是 |
| P3 | alternate alias × 已由按键表示的 shift | 21 | 31 | 3 | 0 | 是 |
| P4 | 既存路径 × 空格/引用表示 | 4 | 2 | 4 | 0 | 是 |
| P5 | 复合容器中的局部捕获 × host 调用 | 20 | 20 | 11 | 0 | 是 |
| P6 | clone × 内部共享捕获状态 | 22 | 22 | 1 | 0 | 是 |
| P7 | 递归结构 × 非恒等转换 | 8 | 8 | 8 | 0 | 是 |
| 合计 | 四个 issue 家族 | **263** | **168** | **49** | **3** | **7/7** |

“组合检查”按实际观察到的唯一检查 ID 计数：221 个静态声明，另有 Go 在运行时展开的 42 个。多个报警可能是同一缺陷的多个输入，**49 条报警不等于 49 个不同缺陷**。40 条证据匹配七个已知目标，其余九条是额外行为证据。

全部声明检查均有结果，没有编译、导入、超时、跳过或缺失结果。28 个静态不支持位置另列，不能记为通过。候选的控制全部通过；参考有九个原始 seed 控制失败。参考的 22 条原始生成失败中，19 条因自身来源控制失败而不能形成组合报警，剩余三条保留为参考报警。共有 22 个组合的双侧比较受控制失败阻断，其中包含三条参考通过的组合；因此不能把这两个“22”混为一类。

三条参考报警分别涉及“去掉 text 后 shifted alternate 仍决定字符”“改变 printable 主键但保留 shifted/text 字符”“大写 primary 的 base_key 应保持小写”。它们在候选上均通过。参考补丁不是需求真理，`reference alerts = 3` 不能直接解释为三个候选误报。逐条输入、失败位置、原断言、issue 依据与完整 ID 见 [oracle 审计](contract_v6_oracle_audit.md)及 [JSON](../../../research/experiments/contract_v6_oracle_audit.json)。

## 指标如何解释

- **Test / Assertion Hit@10**：目标入口是否排进前十。本轮检索都是 7/7，但它们不能替代运行后的缺陷检出率。
- **已知目标检出率**：有至少一条有效证据匹配已知目标机制的 case 数 / 7。发现别的问题不能抵消该目标的漏报。
- **候选报警**：组合在候选上失败，且该组合依赖的原始/恒等控制通过。它不读取参考结果。
- **受控差分证据**：候选报警对应的同一组合及控制在参考上通过。仍须判断输入和 oracle 是否有语义依据。
- **参考报警**：相同报警规则作用于参考实现。单独报告，不能直接当作真实 FPR。
- **审计发现的错误 oracle 数**：逐条检查报警是否破坏输入前提或与需求矛盾。本轮为零；它是开发集上的人工裁决，不是自动正确性保证。

当前没有对全部正确组合和所有潜在缺陷的完整标注，因此不计算总体 FPR、总体 recall 或“组合覆盖率 100%”。

## 重放与模型稳定性

固定三份模型输出后，重新生成七例，manifest、测试源码和实现快照均逐字节一致；再执行 14 个全新容器，所有义务、控制、状态、报警和目标匹配完全一致。此次重放没有新模型调用。详见 [复现报告](contract_v6_reproduction.md)。

模型重抽样使用完全相同的请求重新获取三份保持条件，再统一执行：仍检出 7/7 个目标，49 条候选报警与三条参考报警的集合均相同。P1/P2 的准入集合相同，P3 从 21 条变为 22 条，新增项双侧通过；三份模型源码均有变化。未挑选各 case 的最佳输出。新增项的关系依据尚未独立确认，不能以双方通过证明有效。结果见 [独立重抽样报告](contract_v6_model_repeat.md)及 [oracle 审计](contract_v6_model_repeat_oracle_audit.md)。

最终本地回归 **169 passed**；`git diff --check` 通过。测试覆盖解释器、输入域、绑定改写、递归展开适用性和执行分类等行为。它们不证明生成关系的普遍语义正确性。未修改的主实验及重抽样模型缓存纳入 [Git 冻结目录](../../../research/frozen_contracts/README.md)，可离线重新生成。

主实验成功推断使用 provider 返回标识 `gpt-6-astra`，三次成功请求共 25,992 tokens；独立重抽样另用三次、27,200 tokens。最初三次 TLS 失败作为请求记录保留，没有响应或用量；重试请求字节相同。没有独立验证 provider 背后的实际模型身份。P1 输出最初因纯局部赋值表达式不受解释器支持而拒绝；加入通用支持后，对原始字节重新验证，未手改模型输出。全部开发阶段共保存 36 个请求记录、32 个响应，已报告用量合计 616,176 tokens，四个请求用量未知，货币费用未报告；不能只报最终三次请求而隐去开发成本。详见 [模型调用账本](model_call_ledger.md)。

## 失败结果与开发偏差

早期最小函数依赖从有限测试推断“不依赖”，P3 虽找到其他差异，却遗漏 alias 目标。额外经验 guard 又屏蔽了 P2。有限 ID 筛选也不能保证正确：screening v1 有三条候选失败/参考通过，但 oracle 与 issue 明确冲突；后续模型曾出现校准失败和输出格式失败。它们均保留在 [历史记录](context_lifting_execution_notes.md)。

| 后续协议分支 | 协议目标检出 | 主要观察 |
|---|---:|---|
| screening v4 | 2/3 | P2 漏报；四条参考报警中两条不在支持的 producer 输入域 |
| contract v4 | 2/3 | P1 被过窄编码条件排除；81 条参考报警中 78 条属于不支持的 producer 输入域 |
| contract v5 | 2/3 | P2 被非空 text guard 排除；两条参考报警有需求依据 |
| contract v6 | 3/3 | 25 条协议候选报警未发现错误 oracle；三条参考报警有需求依据 |

v6 默认模型证据去掉候选实现正文，保留 issue、既有测试、API docstrings 和公开协议事实；同时调整提示，使需求适用于其声明的完整条件域。两项同时变化，**不是干净的单因素消融**，不能把提升归因于其中一项。协议输入域有公开规范及 producer 依据；库适配器依靠人工关系假设及有限语法识别，没有按 case ID、目标测试名或行号分支。它们仍在已知案例上开发，不能由此宣称无过拟合。[范围审计](contract_scope_audit.md)记录了实际读取、哈希检查和仍存在的假设。

## 仍可能怎样误报或漏报

模型保持条件过宽会迁移错误断言，过窄会排除目标组合。已有测试一致性只能发现有限反例。来源控制通过也不能证明新上下文语义相同。

静态切片、前十预算、一次一坐标变化、128 个提案预算及有限适配器都会漏掉组合。协议生成器尚未覆盖全部 functional-key + text 形状；Go 的参数和返回深度受限；递归展开有界；结构比较两条路径若同时出错也可能通过。

下一步验证应冻结当前算法、提示和适配器，在未见 issue 上比较目标检出、无效关系、参考冲突、人工裁决和成本，再把生成测试接入修复循环测 issue resolution rate。当前 7/7 是可以复现的 pilot 结果，尚不能替代这一步。
