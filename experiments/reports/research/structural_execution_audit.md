## 是否覆盖已知问题类别

**P5：覆盖 Go 调用返回复合闭包对象时的局部栈问题。** 生成器把检索测试中的原始脚本置于工厂作用域，并返回包含脚本声明和观察闭包的 map。相同工厂通过 guest 执行成功，通过 Go `.Call()` 执行时产生 `ObjectPtr` 被当成 `String` 的 panic。`scope_e85c353c86c2/call/make(1)(1)` 的 guest 结果是整数，host 在工厂返回复合对象时失败；对应未提升作用域的控制通过。候选 `vm.go` 的 Go 根调用将 `sp` 设置为参数个数，而普通调用为 `NumLocals` 预留空间，与该触发方式一致。这里不依赖 panic 文本判断报警，判据是两条执行路径的结果不一致。

其中两个 P5 见证的 guest 预期是运行时错误，而非正常返回值：输入函数参数类型不适用，但 guest 和 host 按 issue 约定仍应保持同类运行时错误。候选返回错误类型或 panic，参考正确保留错误。即使只看具有正常 guest 返回值的其他见证，P5 也仍被检出。

**P6：覆盖 clone 破坏克隆内部共享捕获单元。** `scope_b0032d8a8eeb/clone/inc` 中，`inc()` 在克隆内先后返回 1、2，独立生成的 `__observe_counter()` 却始终返回 0。同源新实例的相同调用序列中，观察闭包返回 1、2；源实例在克隆执行前后均为 0。该见证区分了“源与克隆隔离”与“克隆内部保持共享”两个条件，确实检查后者。候选 `call.go` 每个 closure free slot 新建 `ObjectPtr`，与观察结果一致。未提升作用域的 clone 控制通过。

**P7：覆盖递归组合丢失非恒等变换。** 身份控制在递归版本和有限展开版本上相等；从已有测试提取的纯对象扩展操作，在有限展开结果的各层加入字段，而递归版本没有这些字段。`schema_7af9a228b100/extend_2a7c352adf4a` 对应原有 pipe 场景；另外七个见证覆盖 sync/async、不同树形和 record 输入。候选 `_resolveRecur.ts` 从 pipe 首项复制属性，包含运行函数；这会覆盖原 pipe 的运行逻辑，与“字段扩展未执行”一致。

## 断言为何不依赖参考答案

Go host/guest 比较执行的是同一份提升后的源码、同一参数和调用路径，每次从独立初始化状态开始。clone/fresh 比较执行相同脚本所得的两个状态，对克隆和新实例施加相同调用序列，同时检查源实例的观察值保持不变。预期的具体整数不是生成器写入的常量。

TypeScript 比较递归定义 `μF` 和 `F^8(never)` 对同一输入的运行结果。有限展开解析成功时，当前这些容器构造中的底部 `never` 没有被访问；因此，对于该有限输入，两种执行方式应得到相同结果。扩展义务还检查其有限展开输出不同于未扩展的有限展开输出，避免恒等操作造成空洞通过。参考实现只用于外部评价这些已冻结义务。

## 仍然存在的失效方式

1. **共同错误会漏报。** 两条路径仍复用同一解释器或验证库；guest 与 host、递归与展开路径共同出错时可能相等。此次结果只能证明当前已知问题被区分，不能证明 oracle 完备。
2. **有界观察会漏报。** Go 参数固定为整数 1、固定元数不超过 3，返回结果最多继续探索两层、每个容器至多四项。clone trace 本身不继续调用返回闭包。深层或其他参数才触发的错误可能遗漏；达到边界时的 callable 标记不是对其后续行为的证明。
3. **支持范围之外的种子被明确排除。** P5 有 3 个、P6 有 7 个静态候选点不支持，包括无顶层函数声明、缺失外部 callback 等。当前没有执行阶段无效义务，不代表所有检索种子都成功转为测试。
4. **一般程序的副作用需要更强前置检查。** 当前实际使用的 Go 种子没有外部回调/模块依赖；TS donor 只有对象展开和常量属性写入。但通用的 schema builder 或脚本仍可能读时钟、产生随机值或依赖构造次数。TS 多次构造有限展开与一次构造递归的等价性，对有状态 builder 并不自动成立。
5. **报告枚举仍有局限。** Go 的部分义务由 guest 返回形状动态展开；当前两种实现输出的 ID 集相同，但将来形状变化可能导致义务缺失。当前 Go 元数据没有预声明所有动态义务，所以 `declared_unexecuted=0` 不能用来证明生成空间被完全执行。
6. **序列化观察有边界。** 当前见证只用到了稳定的整数、错误类别及普通 map/array 结果。以后若出现 cyclic container、immutable container 或隐藏对象身份，`ccValue` 的字符串/结构观察并非通用行为等价。

最小的一般性后续检查是：对同一冻结生成物在全新容器中重复运行，检查义务 ID 集、控制结果和报警集合稳定；对动态枚举记录种子和截断计数；在接受 stateful builder 或不透明对象类型之前，先加入构造确定性和观察可达性检查。这些检查不需要按某个 pilot 改变关系判据。

## 特例与版本检查

`structural.py` 没有 pilot ID、目标测试名称、手工标注路径、参考补丁路径或目标输出常量。API 名称如 `recursive`、`Recur`、`transform` 属于语言/库适配器；输入属性和值来自被提取的种子或 donor。unit test 中的变量名只用于验证通用语法分析。参考补丁定位仅出现在 evaluator 的 `runner.py` 中。审计时新实现仍有未跟踪文件，最终结果需要由 root 提交 Git 后记录版本。
