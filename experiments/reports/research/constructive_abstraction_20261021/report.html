P2-B：竞争解释与反证

案例假设检验
T13源与副本没有隔离不解释本轮最小失败：源仍为 0，目标写入为 1；错误发生在副本内部。
T13目标 globals 绑定错误见证中的读写只依赖本地捕获单元；无需目标全局值差异即可失败。
T13捕获单元的别名在复制时被拆开支持：8 个共享且经过转移/克隆的变体失败；独立单元和不转移的控制通过；仅增加捕获指针 memo 的局部干预后全部通过。
T17默认表达式总是提前执行不支持：普通存在值的计数为 0；错误只出现在 present-undefined。
T17缺失与合法值在查找结果中混淆支持：数组和映射的 present-undefined 都触发 fallback，缺失与普通值控制正确。
T29新建查询掩盖了旧查询失效尚未得到故障证据；60 个保留/新建对照一致。只保留作为可检验假设。
cross-case所有案例都是从不考虑组合/状态拒绝：T13 嵌套转移和递归闭包检查、T29 对事件查询身份的修正、T17 显式考虑 undefined 都构成反证。
候选 A：保留状态身份的整体复制：不同访问器共享同一可变单元
Mechanism
按外层闭包分别复制内部状态，破坏跨闭包的捕获别名；仅测试同一函数对象的重复引用会经过不同的 memo 命中路径，不能暴露该错误。
Property
在承诺保留捕获语义且隔离源状态的整体复制中，源内同一个可变单元经两个访问器可达，目标内这两个访问器仍应汇聚到同一个新单元；该新单元与源单元隔离。
Derivation
T13 要求 Go 调用保持 in-script closure captures 行为，并要求 transferred captures 是转移时快照且源/目标隔离。将两条契约用于同一整体转移的闭包对，得到内部共享、外部隔离。共享保持部分是对组合契约的语义推导，不是 issue 原文逐字声明。T25 的已有 object-identity 测试提供明确的参考保持契约。
Construction
固定两个不同访问器，生成共享单元/独立单元两种图；整体 transfer 或 clone；目标通过一个访问器把 0 写成 1，经另一个读取，同时读取源。共享图期望目标读 1、源读 0；独立图期望交叉读 0。自动扩展 flat/nested 和初始状态 0/2，并用不转移的原图作控制。T25 将访问器适配成两个不同外层对象，内部指向同一 Error，修改 message 后交叉读。
Simplification
不需要分析任意闭包程序、不需要恢复完整堆图、不需要直接检查私有捕获指针。由构造时已知的最小共享图得到局部 oracle，以一次写和两次读行为化地观察别名。仍需人工核验复制契约并提供构造/转移/读写 API 适配器。
Scope
具有共享状态保持与源隔离契约的整体对象图变换，并且共享单元有可执行的写/读观察。T13 已确认；T25 独立系统复用通过。不能推广到按字段值复制、刻意解除共享、保留共享资源的浅复制、不可观察的内部状态，或把两次独立 transfer 当成一次整体复制。固定小图不保证发现仅在更大图/特定深度出现的错误。
Counterexample
最小失败见证是两个不同闭包共享一个整数捕获：目标 inc()=1、get()=0、源 get()=0。范围外反例：Python deepcopy 对函数返回原对象；实测目标写后源也为 1，这是 Python 允许的行为。只要删去契约门槛，通用复制隔离 oracle 就会误报。
Prior Art
CPython test_deepcopy_memo 已直接检查副本内两个引用相同且与源不同；memo 保持对象图身份是已有技术。Korat 已从指定谓词构造有界堆输入；Metamorphic Testing 已从行为关系产生跟随测试。当前增加的是该性质在闭包捕获层的实例化和原轨迹故障证据，未证明新的构造原理或自动适用性判定。 CPython test_deepcopy_memo · Python copy documentation · Metamorphic Testing: A New Approach for Generating Next Test Cases · Korat: Automated Testing Based on Java Predicates (ISSTA 2002)

候选 B：当前状态查询的重新计算一致性
Mechanism
候选机制：每次新建查询避开已维护状态，可能无法暴露旧实例的失效/更新错误。本轮没有确认 T29 实现存在该错误。
Property
纯、确定、仅依赖当前数据的查询在更新完成后，其成员集合不应依赖查询缓存是否经历过先前调用。
Derivation
来自 T29 的依赖 trait 值过滤、set/add 后重新评估契约，加上生成器选用的纯谓词 h.value > 0。仅对普通查询/Not 查询成立；显式依赖历史的 Added/Removed/Changed 不在域内。
Construction
创建并查询稳定实例以预热，执行一到两步 set/remove/add 历史，再把其成员集合与同一 world 上新建的同谓词实例比较。枚举 5 种操作的长度 1/2 序列及正向/Not 两种查询，共 60 个测试。比较时复制结果数组并规范化集合顺序。
Simplification
无需手算每段更新历史后的完整成员集合；新建实例给出一个可执行的局部一致性 oracle。仍需证明新建实例确实走不同的缓存生命周期、谓词无外部状态、数据/时机对齐。两条路径可能共享错误，相等不是正确性证明，不相等也不能单独指定哪条路径正确。
Scope
同步更新完成后的当前状态派生视图/缓存。T29 原任务可以接入此检查，但 60 个测试全通过；不能把它写成已验证的 failure class。异步最终一致性、订阅、快照、事件流、随机或有副作用谓词不适用。
Counterexample
在一个实体上查询 Added(p) 后再次查询同一实例应为空，新建 Added(p') 应返回该实体。原 Koota 补丁实测 retained=[]、fresh=[1]，这是正确历史语义，反驳无条件的新旧实例等价。
Prior Art
Nominal Adapton 已研究 from-scratch consistency；Adapton Lab 已提供生成/编辑输入后对比 cached 和 naive 计算的通用测试框架。2026-10-15 的 Rondo 预印本进一步比较保留/重置编译器状态并对齐程序状态。因此本候选尚无实质新意，也没有新的真实失败证据。 Incremental Computation with Names (OOPSLA 2015) · Adapton Lab test harness · Stateful Testing for Deep Learning Compilers

候选 C：只在缺失时默认：保持存在位与值的区分
Mechanism
实现把 absent 与 present(undefined) 投影为同一个值，再以该值选择默认分支；测试只覆盖 absent 和 present(ordinary)。轨迹显示 Agent 曾考虑区分，但选择了另一个语言的契约。
Property
当契约明确是 absence-only defaulting 时，存在位独立于值；present(undefined) 保持 undefined，且不得执行 fallback。
Derivation
直接来自 T17 issue 的 only when a position or key does not exist，以及 defaults evaluate lazily。它不是从所有 default API 推导的普遍法则。
Construction
构造 absent、present(undefined)、present(0) 三个输入类，分别装入数组/映射；fallback 递增 hits 并返回 7。oracle 同时检查绑定值和 hits：缺失为 (7,1)，显式 undefined 为 (undefined,0)，普通 0 为 (0,0)。
Simplification
只需一个存在位和一个可观察的 fallback 副作用，无需枚举任意嵌套模式、求整个绑定语义或写参考解释器。减少的是这一局部默认分支的 oracle/输入构造难度；没有自动解决应当选择哪一种 default 契约。
Scope
明确区分缺失与合法 sentinel 值的 default/lookup API。T17 数组和映射均复现。Python dict.get 的 presence/value 子性质可复用，但其默认参数求值不是惰性的，不能复用 hits 子性质。
Counterexample
JavaScript 的 const [x = fallback()] = [undefined] 合法执行 fallback；本机 Node 实测 (7,1)，与 ECMAScript 规范一致。因此不能仅凭相似语法将 absence-only 契约用于其他语言。
Prior Art
这是显式契约驱动的输入分区与副作用断言。QuickCheck 早已支持给定性质和自定义生成器的自动检查；当前没有超出这种基于性质测试的实质差异。存在性与值的区别也由标准映射接口体现。 QuickCheck: A Lightweight Tool for Random Testing of Haskell Programs (ICFP 2000) · ECMAScript 2024 IteratorBindingInitialization
