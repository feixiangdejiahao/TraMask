# 对“区分上下文搜索”的独立评议

这是对方法候选的评议，没有运行实验。相比关系标签，这个方向的优势是：上下文本身是可执行程序语法，可以定义一步扩展和预算。下面仍有两个核心缺口，不能靠名称消除。

## 1. 先明确搜索对象，不然仍是两个黑盒

`K[p0] != K[p1]` 只是目标；算法必须公开输入构造 grammar、可用 continuation grammar，以及两次运行中哪些对象被认为对应。特别是动态语言、embedded script、Go 的 `Object` 接口：同类型不等于同语义角色，类型信息也不会自动发明返回复合对象的 factory。

`p0,p1` 为 trajectory 真实版本能增加可执行性，却不保证它们的差异包含遗漏缺陷。历史版本同样可能在目标语义上都错。局部AST替代可控但覆盖范围小；LLM补结构仍是一个依赖模型的候选假设来源，不能悄悄称为程序分析保证。

**建议固定表述：** rival是搜索工具，`K[p0] != K[p1]`证明测试能判别二者，不证明任何一方正确。oracle必须另由issue、已有有效断言、可信表达式语义提供。正确性证据不足时输出需要判定的区分测试，不能归入已确认bug。

## 2. paired typed values 需要包含别名差异

只追踪 `value0 != value1` 会漏掉最重要的P6：两个克隆结果所有标量值都相同，但两个closure的capture是否指向同一cell不同。对象地址不同也不能直接当行为差异——两次独立执行的分配地址本来就不同。

状态可保持很小：

- 对齐的公共根/测试局部变量，以及从根出发的访问路径；
- 标量值或正常/异常出口差异；
- 访问路径对之间的别名关系差异。

对象对齐以共同输入、同一调用产生的结果、同一访问路径为锚，不比较裸地址。内部字段/捕获单元可作为插桩搜索信号，最终断言仍落到公开可观察行为。

## 3. 一条真实、非case-specific的扩展规则

**别名差异的写读扩展。** 当前同一测试前缀在两个rival中得到对齐访问路径 `x,y`，满足：

```text
alias0(x,y) XOR alias1(x,y)
```

从仓库已有可调用方法/测试片段中取 `w` 与 `r`，使其效果摘要满足：

```text
w(x,a) 可写 x 所达的某字段/单元 ℓ
r(y)   可读 y 所达的对应字段/单元 ℓ
```

对两个rival执行完全相同的扩展：

```text
w(x,a)
z = r(y)
```

保留使 `z0 != z1` 或正常/异常出口不同的最小参数 `a`，再为 `z` 找公开断言。参数来自已有常量、类型构造器或可支持表达式的约束求解；**参数选择以reader输出是否可区分为目标**，所以输入与观察不再是独立两阶段。

这条规则不写入 Clone、closure、writer/reader 的专用名字。它也适用于容器copy、对象快照、共享缓存与不同view。P6是它的一个实例，而不是该规则的全部定义。

程序分析具体工作：对直接AST字段/下标/闭包自由变量计算有界read/write access paths；沿已解析直接调用做摘要组合；别名由两次执行插桩恢复。动态调用未解析时标unknown，允许候选或提高代价，不能作为“无读写”硬剪枝。能够读取closed-over state的callable，本质上其capture cell属于effect footprint。

**有条件的剪枝。** 若一个候选操作的sound read summary与当前差异单元不相交，且write summary不可能经任何活着的alias-difference路径激活差异，也不会构造后续需要的新receiver，则它不值得作为下一步观察扩展。工程上若summary不sound，只能降优先级；将其宣称安全剪枝会产生系统性漏检。

别名已相同、值不同的情况是更简单特例：沿read footprint命中差异单元的operation扩展；结果成为新的差异根。异常出口可将catch/finally之后的有效局部变量加入后继观察，definite-assignment排除未定义值。

## 4. 它为什么还不等于统一方法

这条规则正面解决“差异存在但尚不可公开观察”，但不解决所有“怎样让差异首先出现”。如果P5的初始输入只返回closure，两个rival在该前缀上根本没有复合返回差异；需要新的输入程序构造grammar。P7同样需要将非恒等transform放进被执行的递归层。类型+def/use本身无法产生这些嵌入语言结构。

若方法写成“先生成能触发差异的输入，再延伸observer”，它并非真正联合搜索，而是常见的differential execution加后缀。要名实相符，至少要允许observer的未满足前提向前反馈：例如既有 `r(y)` 需要一个可读路径，前缀必须建立该路径并通过写操作使其在两解释间可区分。上面的写读规则给出了一个具体联合子问题；嵌套返回、协议编码等仍需各自可公开实现的前端，不能承诺自动覆盖全部17例。

## 5. 值得做的最小可验证主张

可以首先主张：**在有界可调用操作和已有rival下，程序效果与别名差异能引导生成短的公共观察上下文，比随机延伸或只变异输入更有效地暴露rival差异。**

对照应包括：固定输入只加观察、固定观察只改输入、无effect/alias引导的同预算上下文搜索；报告区分rival的效率与真正缺陷检出分别多少。另加“rival获取成功率”作为独立前置指标。若这个主张尚未实验成立，不要把它升级为自动解决combination gaps。
