# 轨迹副本会重复消耗多少组合搜索预算

这项分析支持把结构分桶保留为下一版的调度消融，不支持立即接入当前主线。17 个已见开发案例的静态模拟只释放了 31/1853 个首轮执行槽位（1.67%），收益主要集中在 N08 和 N05。没有运行新的 repository tests，没有读取 target、verdict 或隐藏测试，也没有调用模型，因此不能把结构多样性增加解释为漏报下降。

最终结果是 `results/relation_search_20260929/trajectory_buckets_analysis_v3/analysis.json`，附带输入 SHA 和分析代码快照。v1/v2 是过程中保留的早期输出，以 v3 为准。`history_breakdown.json` 区分历史副本与普通结构重复，`N08_import_evidence.json` 保存实际导入位置证据。

## 一个简单的调度方法

把同一 operator 下的候选按“源测试 AST、变换后 AST、来源环境”分桶。每次先从不同桶取一个候选，再回到同一桶取第二个副本。operator 之间仍公平轮转。输出是原候选的一个排列，不删除任何副本，也不声称同桶意味着行为等价。

AST 保留文字值、运算符和全部断言，只统一测试注册函数名和能明确识别的局部绑定。影子绑定、Python fixture 参数以及 global/nonlocal 名称保留。历史 Go 名称只依据 `relocated_globals` 和原内容 SHA 撤销工具添加的后缀，不用正则把任意 `_rh_` 名称都当成同一对象。

环境包括原始来源位置、非测试代码、helper/global 定义、导入绑定及 enclosing class/suite。具有 Test 前缀的 helper 不能仅凭名字移除；被当作 callback 引用的声明也要保留。不同代码快照可以来自同一原始文件，却提供不同 helper，这些差异必须分开。

对导入，Go 根据记录的 `go_modules` 匹配实际源包目录；Python/TS 匹配 corpus 内的实际源文件位置和内容 SHA，保留歧义集合。外部或无法解析的模块明确标为 `external_or_unresolved`，只有 module/symbol 声明证据，不伪称已经解析到具体函数。N08 的 `base` 与 `vfs` 在三个快照中分别指向同样的 22 个 corpus 源文件及 SHA；这是源位置证据，不是比较 `_rh_` 文件名。`testing` 与 `require` 不在该 corpus 的生产源码集合，原型明确保留未知状态。

## N08 说明为什么不能只比较测试体

首轮 17 个 `bounded_owner_prefix_rebind` 候选只看规范化后的测试体和输入变换，会压成 3 个桶。加入来源环境后是 9 个桶，8 个重复槽可以先让给其他桶。

其中确实存在 helper 差异：一组 `openDurabilityTestDB` 在 cleanup 中无条件调用 `d.Close()`，另一组先判断 `d.closed.Load() == nil`。两种初始化/清理环境不能因为测试函数文本相同就当成同一场景。另有导入集合差异；当前保守地保留整个导入集合，即使部分 import 可能不影响这个测试。

同一候选池、同样 17 个 operator 槽位重排后，该 operator 的桶数由 9 增至 17。`owner_prefix_rebind` 也增加 8 个桶，因此 N08 的 128 个槽位整体由 110 个桶增至 126 个桶。所有旧副本仍位于后续队列。

## 仍可能错误分桶的场景

1. 测试读取自己的名称、文件名、调用栈或 snapshot 名称。名称规范化不保留这些运行时区别。
2. 同源历史 global 被 namespace 成不同实例；跨文件代码可能观察对象身份或共享状态。相同声明内容不证明是同一个运行时对象。
3. 外部模块动态解析、反射、fixture 自动注入、模块初始化或间接 callback 依赖超出静态环境范围。
4. 当前有限的局部绑定分析和 import 解析遇到语言特性时可能保守拆桶，也可能漏掉动态区别。

所以，即使不删除候选，在有限预算下把某个副本推迟仍可能推迟真正有用的场景。后续若接入，必须保留完整队列和该限制，并在未参与设计的轨迹上比较实际缺陷检出；不能把 AST 桶覆盖作为最终质量指标。

原型位于 `experimental/trajectory_ast_buckets.py`，分析入口为 `scripts/analyze_trajectory_ast_buckets.py`，不接入冻结 pipeline。8 个测试覆盖实际来源解析、helper/global/import/literal 差异、callback helper、fixture/global 绑定、class 上下文、可验证的历史重命名和调度排列性质。当前建议是封存分析，先完成主方法的端到端实验。
