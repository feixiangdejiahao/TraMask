# 本轮程序分析与小模型辅助实验

时限：2026-09-24 03:25:54—08:25:54 UTC（北京时间 11:25:54—16:25:54）。目标为两个预定轮次分别检出七个指定缺陷，且无错误/未知报警、模型协议失败或相关执行错误。七例是已经分析过的开发集。

## 时限结束时的结论

五小时时限已到，停止新增实验。七批均未获得已确认目标检出，未达到“七例无漏报无误报”的主目标。按用户的时间上限要求保留实现、全部结果和失败证据。尚无依据声称提高了 issue resolution rate，也不能把本地回归通过当作缺陷检测有效性。

第七批是相同候选及语义消息下的推理配置对照：14 个生成单元中 11 个有效，冻结 70 项义务；66 项执行、4 项因生成的 Go 调用类型错误受阻。两轮确认目标检出均为 **0/7**，另有 **3 次模型补全协议失败**。第一轮两个报警经独立二次审阅，其期望适用性仍为 unknown；没有确认其为真实缺陷或已知目标。事前审核曾将这两项标为 valid，原封存不改写，审阅分歧另行保留。不能把原始汇总中的零错误/未知报警误读为没有未决报警。

核心方法仍为 `T=(S,q,e)`：程序提取动作、观察及源期望，沿依赖关系组合动作和已有观察；模型只补有限的期望值表达式。模型不能改写测试体。独立人工 oracle 审核属于评价，不是已自动实现的生成能力。

## 实验揭示的主要问题

1. **候选中的语义组合仍不足。** 第五批的保留候选池没有找到完整目标判别测试；第六批虽增加了部分联合 setup 与结构化期望，仍未建立完整目标测试。这个检查只针对预算裁剪后的池，不能区分语法不支持与更早裁剪，也不是不可表达性证明。
2. **程序相容与期望正确仍有距离。** 依赖关系说明操作可能影响观察，并不说明组合前提成立或期望保持。第五批104个接受表达式均为常量，其中99个等于源期望，没有候选实际适用源见证；该批不能证明学到了可复用的关系。
3. **物化与协议还有损失。** Go 部分候选存在真实类型错误，整运行单元被阻断；额外推理预算也不保证得到有效最终答案。各类阻断单列，不视作主动弃权或零误报。

增加期望表达式能力不能补出不存在的动作/观察组合；修复编译也不能证明输入已覆盖目标交互。当前实验证据尚不支持“该方法已能自动、可靠补齐遗漏组合”的主张。
