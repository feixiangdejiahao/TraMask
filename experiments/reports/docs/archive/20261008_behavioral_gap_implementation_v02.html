组合测试增强：改进实现与本地验证

日期：2026-10-08。实现版本：joint-observation-augmentation.v2。

本次已修改算法实现。程序先提取联合行为及原测试证据。模型再判断需求、确定补测目标，并根据反馈修改测试。本次完成代码测试和真实任务的提取检查。没有运行新的 DeepSeek 效果实验。

问题与输入

算法接收已应用原补丁的仓库、公开需求、补丁和公开执行历史。它检查提交前的验证是否遗漏必要组合。gold 补丁、benchmark 失败测试和人工目标不进入在线算法。

组合目标包含三部分：共同成立的条件、这些条件影响的操作、需要检查的结果。结果还包含观察阶段。例如，恢复状态后的直接读取，与后续消费者运行后的读取，是不同检查。

程序关系数量与条件维数不同。多次函数调用可以传递同一个条件。一个函数也可以包含三个独立条件。实现分别记录这两个数量，不再用调用条数代替搜索维数。

实现的主要改动

部分当前处理解决的问题
相关程序操作连接赋值、实参传递、分支、提前退出、可能的共享状态、指令分派及声明约束。每个关系保留源码位置和不确定性。局部函数的结果不能替代跨操作的联合行为。
联合条件从源码提取分支条件、字段存在性、默认值传播、共享关系和观察阶段。默认检查最多三个条件的局部组合。两个单项测试不能自动代表同一次调用中的联合检查。
原测试范围分别保存每次入口调用的参数、对象绑定、操作路径和断言。未知值保持未知。测试路径扩展达到上限后，仍保留相关测试清单。单个断言不再被解释为整个行为已充分验证。
执行历史按候选关联代码阅读、修改及前后的测试命令和反馈。单列修改之后的验证记录。模型可以检查原验证如何形成。命令出现不再被解释为最终补丁已经通过测试。
模型输入发送局部条件、关系、测试范围及源码片段。模型可以继续查询源码、测试、关系和历史步骤。省略内容有明确标记。减少大段文件和历史文本对关键差异的干扰。
模型迭代提供查阅、运行已有测试、生成补测和结束判断四类动作。每个候选最多调用三次模型、执行两次测试命令。全部候选共享 token 预算。模型可以根据新证据修改目标和测试。重复动作与无效答复不会获得额外预算。

算法保留单次模型调用入口。新增的 agent 入口支持受限迭代。执行命令由调用方提供。模型生成测试代码，不生成执行命令。每份测试及其反馈单独保存。

Python 执行反馈记录选定源码行、可读取的条件值、对象标识及调用标识。同一入口内部的两次相同调用仍分别记录。Go 和 TypeScript 目前只返回测试输出。

程序不会删除被提前退出阻断的候选。该阻断可能正是补丁错误。程序也不会仅凭入口参数，把未确认到达的后续操作记为已经检查。

验证设置

第一类检查使用小型自建项目。测试覆盖三条件缺口、独立调用、未知输入、默认值传播、导入别名、接口调用、类型字段关系和提前退出。模型流程使用固定答复替身，并实际运行小型 Python 测试。

第二类检查使用 T10、T13、T17、T20、T24、T28 的完整原补丁仓库。程序只读取原补丁、公开需求和公开执行历史。它没有使用前轮人工选取的材料。每条任务最多保留 80 个候选。

这些任务来自此前的诊断集合。它们用于检查实现能否取得关键材料，不能估计未见任务上的检测准确率。下表是 Codex 对提取产物的静态核对，不是独立人类评审。

改进原型的 64 项测试全部通过。全仓库检查得到 5063 项通过、4 项跳过和 2 项失败。30 项子测试也通过。最后的测试范围调整另通过了上述 64 项原型检查。

两项失败均位于本轮未修改的文件。旧模型接口的审计测试仍可复现失败。审计器未支持接口中用于校验输出额度的 isinstance 调用。进程清理测试在读取已退出进程时发生竞争；单独复跑已通过。

当前限制

静态关系表示可能联系。接口接收者、对象别名和异步顺序仍需进一步判断。类型相同或字段名称相同，不证明运行时对象相同。

每个候选最多保存 120 行测试范围，每次入口调用最多贡献四行。路径扩展还有总量限制。截断后保留的测试目录支持继续查阅，但程序不能据此宣称不存在其他联合测试。

原测试中的动态构造、复杂解构和嵌入脚本常产生未知值。存在联合输入也不证明断言足够强。已有联合测试是否未运行，仍须由执行证据支持。

本次没有测量正确检测数、正确补测数、误报、漏报或 resolution rate。提取到相关材料不等于模型能够利用材料。测试执行失败也不自动确认补丁缺陷。
