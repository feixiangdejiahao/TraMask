旧 AI 审阅将 20 个 trial 标为找到有效缺口并生成补测；其中 3 个 trial 命中历史预标注目标。这些是初步标签。

一个 trial 是 agent 完成一次任务的开发记录。记录包含代码阅读、补丁修改和验证过程。本实验选择 30 个不同任务的 trial。每个 trial 在历史审阅中都至少有一项已确认的组合缺口。

组合缺口指验证没有共同检查一组相关条件及其结果。例如，测试分别检查缓存导入和原有缓存，却没有检查导入后是否仍保留原文件。缺口也可能出现在断言中。输入包含组合，不代表测试观察了组合结果。

本次主指标判断每个 trial 是否至少找到一项真实缺口。它允许发现历史标签之外的缺口。另一个指标只判断是否命中选样前的具体目标。两者回答不同问题，必须分别报告。

候选池来自此前审阅的 211 条失败记录。其中 160 条记录同时满足两个条件：存在已确认缺口；项目使用当前程序分析支持的 Python、Go 或 TypeScript。每种语言选择 10 个不同任务。每组含 4 个带多关系缺口的 trial，另含 6 个只有单关系缺口的 trial。

程序对种子 20261007-pilot30-v1: 与 trial 名称拼接后的 SHA256 值排序。它在每组按该顺序选样。全组共 18 个只有单关系缺口的 trial，12 个带多关系缺口的 trial。实验未按模型结果换样。分析失败的 T01 仍计入分母。

模型收到任务需求、提交补丁、相关源代码、自动提取的测试和开发步骤。模型没有收到人工缺口标签、参考实现、隐藏验收测试或任务成败标签。历史标签仅用于选样和后续评估。程序没有手动指定 41 项缺口作为生成目标。

所有 1005 次请求使用 deepseek-v4-flash、temperature 0、thinking enabled、high effort，以及 32768 个最大输出 token。每个候选只调用一次。实验没有让模型根据失败结果修复测试，也没有修改预期值。

provider 返回的模型标识是 deepseek-flash。模型目录将它标为 DeepSeek-V4.1-Flash。官方更新说明也记录了旧名称的重定向。因此，本实验只能说明该名称在本 provider 上实际服务的版本，不能声称测试了原始 V4.0 权重。参见 DeepSeek 官方更新说明和provider 模型记录。

正确检出必须有公开需求或 API 语义支持。审阅还必须确认原验证没有覆盖所报告的组合。历史标签未收录某个建议，不足以判定它误报。反过来，原测试没有提交到代码库，也不足以证明 agent 未运行过该测试。

正确补测必须实际执行。它还必须保留必要的对象、键、状态和顺序，并用有依据的断言观察组合结果。有效断言在补丁上失败，也算成功生成。语法错误、错误 API、无依据的预期值和环境失败均不算成功。

语义审阅由本次 Codex 助手完成。审阅使用公开需求、原代码、完整 trajectory 和执行日志。它没有调用第二个 DeepSeek 评审器，也没有获得独立人类复核。该结果是可追溯的 pilot 评估，不是人类一致性验证后的金标准。

程序分析先找可能未验证的联系，模型再判断该联系是否构成缺口。

程序解析补丁涉及的函数及其测试。它收集调用、结果传递、字段读写、共享状态和条件分支。它用这些联系寻找可能需要共同验证的两端。例如，一个操作写入某个键，另一个操作随后读取同一键。

程序也连接两条相关关系。中间处理必须读取结构、修改状态或影响分支。程序要求共享对象或值的线索，避免只凭相同变量名组合测试。当前实现只搜索短的两关系组合，没有完整建模任意长度流程、并发交错或隐式依赖图。

程序检查原测试是否有相关联合调用和结果观察。若找到此类结构，它保留候选以核对执行证据。本次共有 50 个这样的候选。因此，本次“程序筛选”主要改变提交给模型的问题，没有将所有已有结构的候选从模型调用中删除。

模型根据每个候选及其材料输出一种判断：存在缺口、没有缺口、属于选测问题，或证据不足。对存在缺口的候选，模型直接生成测试。它无需另写一套规则。本次没有模型回答被接受为选测问题。

程序共形成 530 个单关系候选和 475 个多关系候选 ID。这个分类描述程序搜索区域。它不等同于历史缺口分类。475 个多关系候选没有带来任何一项历史多关系目标命中。

三个历史目标的命中结果具有不同含义。

T10，缓存导入。目标缓存先在同一个分析键下保存 a.py。待导入缓存保存 b.py。新测试导入后读取两者，再重载磁盘缓存。两者均保留，测试通过。这确认补强了验证，不说明原补丁有 bug。

T14，Retry-After。旧服务端夹具在发送状态码后才设置响应头。新测试先设置 Retry-After，再发送 429，并通过真实上传入口观察重试等待。测试通过。它使用真实时间阈值，未注入可控时钟；因此存在时间噪声风险，也没有独立断言等待上限。

T24，默认解析模式。旧测试显式指定 put。新测试省略 mode，并提供触发条件但缺少必填字段的输入。公开默认行为要求拒绝该输入，实际补丁却接受了它。有效断言失败，说明该补测揭示了缺陷。

主要不足是目标表达与证据连接，不能只归因于模型能力。

程序没有可靠连接测试编写与执行反馈。例如，T26 自动恢复的历史测试源文件为 0。模型可见临时脚本的部分编写步骤，却缺少后续修正和成功执行步骤。相关脚本使用 JavaScript，而当前恢复只接受 Python、Go 和 TypeScript 路径。模型因此多次把已经执行的 SQL 检查报告为缺口。

局部程序联系没有表达决定性条件。例如，T22 只有两个“检查返回对象”的候选。它们没有表达异步递归入口包住同步 schema，并处理非空递归子项的组合。T20 没有连接配置约束与 Go 运行时的含义。增加相同形式的局部候选，不能自动覆盖这些目标。

多关系目标常依赖同一状态及特定顺序。遗漏包括旧执行结束前重用同一键、没有初始化器的中间依赖、以及两次查询之间的多次真假变化。当前两关系连接没有充分表达这些执行条件。这与 0 / 12 的历史多关系命中结果一致。

模型有时在生成测试时丢失了它已识别的条件。T29 有一份建议正确指出已缓存 Or 查询的更新问题，却在每次查询时创建新 predicate。测试通过，但没有检查缓存查询。因此该建议算正确判断，不算正确补测。其他保留同一 predicate 的生成测试则出现了有效断言失败。

这轮结果支持优先改进两点：连接测试版本与执行反馈；在候选中保留具体的对象、状态变化顺序和应观察的结果。它不支持仅扩大候选数量。由于没有进行手动候选注入或其他对照，本实验不能把 38 项历史漏检严格分配给程序分析阶段和模型阶段。
