如何联动 trajectory 与程序来搜索

建议将研究问题抽象为：恢复原 agent 的验证限制，再搜索一个合法上下文，使被该限制隐藏的行为区别变得可观察。验证限制指测试固定的输入、对象、配置、执行阶段或观察位置。它必须能对应到具体代码，不能只是一句抽象主题。

第一步：从验证过程提出少量可查证的问题

程序先把测试创建、修改、执行结果与相关补丁修改连起来。模型读取这些局部记录，提出具体问题。例如，“这次 helper 替换是否绕过挂载？”或“复制是否保留共同捕获单元？”模型可以在此处参与，不必只在最后作判断。

搜索优先级可由三个信号支持：轨迹明确提出过风险；测试在失败后改变了相关条件；最终代码仍含对应分支。只有测试名相似或函数共同出现时，证据较弱。该排序目前是待验证设计，不是本轮测得的最佳策略。

第二步：让程序返回足够小的行为事实

每个候选只需表达四项信息：原测试固定什么，哪个操作可能受影响，哪个对象或值连接它们，断言实际观察什么。程序给出代码位置和能确认的关系。对别名、回调和框架行为无法确认时，保留未知，不将模型猜测写成程序事实。

例如，T24 可表示为“测试显式 mode=put；调用者仅局部默认化；helper 读取原 options；断言检查是否抛错”。T13 可表示为“inc 和 get 读写同一捕获单元；原传递测试只搬运同一函数的重复引用”。这种表达比纯关系名称更直接，也比全仓库形式模型更容易核查。

第三步：沿关系搜索，而非任意交叉功能

优先复用原测试的合法输入和断言。只改变隐藏区别的那一处条件。可改变输入取值，复用同一对象连接两个阶段，或把断言延伸到后续消费者。T24 删除显式 mode，T16 复用 Env，T27 检查 result，分别说明这三种方式。

搜索可以从一个局部关系开始。若结果需要经过另一操作才可见，就沿相同对象或值继续。T13 需要共享、传递、读写三个联系；T30 需要子宽度、父列宽和兄弟偏移。关系数量由行为传播需要决定，不由固定的二元或三元输入枚举决定。

第四步：防止生成过程再次消除目标条件

模型生成候选后，程序核对关键条件是否仍在。例如，T27 保留默认过滤器，T22 保留非空 children，T13 保留两个不同函数共享单元。这里先核对目标结构，不要求模型额外发明一整套精确检查规范。

模型再依据公开需求解释预期。原实现、原测试和原 agent 的推理只能提供线索。若同一联合测试已存在，则选择补断言、修正预期或重跑；不把它包装为新输入缺口。

可以形成的研究贡献

核心候选贡献是把 coding agent 的验证决策变成程序搜索约束，并恢复原测试无法区分的行为。trajectory 提供“为何只验证这一范围”，程序提供“这个范围之外是否存在相连行为”，补测提供可观察的区分实例。

这一设计利用了仓库级 issue resolution 的特性：agent 同时修改实现与测试，测试期望可能与补丁共享假设，验证结果又依赖代码版本。静态切片、组合测试或 LLM 推理都是可用组件。论文的新意应由它们在这个问题上的具体抽象、搜索机制和实证收益支撑。

本轮观察还没有证明新算法有效。前次八任务 pilot 中，加入历史文本没有稳定超过原组，31 个行为模型也没有获得完整的原测试输入绑定。两项结果并不矛盾：轨迹确实包含有用线索，但现有表示还没有把线索可靠地接到程序和原测试上。

下一次小 pilot 应先检验这条连接：能否从轨迹提出具体问题，能否绑定真实程序位置，能否保留原测试条件并产生有区别的候选。可固定相同代码材料，对照有无相关轨迹，并加入无关轨迹作为对照。历史失败测试和 gold 继续只用于离线评估。

轨迹中的逻辑：第 69 步已看到重复输入产生 5 次调用，而测试预期是 2 次。agent 将原因归为任务完成过快，使请求没有重叠。它给被调函数增加 sleep，随后测试通过。

缺少什么或需要补强什么：保留重复输入，改变并发上限或任务完成时序。区分一次 batch 内去重与仅合并时间上重叠的调用。

搜索方式：从失败后的 sleep 修改回查公开 batch 契约，再检查不重叠调度。先识别原失败，避免把同一已见行为算成全新发现。

证据强度：轨迹明示调度假设，并实际修改测试。

判断边界：历史固定目标 T01-R1 仍留在旧统计中。本轮发现它与已观察的未合并行为密切相关。不能笼统称 agent 从未验证 batch 去重。第 97 步移除串行化锁属于合理夹具修正。
