   We further demonstrate the effectiveness through concrete examples. PR 14489 in JabRef improves
the HTTP server code but introduces a bug: HTTP server endpoint/libraries/demo fails, returning
HTTP 500 with HTML and breaking demo library retrieval (Issue 14807). After reporting, the
bug was promptly fixed. The detection of this bug illustrates RippleGUItester’s effectiveness in
identifying issues in backend server logic and execution. As another example, PR 5976 in Zettlr
refactors the parsing and rendering of Markdown footnotes. RippleGUItester analyzes the potential
impact, and generates test scenarios focusing on high-risk behaviors such as multi-block footnotes.
After execution, RippleGUItester detects multiple bugs, including incomplete rendering of multi-
block footnotes, odd text spacing, incorrect handling of indented continuations, missing footnote
markers, and tooltips appearing for invalid footnotes. (Issue 6099, Issue 6102, Issue 6103, Issue 6104,
Issue 6106). Fig 7 shows a subset of these bugs. After reporting, all issues were fixed, demonstrating
the effectiveness in detecting bugs from non-trivial refactoring changes.

   We present another example from Godot. PR 113611 fixes missing “+” separators in editor
tooltips describing keyboard shortcuts, a change that appears purely cosmetic at first glance.
Through change-impact analysis, RippleGUItester flags potential localization risks, with support
from preceding change intents (PR 106943 and PR 106946) that altered overlapping code handling
tooltip translation. Guided by this analysis, RippleGUItester generates and executes test scenarios
for tooltip rendering under language-switching conditions. It detects a bug (Issue 114157 ), where
switching the editor to French produces mixed-language shortcut tooltips. While the developers
traced this to temporarily outdated translations rather than functional code, RippleGUItester
successfully detected the user-visible issue and enabled timely translation updates.
