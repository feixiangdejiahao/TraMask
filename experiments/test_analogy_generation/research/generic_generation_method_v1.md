**从已有测试学习上下文交换：Test-Derived Context Exchange，v1**

2026-09-23。本文说明当前原型的算法与研究假设，不报告实验效果。实现位于 [generic_composition](../generic_composition/)，评价约定见 [预注册协议](generic_generation_evaluation_plan.md)。

核心想法是：**一个测试提供已经使用过的操作上下文，另一个测试提供输入、状态准备和断言，把前者的操作放到后者的观察路径上。** 操作从具体测试语法中抽取；原型不按项目或库名选择人工编写的组合规律。语法可组合与旧断言仍正确是两个独立判断。

**1. 一个简单例子**

假设文档明确规定 `wrap(x)` 返回原来的值，下面是两个已有测试：

```python
def test_context():
    assert wrap(calculate(1)) == 2

def test_observation():
    result = calculate(3)
    assert result == 6
    assert type(result) is int
```

第一个测试的 AST 包含 `calculate(1)` 和外层 `wrap(calculate(1))`。程序把共享子树抽成洞，得到 `E → wrap(E)`。第二个测试提供同一 producer `calculate` 的另一个调用，于是候选测试为：

```python
def test_combination():
    result = wrap(calculate(3))
    assert result == 6
    assert type(result) is int
```

`calculate(3)`、局部赋值和两个断言都来自第二个测试；`wrap(...)` 来自第一个测试。模型没有生成新的期望值，也没有决定使用什么操作。模型只判断这条已构造的候选，能否由文档和原测试支持。

这里的文档前提不能省略。单独看到 `wrap(calculate(1)) == 2`，并不能推出 `wrap` 对所有值都保持结果：总返回 `2` 的函数也满足这个例子。因此抽出 `E → wrap(E)` 只证明它来自现有代码，不能证明它保持 oracle。

检索只要求组合的一侧与当前 issue 有关。若检索到的是 `test_context`，它提供操作，普通测试提供观察；若检索到的是 `test_observation`，它提供观察，普通测试提供操作。这里的“双向”指来源角色可以互换，不表示当前引擎自动学习每个操作的逆变换。

**2. 核心抽象及机械保证**

把一条语法改动表示为带关联洞的上下文对：

\[
e: C_0[h_1,\ldots,h_k]\longrightarrow C_1[h_1,\ldots,h_k].
\]

若源片段为 `A`、`B`，学习阶段必须找到同一替换 `σ`，使 `C0[σ]=A`、`C1[σ]=B` 精确重构源代码。若目标表达式匹配 `C0[τ]`，候选替换就是 `C1[τ]`。重复出现的同一个洞必须绑定同一子树；标点、调用名、属性名保持为语法常量。函数调用本身可以是载体，例如 `calculate(3)`；方法调用的 receiver 也可以是载体。

这些等式是**语法重构等式**。它们不表示 `C0[τ]` 与 `C1[τ]` 的求值结果、对象身份、异常、调用次数或副作用相同。例如 `E → pair(E,E)` 可以机械重构，但会重复求值 `E`；实现记录载体出现次数变化，不把它自动认定为安全操作。

底层 [context_edits.py](../generic_composition/context_edits.py) 支持包装、去包装、替换包装和多洞重排。当前 [engine.py](../generic_composition/engine.py) 自动发现 AST 操作时只使用现有调用参数与其父调用的包含关系 `E → C[E]`，尚未枚举所有上下文对，更未实现任意语句序列插入。不能把底层 API 的能力范围当作已实现的候选搜索范围。

**3. 当前候选算法**

先由已有 [观察前沿检索](observation_frontier_method.md) 选出与补丁相关的测试，默认取前十。再解析仓库测试和允许读取的历史测试片段，保留断言、完整测试、参数行、表达式 AST、字节位置、导入及局部可能依赖。完整测试供最终复制；依赖分析主要用于关联输入、调用端口和观察，以及保护期望值来源。

当前只实现两种语法来源，它们共享“已有差异＋目标载体＋原测试观察”这一抽象：

| 语法来源 | 如何学习 | 如何限制目标 | 没有证明的事情 |
| --- | --- | --- | --- |
| 同一调用端口的字符串差异 | 字符串分为数字、单词、空白和标点；比较相近样本，保留共同 token，提取有界替换；纯数字差异还可形成整数偏移候选 | 已解析的同一 callee 身份及参数位置或关键字；目标还须匹配 token 上下文 | 输入文法、取值域、数字偏移是否合理、输出是否不变 |
| 同一 producer 的 AST 上下文 | 从已有 `C[E]` 抽出共享表达式 `E`，形成关联洞并检查原片段重构 | 调用按导入模块与符号、或同文件完整 callee 匹配；非调用要求语法种类及输入端口签名集合都相同，没有端口则不支持；再做精确 AST 匹配 | 返回类型兼容、对象身份、别名、效应、上下文的语义保持 |

例如在同一 `scan` 参数位置见到 `"a, b" → "a,b"`，程序可以提议把另一个测试的 `"c, d"` 改为 `"c,d"`。原型不把这个字符串当成手写的某种协议，也不因去空白在一个例子中可行就自动接受其 oracle。合法性仍依赖任务契约。

新候选至少有一侧来自检索种子。构造时只替换目标测试的指定字节范围，并携带操作来源、目标来源及导入要求。重复的可执行改动去重，按照检索 focus 和规则轮转分配最终候选预算；全局和分组预算限制搜索量。当前 focus 取相关来源中检索最靠前者，因此这不是对每个被复制测试的均匀抽样。

默认候选上限为 128；AST 转换、洞数、候选上下文数、测试体大小和样本邻居数也有固定上限。搜索是有界且不完整的。当前 AST 入口限于实现列出的调用、二元表达式和容器等种类；并不自动涵盖所有标识符、lambda、闭包体或跨语言字符串中的程序。

**4. Oracle 如何保留，以及哪里仍然未知**

候选复制观察来源的整个测试，保留其断言、相关准备步骤和测试框架结构；只应用已记录的输入／上下文改动及必要的测试注册名变化。既有期望常量不由模型重新生成，也不由候选程序运行结果填充。

“断言文本不变”本身不够。例如 `want = 6; assert actual == want` 中，修改 `want` 的定义已经修改了 oracle。因此程序追踪 expected 表达式、断言 helper 的 expected 实参、调用者定义以及局部可能值依赖；**只服务于 expected 的已识别来源被排除出可编辑输入**。参数化表格也保留整行绑定，不能把 expected 单元重新当作普通输入。

另一种情况是 `assert returned is input`、`assert after == input` 这样的关系断言。`input` 同时参与被观察计算和期望关系，不应仅因出现在断言右侧就一律冻结。当前实现将这类共享来源显式标为 `candidate.oracle.shared_input_expected_dependency=True`，由准入阶段检查整个关系是否随输入改动仍成立；它们不能被描述成“固定期望值完全未变”。这只是对已识别数据依赖的区分，尚无健全的通用别名或堆依赖证明。

模型每轮只接收一次固定请求：issue、相关完整测试、断言及 helper、操作的源片段、所有具体候选。输出只能是已有候选 ID 的子集。未知 ID、重复 ID、代码或额外输出字段会被拒绝。模型不能修改输入、改写断言、添加操作、选择下轮搜索方向，也不会看到执行结果。

这是有限候选的语义准入，不是形式验证。模型仍可能误接收或误拒绝；模型不能从缺失的契约中恢复唯一正确语义。既有测试也可能本来就有错误。缓存复用保证相同产物可重放，不能保证重新调用模型时答案相同。

**5. 与 2026 研究工作的关系**

MR-Coupler（FSE 2026）用签名、调用和状态交互恢复功能耦合，再生成、扩增并检验蜕变测试。这里借鉴的是让一个可计算的关系直接约束搜索空间，并把关系的有效性单独处理；本方法用已有测试中的上下文改动约束构造，不要求模型先创造一个通用蜕变关系。论文也报告了基于原程序／mutant 通过率的验证存在无法区分的情况，因此这种验证不能直接成为 oracle 正确性保证。[FSE 官方收录](https://conf.researchr.org/details/fse-2026/fse-2026-research-papers/200/MR-Coupler-Automated-Metamorphic-Test-Generation-via-Functional-Coupling-Analysis)、[作者论文 §3、§4.5](https://arxiv.org/html/2604.10126v1)。

*Escaping the Self-Repair Trap*（ASE 2026 已列入 Research Papers）指出，在以当前实现行为为规范的回归 oracle 补全中，反复优化执行通过可能削弱断言的检错能力；其 DCAware 采用静态上下文与选择性动态状态支持非迭代生成。本项目从中得到的设计取舍是：不把“让候选测试通过”作为改写期望值的反馈目标，模型准入与执行评价分离。该论文并没有证明本方法的上下文迁移正确，当前项目也没有照搬其动态状态生成 oracle 的设置。[ASE 官方议程](https://conf.researchr.org/track/ase-2026/ase-2026-research-track)、[作者预印本摘要](https://arxiv.org/abs/2608.05917)。以上来源于 2026-09-23 核验。

可研究的假设是：**把操作来源与观察来源分开，并将组合限制为源代码可重构的上下文交换，是否能在固定预算下减少无依据的组合，同时保留有用的交互缺陷触发能力。** 这需要独立项目、负控制和消融支持；“使用 AST”“调用 LLM”或重新命名已有测试放大并非新颖性证据。

**6. 可复现边界与尚未实现的部分**

[实验入口](../scripts/run_generic_experiment.py) 分为准备、准入、冻结、执行和汇总。准备阶段保存输入、候选、证据及算法哈希，并固定模型标识、输出 token 预算和允许的轮次；准入阶段核对这些约束并读取固定文件；冻结阶段才把选中的字节改动物化为测试。候选代码、模型请求、响应及选择结果均可追溯。每个声明的准入轮次最多发一次请求，已有轮次不覆盖、不自动重试；预定两轮用于观察重采样差异，各轮独立使用原证据。应报告全部轮次，不能选取效果最好的一轮。

参考补丁、隐藏 verifier、人工目标和执行评价不进入候选构造或模型准入。参考／候选执行只评价冻结产物；双方通过不证明 oracle，候选失败而参考通过也需要独立契约审计。该数据通路约束不等于自动证明研究过程从未受到开发集启发。

当前静态分析的作用是可追溯的 AST 重构、粗粒度符号／导入关联、局部可能依赖与作用域检查；它没有证明完整类型、闭包捕获、指针别名、状态效应或动态框架行为。未知绑定、不可支持的参数化形式和无法物化的测试应保留为失败或 unsupported，而不是由模型现场修补成另一条测试。

原型也没有通用的弱 oracle 检测器，不能自动判断 `assert value is not None` 对某个交互是否足够，更不会自动增加正确的字段断言。它可以携带另一测试已经写出的观察，但这不等于学会新的强 oracle。若缺少适用的上下文、独立契约或有区分力的已有观察，方法可能没有输出，也可能漏掉问题；提高 issue resolution rate 仍需另做受控修复实验。
