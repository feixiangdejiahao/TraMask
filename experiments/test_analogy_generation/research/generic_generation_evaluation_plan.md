# 通用组合生成：预注册评价协议 v1

固定时间：2026-09-23。这是新方法的评价协议，不把先前七个 pilot 的结果当作泛化证据。当前先执行三个跨项目任务和八个独立控制任务；样本小，只报告可复核的证据及失败边界，不作总体有效率推断。此文件固定后，改变规则或预算均须形成新版本，旧结果保留。

## 1. 隔离与冻结

七个 pilot 和此前已查看的项目仅用于 discovery。生成器只能读取当前任务的 issue、候选实现、原有/agent 测试及公开 API 文档。参考补丁、隐藏 verifier、执行结果、人工目标和 evaluator 控制表不得进入生成器或提示。

在打开所选 holdout 的 issue/源码之前，冻结生成器代码、提示、模型标识、输入文件清单、语言支持范围及预算；若为环境准备提前打开源码，须记录暴露范围，并由未查看该源码的生成器开发者继续实现。通用语言/测试框架适配器可以解析 AST、解析依赖与运行测试；不得按仓库、API 名、issue 关键词或 pilot ID 分派组合规则。方法无法处理的项目记为 unsupported，不能为取得成功而替换。模型重采样预定两轮，全部报告，不选最优输出；第二轮不接收第一轮评价反馈。

每任务至多生成 128 条义务，排序与截断规则在生成前固定；保留提出但被拒绝的义务及原因。每任务模型调用和 token 上限由根代理在代码冻结清单中给出，所有比较方法使用相同上限。没有明确预算的版本不能宣称成本公平。冻结产物逐字节用于候选与参考/控制实现；控制失败、编译/导入失败、超时与测试体语义失败分别记录。

来源为 [DeepSWE v1.1](https://deepswe.datacurve.ai/data/v1.1/trials) 的本地缓存，不声称重新下载了当前全部目录。缓存有 113 个任务、31,617 个 trial，其中 DeepSeek-v4-flash 为 452 条。只使用任务 ID、仓库、语言、base commit、模型/harness 标识和 trajectory/候选补丁可用性；不使用 outcome、reward、score、错误类别或 verifier 元数据筛选。

## 3. 独立可证伪控制

独立评价者准备八个小型多语言任务，生成器仅看到普通源码、API 说明和原始测试。完整有限输入域、正确语义、注入故障及判定表由 evaluator 单独保存；不得回流为按任务过滤器。每个任务都有正确实现，部分另有保持原始测试通过的交互故障。确切实例在方法冻结前隔离，不依据生成结果改变。

控制覆盖：(1) 排序消除输入排列；(2) 两个输入分别变化不支持输出常量运输；(3) 值相等但对象身份/别名不同；(4) 重复调用的计数与副作用；(5) 状态操作顺序不交换；(6) 输入有效域/部分函数；(7) 相同当前观察但后续状态不同；(8) 容器位置与次序对观察的影响。至少包含确有可保持关系的正控制和不能保持关系的负控制。有限域穷举给出局部真值；这些控制评价抽象的可靠性，不替代真实项目的外部有效性。

## 4. Oracle 判定先于缺陷宣称

对每个报警，分别检查输入是否合法、上下文前提是否满足、被运输断言是否有契约/原测试/可检查语义推导支持。双方都通过不能证明 oracle；候选失败且参考通过只构成待审差分；双方失败不自动是误报。参考也可能与 issue 冲突。

评价者先记录独立契约证据，再查看候选/参考结果；对报警全部审核，对通过义务按固定哈希抽样至少 20%（每任务至少 5 条，数量不足则全部），防止遗漏“错误 oracle 恰好双方通过”。审核标签为有效 oracle、错误 oracle、输入/前提不适用、证据不足或基础设施失败；有效 oracle 下再判断是否为真实缺陷。保留逐项依据和 unknown，不以多数表决代替证据。重要或有争议项目交第二评价者独立复核。

只有源控制全部按预定依赖通过，且无相关全局运行错误，才可形成有效组合证据。原始控制已经失败，不能归为新增组合的误报；也不能将其原始缺陷当作组合增益。已知目标命中与其他真实缺陷分开，重复义务按同一根因去重。

## 5. 预先定义指标与比较

报告完整流水：任务总数 → 可解析/有种子 → 提出/准入/拒绝 → 生成/执行 → 控制通过 → oracle 审核 → 独立缺陷。unsupported、无输出、环境失败、前提失败都显示数量，不能只报告成功子集。

- **Oracle 有效率**：经审核为有效的义务 / 已审核义务；报警和通过样本分别报告。抽样汇总须按已知抽样概率加权。
- **报警精度**：经独立确认的真实缺陷报警 / 可判定报警；同时给包含 unknown 的保守下界。参考报警率单列，不能命名为全局 FPR。
- **正确控制误报率**：在已证明正确的有限控制上产生错误报警的任务比例及义务比例。语义未知的真实项目不进入该分母。
- **交互缺陷召回**：独立预先注入且源测试通过的故障中被有效组合发现的比例。真实 holdout 缺乏完整缺陷全集，只报告每任务独立确认的新增缺陷数，不冒称 recall。
- **效率与稳定性**：每任务时间、义务数、模型调用/token，以及两轮全部结果。多条近重复断言不当作独立样本；未来置信区间按仓库聚类。

最小比较包括原测试重放、类型匹配的直接输入组合并原样运输断言、完整方法；另消融语义/效应约束以量化其对错误 oracle 的影响。所有方法使用同一源测试、义务预算与评价控制。比较尚未执行时标为计划，不能以工程状态代替数据。

**Issue resolution rate 是另一个实验。** 在相同修复模型、轮数和预算下，按任务配对比较无新增测试与提供生成测试的修复结果；补丁冻结后才运行独立 benchmark evaluator，并报告回归。组合命中率、候选差分数和参考通过率都不能直接代替 resolution rate。
