# 保持观察的上下文扩展

这是实验前的核心抽象记录，保留当时的假设与设计。当前实现、默认模型证据及限制以 [method_design.md](method_design.md) 为准；统一 v6 的 7/7 目标检出、三条参考冲突和重抽样见 [实验报告](combination_generation_experiment.md)。下文“仍在实验”描述的是初稿状态。

核心问题是：**已有测试的正确观察，进入另一种合法上下文后是否仍然成立？** 组合遗漏表现为某个观察尚未在该上下文中接受检验，例如闭包进入 clone、转换进入递归、路径进入命令解析。搜索单位是“已有观察 × 可执行上下文变换”；测试 B 可以提供变换材料，但不要求一定存在完整的第二个测试。

设 t 是包含输入、操作和断言 a 的种子，C 是扩展上下文，B_C 是对应的基准构造，g_C 是适用条件。核心义务只有一个：

\[
g_C(t)\;\Longrightarrow\;\mathcal O(C[t])\equiv_a\mathcal O(B_C[t]).
\]

左边执行新组合；右边给出可追溯的 oracle。符号 ≡ₐ 表示在指定观察下的一致：可以是两边满足同一个已有断言，也可以是两条等价构造路径返回相同的可观察值。不要求整个程序状态相同。g_C 是待核验的语义前提，写出该式不等于证明它。

**算法围绕这一个义务展开。**

1. 用 observation frontier 检索少量种子：解析断言及输入绑定，沿数据流确定所观察的生产对象；在相关测试之间轮流选择代表。它解决入口选择，不证明 oracle 能迁移。
2. 在种子的绑定结构上枚举有限的 C，并同步构造 B_C。执行改写操作确定，不让模型自由撰写测试或期望值；记录原始语句到新语句的对应关系。
3. 检查 g_C，生成原始/中性控制和组合检查。控制失败时保留诊断，不能将依赖它的组合失败当成新缺陷。
4. 冻结产物并执行。候选告警独立计算；随后用相同产物运行参考实现，记录参考告警和无效构造。参考结果只评价生成质量，不能充当生成时的 oracle 或事后筛选器。

**不同 pilot 是同一义务的实例。**

| 上下文扩展 C | 基准构造 B_C 与观察 | 程序分析的作用 |
|---|---|---|
| 脚本作用域提升到返回复合值的工厂，经宿主调用 | 同一工厂经 guest 调用；比较返回 callable 的执行结果 | 提取内嵌程序的绑定、自由名、返回形状，生成有限调用序列 |
| 共享状态从全局提升为局部捕获，再 clone | 新建等价实例执行相同写入与读取；同时观察原实例不变 | 保留捕获关系，给被写绑定添加 observer，使共享丢失可见 |
| 非恒等动作进入递归构造 μF | 对同一有限输入执行足够深的 F 展开；比较输出 | 找到递归孔、动作位置和 donor 的实际值变化；界限不足则不形成证据 |
| Path 绑定扩展为空格文件名和合法引号表示 | 同步替换 setup、调用和断言中的同一绑定 | AST 绑定与字符串插值分析，避免只改输入却冻结旧路径期望 |
| 协议输入增加一个语法坐标/修饰位 | 保留种子的字段断言，仅在保持条件成立时运输 | 将字符串解析为坐标，拆解 bitset，关联字段观察和输入来源 |

这些是受限语言适配器。当前 Go 分析使用受限绑定及自由名检查，不能称为完整跨语言别名分析；递归比较受展开深度约束；协议编码规则是显式领域先验。

**依赖关系只告诉我们哪里值得组合。** 它不能说明组合是否合法、优先级是否改变、旧断言是否仍成立。更不能因为候选源码里没有某条依赖就认定不存在关系：缺失传播本身可能正是缺陷。早期最小函数依赖推断已出现误报，增加经验 guard 又造成漏报，见[执行记录](context_lifting_execution_notes.md)。

少量 LLM 的职责收缩为提出纯布尔保持条件 `preserves(a, source, followup)`。输入限于 issue、已有测试和相关代码；输出冻结为受限表达式，经 AST 检查、已有正反事实及局部反例检查后使用。输入变换和期望断言仍由程序产生。检查能拒绝部分错误，不能证明模型条件正确；当前模型条件仍在实验，尚不能宣称可靠解决 oracle 问题。文档角色推导的 alias 运输同样明确保留语义假设。

**2026 论文提供的设计依据。** MR-Coupler 用签名、调用及状态交互筛选功能耦合方法，再生成关系测试并通过放大与变异分析检验。可借鉴的 insight 是让程序结构约束搜索，并把关系有效性单独验证；我们并未据此获得正确性保证。[FSE 2026 官方页面](https://conf.researchr.org/details/fse-2026/fse-2026-research-papers/200/MR-Coupler-Automated-Metamorphic-Test-Generation-via-Functional-Coupling-Analysis)、[论文 §3](https://arxiv.org/html/2604.10126v1)。

ArrayDiff 的序列生成显式维护输入要求；替换 API 调用时约束输出类型和形状，以免破坏后续输入。其 LLM 主要辅助迁移已有语义要求。这支持“变换必须携带可检查的适用条件”，也说明仅靠类型兼容不足以保证有效组合。[FSE 2026 官方页面](https://conf.researchr.org/details/fse-2026/fse-2026-research-papers/107/LLM-Assisted-Input-Requirement-Aware-Differential-Testing-of-Array-Programming-Framew)、[论文 §3.1–3.2](https://jhe16.github.io/files/FSE26.pdf)。以上来源于 2026-09-23 核验。

与既有蜕变、差分和测试放大方法相比，潜在贡献是从**观察尚未覆盖的上下文扩展**组织搜索，并以绑定保持的改写自动构造 oracle。当前只是可检验的研究假设，不能宣称新颖性已成立。需要在未见 issue 上比较无上下文筛选、自由 LLM 生成和既有放大基线，分别测目标缺陷检出、有效组合比例、参考告警与成本；七个已知 pilot 不能证明泛化。
