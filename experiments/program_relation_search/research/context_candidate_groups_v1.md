# 同一观察上下文中的候选分组：静态首版

2026-09-29。实现和通用 toy 先冻结，再统计 17 个旧全候选池；没有调用模型、执行目标程序或读取评价目标。封存材料：`results/relation_search_20260929/context_candidate_groups_v1/seal.json`。

## 核心问题与抽象

例如同一个测试的 `result = operation(10); assert result == 10` 已生成输入 `20`、`21`、`22`、`23` 的四个候选。四次分别解释相同程序很浪费；可以向模型呈现同一源码上下文中的四个明确替代项，请它选择至多一个值得补全预期的候选。四个输入仍可能跨越不同语义边界，分组不声称它们行为等价，也不把其中一个的正确预期推广给其他成员。

这里的可计算对象是**共享源观察上下文的替代项集合**。组内共同条件是：原测试、操作族、语法形状、编辑的精确源码位置和角色、可达的原观察及编辑端口集合、显式观察焦点均相同。语法形状复用现有 `semantic_selection`：擦除字面量值，保留 AST 结构、运算符、成员名和导入身份。直接修改接收对象或 callee 名称时还保留确切名字，防止局部名字归一化把不同绑定合并。原断言的 actual、expected、assertion 跨度和每个编辑原文全部保留。

程序位置本身区分 `read` 之前和之后的两个相同文本断言；对象和 callee 的区别不会因为名字类似而当作同一个问题。组内的每个候选仍是原来可独立重放的程序编辑。这个静态原型尚不发送 prompt，也不产生或验证 expected。

## 算法和接口

`experimental/context_candidate_groups.py` 提供三个接口：

1. `build_catalogue(corpus, frontend, candidates)` 复用 shape 和 impact 分析，得到完整分组及源证据；无目标或缓存输入。
2. `schedule(catalogue, budget=16, max_group_size=4, policy='shape', previous=None)` 从各上下文尚未展示的候选中，按原 shape 排名每次取最多四个。优先服务累计展示次数较少的上下文。`shape` 按原次序轮换；`impact` 优先增加尚未展示的观察及观察端口，每第四组使用原 shape 次序。
3. `select(...)` 合并上轮保留候选、重新建目录、调度。本轮未展示的所有候选保留在 frontier，包含当前断言接口不支持的候选；同一个候选 ID 的源材料改变会明确拒绝。

每轮预算是最多 **16 个问题组、最多 64 个候选、最多 16 次预期修订**。这与 16 个单例问题的候选曝光数和 token 预算不同，不能直接称作等成本。候选出现在被选组中也只代表“已展示”，不代表模型已修订或检测出缺陷。当前跨轮状态按展示更新；接入模型后仍应另行记录每个成员的判断和产物，不能将未被模型选中等同于正确或永久放弃。

## 静态结果

旧全池共有 4,502 个候选，形成 4,160 个上下文。其中 2,315 个候选符合已有局部断言审查接口；其余 2,187 个留在 pending，并未删除。4,160 个上下文中有 3,995 个只有一个成员，严格共同上下文能合并的比例有限。具有可审查成员的上下文有 2,049 个，其中 1,929 个也只有一个可审查成员。N09、N10、P7 在这个定义下全部是单例。

| 调度 | 轮次 | 展示问题组 | 展示候选 | 累计展示的原观察数 |
| --- | --- | ---: | ---: | ---: |
| shape | 第一轮 | 272 | 322 | 306 |
| impact | 第一轮 | 272 | 325 | 674 |
| shape | 第二轮 | 266 | 313 | 530 |
| impact | 第二轮 | 266 | 296 | 865 |

每列是 17 个 case 的求和；第二轮观察数是两轮累计，各轮展示候选互不重复。P5 第二轮只有十个剩余可审查问题，因而总组数是 266。第一轮平均每组分别展示 1.18 和 1.19 个候选，没有接近理论上限四个。impact 增加的是源码观察曝光，不能据此推断正确组合测试、漏报或 issue resolution 已改善。两个策略每轮 16 组固定，但展示候选数不同，后续模型实验还需测实际输入输出 token。

全量静态计算耗时约 152 秒。12 个新增通用 toy 覆盖 Python/Go/TypeScript 字面量分组、不同调用阶段、接收对象/callee 区别、显式观察焦点、每组限额、跨轮公平、零预算、输入顺序确定性、同 ID 改源拒绝、无评价标记依赖、不可审查候选保留；与 33 个相关既有测试合计 45 通过。对全 17 个结果另验每轮无重复、跨轮无重复、每组同一上下文、组和成员预算、已展示与 pending 构成完整分割，全部通过。

## 当前结论

这个简单分组机制能够减少一部分重复上下文，但旧候选池里严格同上下文的变体没有设想中密集。不能为增加合并量直接放宽对象、观察阶段或 callee 区别。是否帮助模型选择跨语义边界的输入、是否减少漏报，尚须独立的分组 prompt 实验；此次结果只证明完整候选保留、有限分组以及静态曝光变化。评价端可以在封存后核验历史目标覆盖，生成端不依据该结果调整规则。
