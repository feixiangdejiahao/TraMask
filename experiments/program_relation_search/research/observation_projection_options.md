# 冻结实现之后的观察扩展选项

本文只基于已冻结的通用实现与独立微例分析，不使用真实案例、运行结果、参考实现或隐藏测试。核心和测试文件均未修改。下列微例是为说明表达能力自行编写的程序，不是经验效果结论。

## 1. 最大缺口在观察本身，不能只靠更聪明的 τ 补齐

当前 proposals 对每个候选选择一个已有 capsule，保留其实际值表达式及断言谓词，暴露一个已有 expected 位置。虽然协议有 observe 编号，当前每个候选只有一个观察选项。模型能够改变期望，不能改实际值表达式，也不能增添原观察没有读取的状态。

固定观察 O 把状态划分为等价类：

    s ≈O t  当且仅当  O(s) = O(t)。

若正确组合状态 s 和错误组合状态 t 落在同一个等价类，那么任意只改变右侧期望的 τ 都无法区分它们：两者要么一起通过，要么一起失败。这是表达能力限制，与模型推理能力、提示长度和候选数量无关。

这不意味着当前整个候选池必然检测不到某个缺陷。另一个已具有强观察的源测试可能刚好接受同样的上下文。但当前算法不能系统地确保“有价值的组合状态”和“能区分它的观察”出现在同一个生成测试里。候选生成多样性与观察多样性是两个独立维度。

## 2. 一个统一的扩展：把观察切片也作为可移植的程序项

建议把组合候选写成：

    action slice S  +  observation slice q  +  expected transformer τ

S 决定建立哪些对象、执行哪些操作及其顺序；q 决定在 S 的哪个最终值或状态版本上读取什么。两者都由程序从源码选择、裁剪和换根。LLM 仍只给选定观察的期望表达式 τ，以及必要时在冻结输入上可计算的条件。

最小算法如下。

1. 从每条源断言的实际值向后切片，得到观察片段 q(r)。把其被测 receiver 或返回值 r 暴露为根端口。保留必要的常量定义、索引、字段投影及观察调用；不搬运原断言框架或原对象初始化。

2. 独立保留已有的上下文/状态序列生成。对每个 S，列出组合之后可观察的根：原 receiver 的最新状态版本、操作返回值、包装上下文的结果。分配类型和别名标识。

3. 按已解析类型、构造器来源和实际调用位置匹配 q 的根端口。将 q 的根统一替换为选定根，搬运其封闭的局部依赖，产生新的实际值表达式 O'。源观察里没有对应来源的自由名不能直接借用。

4. 每个生成测试只执行一个新的终端观察。不同观察各自重放同一动作片段，避免 snapshot、pop、iterator 等潜在有副作用的观察互相影响。无法证明纯度并不必然禁止该观察，只是不把多个观察顺序串到同一对象上。

5. 给 τ 的值槽仅来自可静态解析的源期望和动作输入，包括 recipient 原操作输入与 donor 新操作输入。若 O' 没有已知前态期望，模型可以提出仅由这些冻结输入构成的绝对期望；不能把未知值当成已知 pre，也不能运行 SUT 录制它。未知且实际被公式所需的信息仍然是 unsupported。

6. 模型补期望，程序生成固定形状的断言。模型不能新增操作、改动作顺序、发明观察方法或写测试正文。相同动作片段可产生少量 q 不同的候选，按源观察调用和字段路径轮换，而不是让某个测试中大量相似断言占满预算。

这不是按 API 名字编写算子。q 的组成单位就是测试中出现过、经依赖分析抽出的程序切片。“同类型换根”是统一操作。是否某个 q 的语义确实适用于这个状态，则仍需要源契约与小范围语义补全。

### 微例一：状态序列的长度正确，顺序错误

源测试分别验证一次插入、数量或快照：

    s = Sequence()
    s.put("a")
    assert s.size() == 1

    other = Sequence()
    other.put("b")
    assert other.snapshot() == ["b"]

程序把第二个 put 接到第一个场景后。若实现错误地把新元素插到头部，组合状态为：

    s.size()     == 2
    s.snapshot() == ["b", "a"]

只有 size 观察时，即使 τ 得到完全正确的 2，也看不到顺序错误。

程序从第二个测试提取 q(r) = r.snapshot()，把 r 换成组合后的 s。固定输入槽提供两个操作的字符串参数，模型只补：

    τ = [arg[0], arg[1]]

生成实际值 s.snapshot()，期望 ["a", "b"]，即可观察到交互错误。独立 toy 实际得到 size=2、snapshot=["b", "a"]；旧观察通过，新观察失败。

边界：单次插入的源例子本身不能证明多次插入是 append 而不是 prepend。τ 所依赖的顺序语义应由公开契约或明确的源测试证据支持；有限见证只能反证，不是归纳证明。若整个可见语料只有 size 观察，也没有可静态读取的内容投影，纯源观察迁移不会凭空创造 snapshot。

### 微例二：上下文改变返回类型，原观察位置不再合法

源测试：

    assert Atom("\0").text == "\0"
    assert wrap(Atom("a")).item.text == "a"

Atom 有 text，wrap 返回具有 item 的 Envelope。把包装上下文接到第一条测试，如果只改 expected，保留下来的实际值会是：

    wrap(Atom("\0")).text

它连观察位置都错了；不能靠 τ 修复。

程序已知上下文输出根变成 Envelope，便从 Envelope 的源测试搬来：

    q(e) = e.item.text

得到：

    assert wrap(Atom("\0")).item.text == "\0"

这里模型的补全只有 τ = pre[0]。程序决定实际值访问路径，依据是源观察的根类型和数据流。独立 toy 中，wrap 对普通字符保持原值，却错误删除 NUL；原始两条测试均通过，新观察的实际值为空串。

这个例子对应“观察上下文外部结果，并沿源测试已有路径观察内部载荷”。不需要模型写 .item.text，也不需要预置某个包装 API 的算子。

边界：类型匹配只能保证路径可能可用，不能证明 item 确实代表被包装输入。若 Envelope 有多个同类型字段，程序应给出分别来自源测试的少量观察候选；τ 仍需承担所选路径与原语义的对应关系。不能仅因字段类型相同就宣称 payload 保持不变。

## 3. 同一抽象的一个可选闭包：比较两条程序选择的执行次序

上述观察迁移优先解决“看什么”。还可以让程序生成两条固定的动作序列，并把它们的观察比较当成新的布尔实际值：

    O' = q(S1) == q(S2)
    expected = True

这样仍可使用小 τ，甚至 τ 只是常量 True。不需要把运行时输出塞进当前定义为源期望的 pre 槽。两个 SUT 输出都属于测试的实际值计算，独立语义假设是它们应满足的关系。

最小构造只对已有的两个相邻操作做一次交换：

    S1 = setup; A; B
    S2 = setup; B; A

程序完整重放 setup 两次，保持每条分支内部的别名拓扑，再将相同的源观察 q 移到两条序列末端。不用深拷贝任意 SUT 对象，也不让模型编排新操作。LLM 只接受或省略该固定候选，并给 True 或一个冻结输入条件。

### 微例三：不同键的更新不应互相污染

公开语义是对不同键的赋值互不干扰。可见操作为：

    put("a", 1)
    put("b", 2)

程序产生两次独立初始化及两种次序，搬运已有 snapshot 观察，最后比较快照。一个错误实现只在写 b 且 a 已存在时修改 a，会得到：

    A;B 的 snapshot = {"a": 2, "b": 2}
    B;A 的 snapshot = {"b": 2, "a": 1}

两个长度均为 2，比较 size 仍看不到错误，snapshot 比较为 False。独立 toy 实际产生了上述结果。

条件不可省略：若两个 put 写同一个键且值不同，正确实现也应产生不同结果。模型可给只在冻结参数上求值的条件，例如“两个键不同”；程序不应把 false 条件发射成运行时 skip，而应拒绝该候选。依赖源码识别出的非干扰只能帮助筛选，不能把 buggy 实现当前的写集合当作应当交换的语义契约。

这种关系测试的可靠性边界较清楚：

- 构造器和初始化必须使两条分支在相关语义上可比较；新对象不等于外部状态独立。共享全局、外部资源、随机 ID、时钟等会破坏比较条件。
- snapshot 等观察的返回值如果是可变别名，必须在另一分支执行前冻结为受支持的普通值，或在独立重放中隔离。不能让后续操作同时改掉“前一个观察”。
- 交换律不是普遍规律，类型相同或两个操作来自不同测试都不够。必须有独立的关系依据和必要的输入条件。
- 两条错误执行可能以相同方式出错；关系通过并不证明绝对结果正确。已有源绝对期望仍有价值。
- 重排本身不能弥补一个完全看不到目标状态的 q；这个例子真正需要的是“快照观察 + 两条序列”共同出现。

## 4. 建议的研究选择

下一版应先做“源观察切片换根”，把微例一的状态观察迁移与微例二的类型变化后观察迁移视为同一个算法。它直接补上当前固定实际值表达式的限制，继续沿用绝对期望 DSL，也不要求可靠复制任意对象、证明交换律或引入新的模型正文接口。

次序比较可作为这个抽象的一个小扩展：程序只增加“双重放 + 同观察比较”这一固定骨架，仍然从源切片取动作与观察。它适合绝对预期难以列出、但存在清楚关系契约的场景；不宜替代观察迁移或绝对 oracle。

学术上更准确的目标不是“生成更强的断言”，而是：在预算内选择能区分不同组合状态的观察。一个新增字段投影未必比旧观察严格更强，也可能只是互补。因此应保留源观察的来源、根映射和读取路径，按这些结构事实控制覆盖与多样性，而不假装程序已证明它们的语义强弱。

做对比时，最好固定动作组合 S、检索输入和补全预算，只比较“保留原 O”与“程序选择 O'”。这才能区分收益来自新观察，还是仅仅来自执行了另一批输入。本文没有读取真实运行结果，也不据此调整已冻结代码。
