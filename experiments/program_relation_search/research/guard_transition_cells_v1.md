# 同一编辑端口为什么不能只保留一个代表

`impact_selection` 的义务 `(q, p)` 回答“这个输入编辑可能影响哪个观察”，没有回答“不同输入值是否让后续操作进入不同条件”。同一个端口的两个变化可能拥有完全相同的依赖路径，却跨越不同条件边界。因此，依赖相同不能作为只优先审查一个数值代表的充分理由。

本轮离线原型把计算对象细化为**观察相关的 guard 转移向量**。其成分完全来自源码：观察 `q`、通向该观察的已解析调用、被调代码中的比较位置，以及编辑前后两个比较操作数的 `< / = / >` 关系。它是用于分配推理机会的有限谓词抽象，不是新测试的正确预期，更不证明同一格内行为相同。

## 一个未使用任何 pilot 的例子

```python
def produce(value):
    return value + 2

def accept(available, cost):
    remaining = available - cost
    if remaining < 0:
        return False
    return True

def test_case():
    available = produce(3)
    cost = 7
    result = accept(available, cost)
    assert result is False
```

把同一位置的 `3` 分别改为 `4` 和 `6`，都是增大输入，编辑端口和观察依赖也完全相同。但前者让 `remaining=-1`，后者让 `remaining=1`，分别落在同一 guard 的两侧。程序静态完成这些步骤：

1. 从 `result` 找到被观察的 `accept` 调用。
2. 用实际参数到形式参数的绑定恢复 `available` 与 `cost`。
3. 在限定的无副作用整数表达式范围内，对 `produce` 的返回式及直线局部赋值做常量传播。
4. 计算 `remaining < 0` 两侧的关系；记录编辑前后 `(-1,-1)` 或 `(-1,+1)`。

这里的符号 `-1/0/+1` 表示左操作数小于、等于、大于右操作数。模型仍负责根据 issue 判断测试应期待什么；源码 guard 可能本身有缺陷，不能拿它推导的分支输出充当正确 oracle。

如果后续要接入调度，可把义务从 `(q,p)` 扩成 `(q,p,guard关系)`，对不同关系各保留审查机会。尚未实现或验证这一调度修改；也不能把同关系候选从程序执行队列删除。

## 与已有数值分桶的区别

已存在的 `numeric_relation_buckets` 比较编辑方向、同调用的字面量实参，或测试内直接局部比较。此前统一池对照中，数值分桶没有改变任何案例前 16 名，而且测试局部 def-use 扩展在真实池中没有产生连接。

新原型不继续增加这些语法桶，而是把值送入**被调程序的 guard**。上面例子的原模块只得到“增大”，因为阈值关系跨越 `produce` 的返回式、测试局部绑定、`accept` 的实际参数绑定和被调函数的 `remaining` 赋值。新原型对这些有限源码计算进行组合。

这借用了经典谓词抽象与跨过程常量传播思路。当前可讨论的研究贡献应是“以观察为目标恢复组合条件，指导有限语义判断预算”，不能声称单纯计算 `< / = / >` 是新的学术抽象。

## 当前原型支持什么

独立模块为 `experimental/guard_transition_cells.py`，入口 `candidate_cells(corpus, frontend, candidate)`。不修改原候选、不调用模型、不运行被测仓库、不自动接入主实验或 `impact_v1`。

支持 Python、Go、TypeScript 的共同整数片段：闭合整数字面量、直线局部绑定、`+ - *`、唯一解析的实参/形参映射、返回整数的直线辅助函数，以及有限深度的调用转发。Go 只接受原型明确支持的 `int/int64` 参数；复合赋值、窄整数、隐式默认参数和未知调用保持 unknown。关系值是静态数学计算，运行路径可行性没有得到证明。

| 场景 | 当前能否表达 |
|---|---|
| 一个操作的整数结果与另一个操作参数跨越 guard 边界 | 能，限于支持的常量传播片段 |
| 同时改变两个操作的输入 | 能，前后分别绑定全部实际参数 |
| 中间重新赋值覆盖旧输入 | 能阻断旧输入影响 |
| 原测试未调用的另一函数中的 guard | 不纳入 |
| 同一被调函数内与返回值无关的 guard | 可能纳入；当前调用级关联较粗，尚无精确返回值切片 |
| 闭包共享捕获、对象别名 | 不能，函数值和可变对象不在整数抽象内 |
| `pipe`、转换器等高阶组合操作的语义 | 不能，仅能处理静态解析且返回整数的直线调用 |
| SQL/配置字符串内部的约束 | 不能；字符串仍为不透明输入，不猜测宿主之外的语言 |
| 不同调用时机、线程顺序、观察阶段之间的可变状态 | 不能；只有原源码位置和局部绑定，没有事件发生顺序证明 |

因此，这只是对一种遗漏机制的可计算细化，不是覆盖全部 combination gap 的替代核心。若大量真实案例落在 unknown，不能依靠补关键词或增加任意分数来声称解决问题。

## 验证与结论边界

新增 18 个通用测试，验证三种语言的跨操作 guard 边界、调用转发、同格不等于同输出、联合输入编辑、无关函数、重赋值、复合赋值拒绝、闭包/副作用 unknown、嵌入约束 unknown、改 callee 或新增导入覆盖旧名字后不继承旧绑定、命名变化以及标签/缓存不影响分析。与已有数值分桶测试一同执行通过 42 项。

没有读取新一轮目标排名或 oracle 缓存来定义规则。规则与 toy 于 `3a359fc` 冻结，再进行下列真实源码覆盖检查；没有检出率或排序改善结论。

## 冻结后的真实源码覆盖：当前拒绝接入主方法

首先完全复用 `oracle_evidence_v3_census_final` 已固定的每例 8 个 SHA 抽样候选，共 136 个，既不重新抽样也不选择已知目标。24.012 秒完成全部分析，程序异常为 0，但**非空 guard cell 为 0/136，跨 guard 关系也为 0/136**。

候选级 unknown 原因中，104 个包含无法唯一解析的调用，70 个涉及不支持的状态接收者，16 个涉及当前不支持的 Go 参数类型，16 个涉及隐式默认值或不完整参数绑定。一个候选可以同时出现多种原因，因此这些数字不是互斥分类，也不表示该候选的所有调用均无法解析。

这表明通用 toy 上的区分能力没有转化为当前真实候选的有效覆盖。整数片段不足以支撑本轮统一主方法，应保留为负面探索，不能通过临时加入案例规则、放宽未知值假设或只挑成功 toy 来包装成改进。

随后统一分析固定 17 例全部 **4,502 个候选**，87.249 秒完成，没有达到 650 秒预算上限。非空 cell 为 **0/4,502**，跨 guard 关系为 **0/4,502**，分析异常为 0。这不是抽样偶然漏掉少量支持场景；当前封存池里整个新增分析能力没有形成可用关系，不应接入本轮排序。
