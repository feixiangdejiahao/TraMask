# 从验证见证补齐关系，而不是拼接完整测试

后续研究设计见[用关系形状指导测试搜索](relation_search_method.md)；此前[判别上下文合成](distinguishing_context_method.md)已被否决。原始 trajectory 的成因修正见[17 条验证逻辑重审](trajectory_logic_20260928/README.md)。下文为旧实现记录，新设计只有独立机制验证，没有新 pilot 成绩。

2026-09-28 研究定位修订：阅读 STARS 后，确认 `(q, ρ)` 能描述目标和评价结果，却尚不能直接导出统一的构造算法。**它不再被视为已成立的核心算法贡献。** 三个问题观察保留，以下方法与结果作为已实现原型记录；重审依据及新设计应满足的标准见 [STARS 阅读与方法重审](stars_abstraction_review.md)。本次没有新的生成实验或性能改进声明。

原型采用 **带观察的关系单元 `(q, ρ)`** 表示目标。`q` 是已有验证中真正观察程序状态的表达式；`ρ` 是可控输入、对象和操作之间的一种关系。目标是构造一个新测试，使它在同一次执行中实现 `ρ` 并检查 `q`。关系构造与正确期望是两个独立问题。

最新完整结果为 **4/17 目标检出，仍漏检 13/17**，见 [五小时报告](relational_gap_timebox_20260928.md)与[第七批评价](relational_gap_batch7_evaluation.md)。这一最好配置统一恢复已有源断言，在第六批 3/17 的基础上新增 P2；其余已知检出也在本批重新运行确认。完整断言可能引入过时期望或提前终止，所以这是已见开发集上的观察策略消融，不是已证明可靠的通用 oracle 算法。

例如，已有测试分别使用 `f(1, 10)` 和 `f(2, 20)`，观察相同的结果字段。程序可以在已恢复的源行与绑定范围内发现 `(1, 20)` 尚未出现，并以一次参数编辑构造见证。若已有测试分别使用两个不同对象，程序可以构造两个参数引用同一对象的关系。若源码比较 `target < high`，且操作数能恢复为静态可求值的整数或受支持的仿射表达式，程序可以构造等值边界输入；若另一操作数不能恢复，只能在有整数域依据时提出 `±1` 邻居假设，不能声称已经求出 `target = high`。统一的研究视角是：**划分有限关系空间、找源验证中未见的单元、构造候选见证**，具体 API 的名字不参与定义。实际实现中，显式坐标域进行有限未见单元枚举，其他关系域分别提供有界源编辑假设；不是所有候选都经过统一的缺失单元判定。

## 为什么需要这个抽象

新增十条轨迹的分析见 [发现集报告](expanded_trials_20260926/README.md)，逐例关系、证据边界及论文来源见 [研究假说](expanded_trials_20260926/abstraction.md)。这些案例说明三件事：

1. **同样的两个操作可以形成不同关系。** “两次修改”既可能分离、重合，也可能部分重叠；只统计操作是否出现无法区分它们。
2. **关系必须绑定到具体对象和观察阶段。** 内存解码异常与正常流关闭分别通过，不说明同一个真实流在异常时会关闭；flush 后的观察不能代替 flush 前的观察。
3. **组合可以已经发生，却没有改变断言能看见的状态。** UPDATE name 与 COUNT invariant 同时运行，对检查字段约束是否会拒绝非法写入几乎没有信息。

因此，研究单位应是 `(q, ρ)`，不是“test A 加 test B”，也不是模型自由生成的一组自然语言 feature。程序依赖用于定位关系的参与者、恢复构造和保持对象绑定；不能把 may-dependence 当作应有行为，更不能因为 buggy candidate 缺少传播边就拒绝构造测试。

## 算法的核心

设 `Vq` 是与观察相关的输入位置，`Rq` 是可从源码和已有验证恢复的有限关系域。测试为这些位置提供值、对象绑定和动作顺序。有限域内尚无源见证的关系单元是新的搜索目标：

```text
for q in existing_observations:
    relations = recover_relations(q, source, validations)
    for rho in unseen_cells(relations):
        t = construct_small_witness(q, rho)
        if an independent expected result can be justified:
            execute t with unchanged source controls
```

这段伪代码描述研究目标，而不是完整的约束求解器。实际流水线先由若干有界关系域适配器枚举源编辑，再按显式观察标识，或输入的 may-dependence 与观察轮换选择 `q`。因此，`Vq` 的恢复既不是完整程序切片，也不保证找全所有影响 `q` 的输入；不同关系域也尚未归约为一个统一、完备的求解过程。

实验实现也没有在执行前证明所有期望正确：它执行源断言假设及受限模型变体，再将结果区分为有效目标失败、错误期望和未知。上述伪代码中的独立期望依据是确认检出的要求，不能理解成当前实现已经具备自动、可靠的 oracle 证明器。

`unseen` 在当前实现中首先指**静态源验证中未见**，不是已经计算出完整的 `Checked_P(q)`。历史测试未在最终候选重放，不能直接当作当前覆盖；存在断言，也不证明该断言在新场景中正确。源码编辑可构造，也不证明运行一定实现目标关系。三个层次在实验中分别记录。

[closure.py](../relational_gap/closure.py) 实现有限单元枚举和见证选择。这里的“最少修改”仅指：对于给定坐标赋值，在已提供的同组源行中选择坐标 Hamming 距离最小的种子；不保证源码编辑、语句数或执行长度最小。[cells.py](../relational_gap/cells.py) 将源调用位置及观察映射到这些坐标。其余前端和测试框架适配用于恢复、物化和执行见证，不作为额外的学术贡献。

## 程序负责的工作

**恢复验证。** 从最终仓库与 trajectory 恢复测试、临时脚本及不同文件版本，区分覆盖写和追加写。Python 编辑脚本生成的测试源码可以静态恢复，编辑脚本自身不因此成为运行验证。历史 Go 文件重命名以减少符号冲突，仍必须通过编译与原控制重放。Python/TS 脚本可以转为标准测试入口；打印是观察，不自动成为正确断言。

**恢复局部程序关系。** AST、局部 def-use、实际参数到形式参数的传递、构造对象来源、显式 import/reexport 和调用顺序共同定位关系。先补齐有界 import 依赖再建立索引，减少仅因文件检索预算而漏掉未修改接口包装层的情况；预算与动态依赖仍可能造成遗漏。调用同名只能产生弱假设，不能升级成已经证明的同一方法。已识别的报错消息和测试框架诊断参数从输入供体中排除；这不等于能语义识别任意自定义日志或断言包装器，角色未明的调用仍需标为未知。

**构造关系见证。** 当前支持的是有限的子集：源参数值形成的联合单元、record 字段存在性、源码默认值对应的省略、可代换的数值比较边界、同一对象引用、源字符串片段编辑、异常出口的已有观察、同一 receiver 的一至两步源操作，以及简单 SQL 读谓词与写字段的交互。复杂别名、一般区间反求、任意嵌入语言和并发时序没有被这些规则自动解决。

**恢复解析字段坐标。** 对导入身份可证明的 Python 正则使用，源码 capture 可以继续经 `group`、match 下标、局部赋值、解包及常量分隔符 `split` 细化为层级字段；有界、唯一解析的实际参数到形式参数绑定可以把这种来源传入辅助函数。源 split 的迭代坐标只按闭合源输入的有限长度展开，不推断过滤器或映射函数的输出语义。程序从同一调用槽的源见证交换一个叶值，保留其余输入，并重匹配正则与字段路径；参数化输入还必须保留完整原参数行。循环或异常区间内的局部匹配、条件空值回退以及弱调用关联均保留相应的适用性未知状态。该过程不执行被测解析器，也不证明所有原语义字段都已恢复。

**恢复可选字段存在性。** 当 capture 在一个源输入中缺失、在另一个中存在时，缺失位置本身没有可交换的叶值。可选关系适配器从源码正则的受支持可选子式恢复包含 capture 的语法片段，并从供体复制该片段及正则拥有的分隔结构。只有有界重匹配找到唯一插入位置、且其他 capture 保持一致时才提出候选；重复祖先、多个独立 capture 或无法证明的分隔结构等情形不按名称猜测。解析字段交换和可选片段插入所验证的都是源语法与坐标保持条件，不证明被测程序实际执行了目标关系，也不证明 `q` 能区分相关行为。

**保留数值类型依据。** 数值规则可沿源码可见的整数别名或定义类型恢复底层整数域；Go 的跨文件与包限定类型还要求源导入、包路径及可用模块配置能够唯一定位声明。缺少声明、类型歧义或超出解析预算时仍是未知，指针、数组、map 等类型不能因此升级成整数。整数类型证明只允许相应的数值构造，不会把不可恢复的动态比较操作数变成已知边界。后述派生值复合还要求形式参数的整数类型依据，不能仅依赖原实参恰好是整数字面量。

各关系域按固定预算轮换；基础坐标候选中，相同观察/绑定下已经存在的值组合降级为低优先级，其余关系域使用各自的去重与假设规则。源码字段默认值是比普通 record 子集更强的依据。语义未知的合法构造仍可保留为假设，交独立期望判断与执行，不把未知直接等同不可行。

第五批增加一个受限的见证复合运算：若两个见证针对同一源测试、同一调用的同一实参，并且各自编辑可以兼容，则保留源操作链及其 `q`，在导入的派生值上应用源码整数比较支持的 `±1` 关系。程序要求形式参数的整数类型依据；原输入碰巧是整数不够。只支持“源派生值构造 → 未知边界邻居”这一有界二步复合，不声称实现任意关系闭包。例子是把 A 中 `child=root.begin(); root.apply(child); n=child.position()` 这段与值和状态相关的操作移到 B 的已有 `root` 上，再将 B 的调用实参替换为 `n` 或受支持的相邻值，仍检查 B 原有的状态。状态修改、求值次序和局部变量绑定必须一起保留；仅复制 `n` 的赋值不够。此处是构造能力说明，不能当作真实案例成功。

**选择一个观察。** 新见证可只保留程序选定的 `q`，中和其他断言的失败机制，同时保留其必要表达式求值、动作、上下文管理和清理。完整原测试作为对照运行。这里的支持范围有限，无法保留求值语义的复杂断言会退回完整测试候选，不宣称任意断言都能安全切片。

## 少量 LLM 的职责

模型看到 issue、必要源码、源测试和程序已经提出的编辑。它可以判断局部期望的适用性，并在程序指定的期望位置给出纯表达式；不能自由修改测试输入、动作、观察位置或生成完整测试。纯表达式只使用已有期望、静态输入和有限运算，先在本地求值成常量，再写入测试；不能调用被测程序获取答案。这里的“独立期望”指不以被测程序的执行结果合成答案，并不表示模型与候选源码隔离，也不构成期望正确性的形式证明。纯表达式校验约束可接受的操作与副作用，语义适用性仍须单独核验。

第二版使用请求内短编号，源测试只发送一次，模型只返回选择和局部期望。每例最多两次请求，每次最多展示 64 项、接受 32 项，单请求源码与提案上限 80 KB。单个格式错误只拒绝对应条目。请求、原始响应、解释器结果、代码哈希和所有运行均保存，缓存重放与重新请求分开。

这些限制使模型的修改范围可复现，并不使其语义判断可靠。模型保留一个错误旧断言，仍会制造误报；因此“模型接受”“测试失败”和“确认目标缺陷”必须分开。

第五批改变执行选择：相同冻结请求中展示的程序候选（每例最多 128 项）都保留原 `q` 作为待核验假设执行。模型补充期望编辑记录不同的变体（最多 64 项）；相同编辑共用原见证。这里未做一般语义去重，仅改变字符串引号等语义相同的变体仍可能独立执行，所以变体数不等于独立 oracle 数。两类按源文件分别分组执行，仍先运行完整源控制。这样模型遗漏不再直接删除一个已经构造的见证，但它不能解决错误或太弱的原断言。期望适用性未确认的失败仍是 unknown。模型预算保持两次请求，执行上限从 64 增为 192，因此不能把后续结果解释成整体等预算改进。细节见 [执行约定](relational_gap_v5_execution_protocol.md)。

## 如何评价

17 条 trial 全部是已见发现集，实际涉及 14 个 task。不能把它们当作独立盲测。

| 层次 | 成功含义 |
|---|---|
| 源测试恢复 | 目标验证的源码、输入与观察进入分析范围 |
| 候选来源命中 | 候选使用了目标源测试；不代表形成了目标关系 |
| 场景命中 | 生成测试确实实现目标 `ρ`，对象和阶段正确 |
| 正确 oracle | 对 `q` 的要求有独立依据，适用于该场景 |
| 目标缺陷检出 | 原控制通过，新测试执行并因目标缺陷失败 |

首批完整结果是 **0/17 目标检出、15/17 源测试及候选来源命中**，并已确认部分错误 oracle。见 [首批独立评价](relational_gap_batch1_evaluation.md)。[第二批](relational_gap_batch2_evaluation.md)恢复目标源测试及候选来源 **17/17**，正确组合并检出 **1/17**，唯一确认案例是 N10。其输入编辑是把显式 `parser({ mode: 'put' })` 改成 `parser({})`，沿源码两层调用找到默认值仍为 `put`，保留已有缺失条件必填字段应抛错的断言；完整原控制通过，新测试因未抛错失败。

第二批共 830 项模型获准候选；272 项失败有通过的原控制，其中只有上述一项已确认为目标缺陷，另有四项已确认错误 oracle，267 项的 oracle 未定。不能把其余失败都计作缺陷，也不能据此声称精确率或误报率已改善。34 次请求全部完成且无协议错误，仅说明通信和格式恢复有效。

第三批完整评价仍为 **1/17**，唯一确认目标仍是 N10，见 [第三批评价](relational_gap_batch3_evaluation.md)。809 项获准候选中，256 项失败有通过的原控制：1 项目标、1 项已核验错误 oracle、254 项未定。错误 oracle 只进行了有限抽查，不能用“4 项变 1 项”宣称误报减少。新增数值规则还暴露出将指针比较错误当作整数边界的问题；后续批次要求整数类型或源整数表达式依据。布尔断言的隐式 True/False 期望成为受限孔，程序仍保留原观察表达式并只改变极性。

第四批在冻结准备中补充下列源关系载体：解析器正则捕获字段、源码调用上下文 `C[f(x)]`、三份源字符串对应的行编辑区间、惰性生成器的字面量 yield 坐标。它们分别提供有限字段联合、调用项嵌套、Allen 区间关系和异常出口关系的可编辑位置；只生成假设，不声称这些位置自动具有正确语义。现有 256 个种子内部增加基于已解析调用路径的排序：其结果流入断言且能到达修改函数的调用优先，然后是未被断言观察的相关调用，再保留未解析者的原顺序。未解析调用不被删掉。这些都是关系见证的前端支持，不各自宣称新的学术贡献，也不能把独立小程序的成功计入 17 例结果。

[第四批最终结果](relational_gap_batch4_evaluation.md)为 **0/17**。具名执行的目标源测试来源从第三批 10/17 增至 14/17，但目标检出下降。N10 的正确默认省略见证仍在请求中，未获模型选择；N05 已有“不截断且保留样式”的输入场景，原断言却仍要求截断，模型修订又因引用空的期望数组而无效。这两例分别说明准入遗漏和 oracle 不适用；不能把输入场景命中计作缺陷检出。[第五批完整结果](relational_gap_batch5_evaluation.md)为 **2/17**，确认 N02 与 N10。1321 个源断言候选及 166 个模型期望变体被物化；639 个失败有通过的原控制，其中 6 个候选对应上述两个目标 trial，4 个已抽查确认为错误 oracle，629 个仍未定。不同历史版本不重复计 trial；上述抽查也不能估计总体误报率。

这一抽象是否有论文价值，仍需验证它是否优于等预算的随机源片段组合、普通 pairwise 与分支/边界生成。程序关系分析、组合覆盖和可观察性各自都已有研究；不能把它们列成一个流程就当作创新。可检验的主张是：**从 agent 的实际验证恢复观察相关的关系域，能否在没有人工 feature model 的条件下，以较少见证发现已有验证遗漏的真实缺陷。**
