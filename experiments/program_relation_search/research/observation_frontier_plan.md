**观察前沿：本轮改进的事前算法约定**

开始：2026-09-23 06:54 UTC；五小时上限：11:54 UTC。原始七例结果保存在 `results/anchor_retrieval/final/`，目标标签不修改。

用户约束：算法围绕一个学术抽象；不通过 pilot 名称、目标行号、特定仓库常量或反复调权达到指标；不调用外部模型。七例已经全部看过，任何本轮结果都是发现集上的开发结果，不能称为独立泛化结果。

核心假设：相同测试中的中间检查会挤占 assertion 检索预算。与函数可达数量相比，**观察值的依赖前沿**更适合识别已经消费了多个行为结果的组合测试入口。这里的前沿是有限静态依赖足迹的偏序，不是断言逻辑蕴含关系。

对每个断言 a，提取实际观察表达式，构造值依赖足迹 D(a)：

- 测试局部值依赖上的、能关联到补丁的调用发生位置；保留同一 API 在不同位置的不同调用。
- 被观察字段的生产者形参来源；字段聚合计算会同时保留多个来源。
- 可能的状态影响和控制边继续保存在原分析中，但不用于证明一个观察包含另一个观察。
- 可确认正常返回值为同一字面量的调用，不把接收者或参数当作返回值来源。

在同一测试中，D(a) 严格包含于 D(b) 时，a 是更早的观察，优先级低于 b。反复移除极大元得到前沿层。相同层优先选择参数化期望能区分更多不同结果的断言，再按原始源码位置打破平局。期望多样性从参数表静态计算，不让模型判断“重要性”。

跨测试复用已存在的 patch/关键词基线顺序，将每个测试的代表断言先安排一次，再继续后续断言；这只是预算分配规则，不作为新的研究贡献。不增加测试名/issue 语义打分，不以输入缺口数量作排序特征。

第一轮实现前写下本约定。实现修复与算法变化分别记录，不扫描大量权重或组合。先验证独立的小程序，再对七例评价；每次完整结果和源码快照都保留。补充检查至少覆盖变量改名、无关语句插入、测试出现顺序变化、组合观察与中间观察的区分。若未达到双 Hit@10=1，只有出现与核心抽象一致的失败证据才修改算法。

边界：前沿命中仅说明找到了既定 A；不保证已有 oracle 可迁移，不代表已生成组合测试或提高 issue resolution。P6/P7 的入口 oracle 局限仍然适用。

**第一轮后（07:12 UTC）**：commit `e69c368` 的七例结果为 Test Hit@10=7/7、Assertion Hit@10=5/7。P4 的实际值/期望值识别有实现错误：右侧期望字典中的内置 `str` 导致被误认为被测表达式。修复为比较两侧的生产值来源；两侧都有来源则保留关系的两侧。独立例子验证正向/反向相等及双输出关系。

P6 中返回值断言与错误状态断言具有相同的调用足迹。对相同足迹增加一种观察精度关系：沿用已有断言提取器的 outcome/incidental 分类，值观察优先于单独的错误/空值状态检查；没有值观察时保留状态检查。它只在相同足迹内部生效，不全局丢弃错误断言。没有增加场景关键词或调节排序权重。

另由独立多态例子发现常量摘要错误：两个不同方法各自返回常量，并不代表动态分派后的值恒定。仅当全部已解析目标返回同一个常量时才能折叠。此修复在查看七例评价前的独立测试中发现。

实现边界补充：测试局部足迹排除 may-state/control 边；字段生产者形参来源目前复用已有保守摘要，可能包含生产函数内控制/状态依赖，不能将整体足迹称为精确值依赖。
